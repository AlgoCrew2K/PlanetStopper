## Executive verdict

**The operator's instinct is correct.** Verbatim answer to "there's no way that candidate came from a fable reasoning over the symphony and figuring out what to change, then putting the candidate through the engine":

> **No advisor reasons over the operator's live symphony tree to change it.** The two symphony-MUTATING features — Logic Changes and Asset Swaps — are **100% deterministic** (zero LLM, direct or indirect, on every reachable path). The one genuinely LLM-driven strategy builder (Strategy Builder, built-new candidates) is **context-blind**: its Opus prompt contains no symphony, portfolio, backtest, or lens data — only an objective name, the grammar, three static examples, and 20 sample tickers. The real-LLM features that DO exist (Chat, Run Advisor, Market Prism) are explain-only, config-tuning, and sentiment-synthesis respectively — none of them mutates a strategy. *(audit-reasoning, 7/7 features traced with model ids + call paths.)*

The failure is **not broken math and not fabricated numbers.** audit-stats confirms the underlying quantitative library (BHY/Yekutieli, CSCV/PBO, bootstrap-Sortino SE, fail-closed vetoes, one-directional-brake acceptance panel) is well-built and, where fully wired, sound by trading-firm standards. The suite fails the operator's intent on **two orthogonal axes**:

1. **Reasoning theatre.** A page-global subtitle *"Claude-powered suggestion engine"* renders above all six tabs, over engines that are provably deterministic; the deterministic engines receive the full raw symphony tree but do nothing intelligent with it, while the one real strategy LLM never sees the tree. The suite advertises reasoning it does not perform, and under-attributes the one place (Market Prism) where real reasoning happens.

2. **Statistical branding without statistical substance.** The sound gate math is fully wired into exactly one engine — Strategy Builder. Asset Swaps and Logic Changes inherited the FDR/Yekutieli *branding* (UI copy, method names) but not the *substance*: the PBO overfitting veto is structurally incapable of firing, the SPY-relative baseline was never extended to them (they gate on "beats a flat 0.0% return" — the exact permissiveness the code's own comments say was deliberately removed for SB), and their operator "Evaluate" buttons run at N=1 where the multiple-testing correction is a mathematical no-op and statistical power is empirically near zero.

**One-line headline:** *Strategy Builder is the in-repo reference implementation of what "right" looks like (real Opus generation → deterministic compile → schema-validate → backtest → FDR/PBO/SPY gate); its rigor was never propagated to the sibling engines, and the UI narrates a uniformly "intelligent" suite that does not exist.*

### F1 — The advisor never reasons over the operator's live symphony to change it `[HIGH]`
**This is the direct answer to the operator.** The two features that MUTATE a strategy are deterministic; the one real strategy LLM is context-blind.
- **Logic Changes = numeric-leaf perturbation only.** `extract_numeric_params` (lce.py:405-447) collects a param only when `isinstance(val,(int,float)) and not bool`; `generate_objective_directed_candidates` (lce.py:531-762) multiplies each numeric leaf by a fixed per-objective constant (lce.py:616/645/674/702/730) and emits a `LogicTweak(node_path, param_key, old_value, new_value, node_description)` — a struct with **no field capable of expressing a structural edit**. **Structurally impossible** (audit-data RUNNABLE-PROVEN, D-1): change a ticker, swap/add an indicator, flip a comparator, add/remove/reorder a condition or if-branch, change the weighting scheme, re-nest nodes.
- **Asset Swaps = 1-for-1 ticker string replacement only** (`apply_ticker_swap` ase.py:375; audit-data D-1b). Cannot change weights, conditions, holding count, or structure.
- **Strategy Builder's Opus is context-blind.** `_build_generation_prompt` (bpg.py:947-1030) = objective name + DSL grammar + 3 static examples + `sorted(membership)[:20]`. Zero portfolio/symphony/backtest/lens data. Real Opus call at bpg.py:1078-1084 (audit-reasoning #2).
- **Cross-challenge:** audit-reasoning (path trace) + audit-data (runnable proof, temp DB, synthetic tree). **Falsification** ("find a reachable path where an LLM reasons over the live symphony to mutate it"): none exists — SURVIVES at full weight.

### F2 — Statistical branding without statistical substance on the two mutating engines `[HIGH]`
The FDR/Yekutieli machinery is real but its teeth (PBO, SPY baseline, meaningful N) are wired into Strategy Builder ONLY.
- **PBO overfitting veto structurally cannot fire** for Asset Swaps or Logic Changes, at any N, ever. All 6 `evaluate_candidate_batch` call sites (ase.py:1047/1075/1277; lce.py:1289/1316/1466) pass neither `dated_returns=` nor `spy_returns_fn=`; `BacktestCandidate.dated_returns` defaults `{}` (backtest_gate_engine.py:264) → `_batch_pbo` stays None → veto always passes (acceptance_gate.py:208). Only SB wires both (sbe.py:857/871). Mirrors a documented pre-fix SB bug (tests/advisors/test_cull_production_wiring.py) whose fix (DE-SB-CULL-001) never reached the other two engines. **Two-independent-trace** (audit-stats §4 + audit-reasoning).
- **Beats-zero baseline, not SPY.** `default_oos_alpha=0.0` at every entry (ase.py:995/1154; lce.py:1181/1372); app.py never overrides. This is exactly the permissiveness the code's own AC-25/edge-14 comments (backtest_gate_engine.py:187-196) say was deliberately eliminated for SB. SB alone sources a real SPY OOS-fold baseline (sbe.py:807-826). (audit-stats §7.)
- **N=1 uncorrected test on the operator "Evaluate" buttons** (JOINT audit-stats + audit-reasoning finding): Asset Swaps (ase.py:1075) and Logic Changes (lce.py:1316) route a single candidate through `evaluate_candidate_batch([one])`; c(1)=1.0 exactly → BHY is a no-op → raw one-sided p≤0.05 on one bootstrapped Sortino t-stat, despite FDR-branded UI. **"Doubly inert: no reasoning generated the candidate, and no effective multiple-testing correction screened it."**
- **Cross-challenge:** audit-stats (math) ⇄ audit-reasoning (route structure) — filed as ONE joint finding, two independent traces. **Falsification** SURVIVES.

### F3 — Near-zero statistical power at reachable fold lengths; "survived the gate" ≠ "proven edge" `[HIGH]`
audit-stats chained the codebase's OWN `compute_sortino_tstat → compute_haircut_pvalue → benjamini_hochberg_adjust` on synthetic data (§5, Snippet 3). At the gate's own minimum fold length **T=13** (FOLD_TRANSFORM_MIN_TOTAL_DAYS=65×0.20, VERIFIED), even a ~100%/yr edge (μ=0.40%/day) yields N=1 detection **3.3–25%**, N=12 detection **0%** across every tested cell. A single ~13-day validation-fold Sortino comparison presented as "statistically significant" is, in most realistic cases, closer to noise than signal. A **fixture-verified T=121** anchor (real symphony hash INfCn3eKsu6i4oTTqdUp, `tests/fixtures/composer/backtest_inline_v1.json`, series_len=606; audit-stats Snippet 4) confirms the result is robust across a genuine ~10x range of T: even there, N=12 (batch, BHY-corrected) detection is **0% for every economically-plausible effect size** (μ≤0.20%/day ≈50%/yr) and reaches only 13.3% at an implausible μ=0.40%/day; N=1 power improves at large assumed edges (46–98% at μ=0.20–0.40%/day) but stays weak (4–14%) at realistic edges. **Sub-finding:** the gate does NOT fix or bound the series length n — `composer_backtest_client.run_backtest` sends no lookback/date-range (composer_backtest_client.py:237+), so n is per-symphony and code-uncontrolled (unlike the autotuner's 250-day budget); a short-history symphony is gated at the near-powerless T≈13 floor with no minimum-power guard. **Falsification** SURVIVES and is STRENGTHENED by the T=121 anchor — two hard rows (T=13 floor + T=121 fixture) plus illustrative T=50; "survived the gate ≠ proven edge" holds across the full verified T range.

### F6 — Winner-take-all gate: correct math, misleading framing, and wrong rejection copy `[MEDIUM]`
- **The math is exactly right.** audit-stats proved (lemma, not asserted) that the single-winner admission test `p_adj_(1) ≤ q` is **IDENTICAL** to the true BHY step-up's own rank-1 decision (`⟺ i*≥1`), computed over the full honest N (backtest_gate_engine.py:766). **This is NOT "over-conservative"** — retracted; `p_adj_(1) ≤ term_1` means the bar can only be as-strict-or-more-lenient than a single-best Bonferroni, never inflated.
- **The defect is set-cardinality, not the threshold.** By taking `argmin` only (backtest_gate_engine.py:788-830), when the true step-up would declare i*≥2 discoveries the system silently discards ranks 2..i* — **legitimate discoveries by its own criterion** — with zero operator visibility (`winner_p_adj` is audit-trail-only, backtest_gate_engine.py:286-291). A power/yield loss, not a validity hole. The fix (if wanted) is a set-cardinality change (admit all `p_adj≤q`), NOT a threshold change.
- **UI mislabel:** "FDR correction applied (N tested, Yekutieli-adjusted)" (ai_advisor.html:1904) invites a controlled-FDP-SET mental model when the declared set is capped at 1 by construction. Also a **partial design explanation** of the operator's standing "0 passed" observation (multi-survivor weeks are impossible by construction).
- **Wrong rejection copy (audit-doc 10.5, render-path CONFIRMED):** `rejection_reason` (pbo_veto/below_spy_alpha/fdr_not_winner) is NEVER read or rendered in ai_advisor.html (grep zero matches). Every reject shows the same hardcoded "did not clear the FDR correction threshold" (ai_advisor.html:1996/2002) — the WRONG statistical claim for a candidate that DID clear FDR but lost the argmin tie-break, and the operator cannot distinguish the three rejection classes.
- **Falsification round CLOSED** (assumed "it correctly controls multi-discovery FDR" → disproved by the lemma; the precise, stronger statement survives): **DEFENSIBLE math / WEAK framing.**

### A.3 Formal winner-take-all derivation + correction (verbatim, supersedes A.1#5's informal wording)
Setup: m=N candidates, raw p_(1)<=...<=p_(m), term_j := (m·c(m)/j)·p_(j), i* = max{j : term_j <= q} (0 if none). `benjamini_hochberg_adjust` computes p_adj_(k) = min_{j>=k} term_j.
**Lemma (proved):** p_adj_(k) <= q ⟺ k <= i*. (k<=i*: term_{i*}<=q and i*>=k, min over j>=k includes i*. k>i*: all term_j>q for j>i*⊇{j>=k}.) So "reject each hypothesis iff its own p_adj<=q" EXACTLY reproduces the classical step-up set {1,...,i*}.
**What the code does (backtest_gate_engine.py:786-791,830):** best_i = argmin(p_adj) = the rank-1-by-raw-p candidate; admits iff p_adj[best_i]<=q. By the lemma with k=1: **p_adj_(1)<=q is EXACTLY "1<=i*", i.e. exactly "does the true step-up declare AT LEAST ONE discovery." Identical formula, not an approximation.**
**Correction (retraction):** "at least as conservative as / typically stricter than" is WRONG. p_adj_(1)=min_j term_j <= term_1 = m·c(m)·p_(1) always → the test is NO STRICTER than single-best Bonferroni-Yekutieli — equally strict or MORE LENIENT, never inflated. So "over-conservative" is the wrong word for the ADMISSION TEST.
**Where "conservative" DOES apply:** the DECLARED-SET SIZE is capped at exactly 1 regardless of how many candidates legitimately qualify (whenever true i*>1, the system silently discards i*-1 legitimate discoveries). That is POWER/YIELD conservatism, NOT threshold-strictness. The right fix (if wanted) is "admit all candidates with p_adj<=q, not just argmin" — a set-cardinality change, not a threshold change.
**Q1 (error rate):** the ADOPTION EVENT (0 or 1 survivor) is calibrated exactly to "does true BHY declare i*>=1" — a batch-level omnibus test, not a set-level FDR. When adoption fires, the adopted candidate is provably in {1..i*} (never one a full step-up would reject). What is NOT controlled (never attempted) is the FDR of a multi-item declared SET — cardinality <=1 makes it degenerate.
**Q2 (category error?):** Math level: NOT a category error (textbook BHY rank-1, correct, full honest N). Selection-rule level: DEFENSIBLE (inherited from autotuner:1288-1292, right for 500 trials of ONE symphony; power-losing but valid for a batch of DISTINCT proposals). Framing level: category mismatch — "FDR correction applied (N tested)" invites "controlled-FDP SET returned" but set size is capped at 1.
**Revised grade:** DEFENSIBLE math (unconditionally, via the lemma) / WEAK framing. Recommended UI correction: "FDR correction applied (N tested)" → "tested against an FDR-calibrated significance bar accounting for N alternatives; only the single strongest candidate is ever promoted per run."
