## Architecture Notes

- **Two-DB pattern:** State DB (`alphabot_state.db`, this module index) and Optuna optimization DB (`optuna_studies.db`) are never cross-joined in application code.
- **Advisor wall:** All Advisor DB reads go through `database.advisor_ro_query`. Direct connection access from Advisor code is prohibited and CI-enforced.
- **NN1 spec-freeze:** `autotuner.OPTUNA_SEARCH_SPACE_KEYS` must never contain `gamma`, `utility_family`, `wealth_argument`, `generator_family`, `horizon_conversion`, or `lambda`. The calibration sweep uses a separate 2-key space and does NOT modify `OPTUNA_SEARCH_SPACE_KEYS`.
- **Return units:** `synthetic_history.py` emits returns in **percent**. The CRRA-EU branch converts at its boundary via `RETURN_PCT_TO_FRACTION = 100.0`.
- **Third-DB pattern (warehouse):** `alphabot_warehouse.db` is a THIRD, separate SQLite file from the state DB and the optimization DB — append-only, never cross-joined with either. `advisors/lens_warehouse.py` and `advisors/frontrunner_signals.py` both write to it (different table sets, same file).
