# UX overhaul: what each page shows and how it is built

> The current state of the dashboard, History, Performance, AI Advisor, Settings and the shared header after the UX overhaul (plans 01 to 07) and the two UX fix batches: one shell, true labels, one guard number, and honest empty and failure states.

**Source:** `templates/*.html`, `static/*.js`, `static/layout.css`, `app.py`, `analytics.py` (symbols named below)
**Last updated:** 2026-11-02

## Overview

Visual tokens live in `static/tokens.css` and are unchanged. The overhaul changes which words and figures appear, where they come from, and how every page behaves when data is missing or a request fails. The engine files are untouched by it. Companion page: [refresh_timing.md](refresh_timing.md) (session anchoring, held results, health).

## The one guard number

The dashboard headline reads "Guard effect on portfolio" for the picked window, in percentage points. It is the compounded Bot return minus the compounded If-held return over the window and all symphonies (`analytics._compounded_gap_pct`, applied to the windowed series that `analytics.compute_windowed_portfolio_strip` already holds; the gap between the hero chart's two lines at its last point). It needs at least `_PORTFOLIO_GUARD_EFFECT_MIN_DAYS = 2` days of the series in the window, otherwise the value is `None` and the page prints a dash. The Performance tab shows the same figure for the same window under the same label ("Guard effect on portfolio"; "Guard effect on symphony" in symphony scope). Crypto stays out only of the cumulative row's return, for the reason that row states.

This overrides the epoch-additive convention for the portfolio headline only. Per-symphony cards keep their epoch-additive figures. History's total reads "Sum of exit alpha" in points, a sum of the exit days' alpha at 15:54 ET, unweighted, not a portfolio return; its daily strip reads "Daily sum of exit alpha (pts, unweighted)" and the by-reason cards use the same words. The `$` figures (`/api/guard-alpha-summary`, `analytics.format_dollar_saved`) are a separate quantity on a snapshot-time basis and are unchanged.

## Windows

`30d`, `60d`, `90d`, `125d`, `ytd`, `1y`, `all` are the dashboard picker's tokens; `analytics._WINDOW_TRAILING_DAYS` also holds `5y` (1825 days) and `/api/performance` accepts `5y` (`_PERFORMANCE_WINDOW_TOKENS`). Performance and History use the same calendar windows as the dashboard. History opens on 30 days and Performance on 60d, its shortest window that can meet its 30 observation minimum. `GET /api/history/<days>` accepts a day count or `ytd` (`/api/history/<any(ytd):days>`). The window picker's heading, the headline and the max drawdown and annualised volatility rows change together on a pick; until the picked window's own answer arrives they show a dash, and a failed or held answer shows a visible notice and a later poll asks again.

## Words on screen

- Symphonies are labelled by display name; the Composer hash appears only in a tooltip. Hash and normalized display name are separate key spaces (the Performance picker sends the hash, the Advisor picker keeps the name).
- Stored enums read as words through one mapping, `app.advisor_words` (`_ADVISOR_WORDS`; an unmapped value reads as its own words, never raw), registered as a Jinja filter. `et_stamp` (`analytics.format_et_stamp`) is the one Eastern time formatter; the missing value is an em dash glyph in the rendered text (`ET_STAMP_MISSING`).
- Max drawdown prints as a positive magnitude on Performance, Advisor cards and tenure evidence.
- Uppercased labels never turn alpha or rho into A or P.
- Text that carries a figure, a basis, a stamp, a data cue or a threshold clears 4.5:1 contrast in both themes by using an existing token (`--studio-ink-dim`); labels on accent-filled buttons clear 4.5:1 in dark as well as light.
- The accent: with no accent picked, no inline `--studio-accent` is written, so the dark theme keeps its own accent (`static/tweaks.js`, `accent: ''`); an earlier version's stored default is read as no pick.
- Closed-market wording: while the market is not open, labels stop saying "today" or "live" beside the last session's figures (hero Today row, card footer, panel empty lines, `HWM`, `LIVE RETURN`, `IF HELD`) and name the session date instead, true on first paint as well (`templates/index.html` first paint, `static/index.js` `applySessionWording`; the History heading uses `todays_exits_day`). Open-market wording is unchanged.

## Pages

**Dashboard (`/`).** Built on the shared shell. The hero chart and card sparklines draw from the first paint (`app._dashboard_initial_data`, first-paint helpers `_first_paint_verdict` and `_first_paint_dial` word and compute exactly what `static/index.js` writes on a poll), a refresh never empties, rebuilds or re-animates a drawn chart, and a theme or accent change recolours the charts without a reload. Picking an account reloads the dashboard for that account. A fleet-correlation banner shows when an alert is active and Dismiss is recorded. The detail panel is titled by the symphony's display name and fills itself when state arrives; at phone width the floating gear is hidden while the detail panel or the chat panel is open. The Max DD row follows the picked window (it matches Performance's for that window, or says it cannot supply one); an unknown Max DD or velocity prints a dash with no warning colour, and a value that rounds to zero prints without a minus sign. The Sleeves, CVaR and dollar panels are rendered from `_dashboard_panels_payload` and follow the poll.

**History (`/history`).** Opens on 30d. The day drilldown names each symphony and lists exits in time order and keeps the drilled day through polls. While the market is closed the exits table is headed by the last session's date, not "Today's exits", from the first paint; the table fits at 375 px with every column whole and no line ending inside a word.

**Performance (`/performance`).** One sign per delta, Max DD as a positive magnitude, friction drag to two decimals, and no row without data (a symphony with no replay sample has no Replay row; one note names how many lack a sample). Each panel renders independently, with the data's age. The preconditions note states its real sample: all position epochs. The exit-turnover note names no internal table. A failed `GET /api/exit-turnover` draws a dash row, never zeros. The Vol (20d) hint says daily standard deviation in percent (`math_engine.calculate_20d_vol` returns the daily standard deviation in percent), not annualised. The Risk Profile states its 60 day window.

**AI Advisor (`/ai-advisor`).** Eight tabs (Overview, Correlations, Retirement, Asset Swaps, Logic Changes, Chat, Strategy Builder, Frontrunner Builder); Retirement is its own tab, no longer a panel inside the Overview. The Overview opens on the Retirement pointer and the advisor controls before the Prism block, with one status line per guardrail producer (history behind an expander) and at most 12 autotune cards, latest run per symphony, with a drawn sparkline (Chart.js is loaded on this page). Chart.js 4.6.1 is served from `static/vendor/`.
- Retirement tab: the actionable card first; two labelled run buttons, "Run recommender" (`POST /ai-advisor/retirement/run`, refused while NYSE is open) and "Run tenure review" (`POST /ai-advisor/retirement/review/run`, no market gate); the last-run block's basis line in words (`app.retirement_basis`); exclusion reasons as sentences; tenure rows and evidence as described in [advisors_tenure_review.md](advisors_tenure_review.md).
- Correlations tab: a colour-filled matrix of the live symphonies computed from the same realized Composer series and the same latest successful retirement run as the Retirement tab, with no Composer call at render (`app._retirement_correlation_matrix_view` and its helpers). Cells are filled by signed colour (`_retirement_correlation_fill_pct`, band bounds `_CORRELATION_MODERATE_BOUND = 0.40`, fill range `_CORRELATION_FILL_PCT_MIN = 15.0` to `_CORRELATION_FILL_PCT_MAX = 45.0`); each cell exposes its aligned days and date window; one thin marker flags low depth against the recommender's 30 and 181 day gates; excluded symphonies are listed with sentence reasons; each symphony's first and last series dates are shown; and no run, a failed run and too few symphonies each have an honest state. The as-of names the last trading date and the run time in ET.
- Chat's example prompts name only flows the page can start; Discuss on a card opens Chat with its context loaded, and on a rejected candidate it never says the candidate cleared the gate.
- Strategy and Frontrunner cards: backtest figures are labelled as backtest figures, with a window only where one is stored (no window is invented; nothing stores a Frontrunner backtest window). A Frontrunner build signals its end through `GET /api/frontrunner-build/last-run`.
- The tabs are one horizontally scrolling row at phone width, and the active tab is scrolled into view on load and on every tab switch.

**Settings (`/settings` and the per-symphony modal).** Reset to globals works; the live toggle is read-only. After a failed settings load the master section binds no control to empty data (no literal DRY RUN, no editable 09:30, Save and Discard unreachable) and the Live execution switch shows no position and cannot be operated until a later good load. Symphonies the shared rule finds no longer held are listed dimmed under "No longer held". The flush confirm reads `GET /api/armed-symphonies` (live `bot_state`, never the frozen snapshot, filtered to real symphony entries) instead of the whole state. A flush keeps every post-mortem file dated on or after the production go-live floor (`_PRODUCTION_GO_LIVE_DAY = "2026-06-22"`) and still deletes synthetic files before it that are not in `_REAL_POST_MORTEM_DATES`.

**Header (`templates/_chrome.html`, `static/chrome.js`).** One precedence, one writer (`renderEngineLabel`): Connection Lost, Not updating (no data for over 90 seconds), Degraded, Closed, Rebalance pause, Opening, Stale (last cycle older than 2 minutes), Live. Degraded outranks Closed. While the market is closed a Degraded header shows no countdown and no tooltip clause about the next minute (the closed wording for `engine_terminated` is `The last engine run did not finish and was ended.`). Every age is measured on `performance.now()` receipts or the response's `Date` header, never the browser's wall clock. The four pages other than `/` follow the engine through `GET /api/header-status`. The theme applies before first paint and across tabs.

## Security changes made in the same program
- `renderDetailLogs` and `renderDetailVars` render text as text: a symphony name carrying markup shows literally. Suggestion Apply and Dismiss use data attributes and a listener, so a name with an apostrophe works.
- `_validate_csrf` reads the `csrf_token` form field only on the login endpoint; every other route needs the `X-CSRF-Token` header. A POST whose `Sec-Fetch-Site` is `same-site` or `cross-site` is refused 403 (`_REFUSED_FETCH_SITES`). The token is compared as bytes, so a non-ASCII token is a clean 403. A refused login form is answered with the login page itself and an expired-form line (`_csrf_before_request`).
- `POST /api/settings` validates every value before any write, all or nothing (`_settings_global_value_is_valid`): a finite number for numeric parameters, `H:MM` or `HH:MM` with hours 0 to 23 for `EXECUTION_START_TIME`, and `per_symphony` or `port_level` for `EXIT_AUTHORITY`. A bad value anywhere is a 400 that leaves `.env` byte-identical. `LIVE_EXECUTION` and credential keys remain outside `_SETTINGS_WRITE_ALLOWLIST`.
- `advisors/composer_series_client.py` does not follow redirects.
- Panic Confirm has an in-flight guard; the liquidation request bytes and the `/api/sell_account` route are unchanged.
- The retirement recommender and the tenure review no longer defeat each other's explanation reuse: reuse compares a row to the newest row written by the same producer (`app._retirement_row_producer`, `_retirement_prior_raw_for`).
