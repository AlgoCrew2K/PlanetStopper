# Feature: Advisor Generation Quality — sophisticated, data-informed, diverse generative output
Status: ready
Created: 2026-07-11

## Summary
Remediation of a **proven, systemic defect** in the AI-advisor's two LIVE generative engines: they emit rudimentary, near-identical, data-inert candidates ("rudimentary garbage" — operator, correct). The empirical overfitting gates (Harvey-Liu BHY FDR / PBO / CRRA-EU / backtest) are the RIGHT judge of simple-vs-complex and already auto-cull gratuitous complexity — but generation **starves** them, emitting only bare-minimum shapes, so "simple wins" is vacuous. This cycle makes the two generators produce **sophisticated + structurally-diverse + real-data-informed** candidate slates and lets the existing gates decide; it also root-cause-fixes the Atlas cache so those data inputs never cold-miss live Mongo (real money).

Three confirmed defect clusters (diagnostics: `frquality` + `frsurvey` + `frcache`, PM-verified — see `.claude/PM-ACTIVE-WORK.md` THREAD H / H2):

1. **Frontrunner (`advisors/frontrunner_builder.py`)** — the single worked example `_EXAMPLE_OVERLAY` (:602) is a 2-tier single-RSI scale-in that anchors Fable to structural isomorphs; the prompt (:661) never asks for compound/multi-signal logic; Atlas is fed as 4-scalar fingerprints (`_gather_atlas_frontrunner_patterns` :1133) that carry zero structural tokens (probe-confirmed) and cannot convey complexity; and a `"kind" in cascade.overlay_tree` guard (:1185, :1290) always fails because the detector's `overlay_tree` is Composer `step`-keyed, so `watched_tickers` is permanently `[]` -> **every symphony gets an identical generic prompt**. Compound/nested output is already reachable (compiler + schema support it) — this is a soft prompt-design + data-plumbing ceiling, not a hard capability gap.

2. **Strategy Builder (`advisors/build_plan_generator.py`)** — a high ceiling (Opus, 16384 tokens, the prompt already teaches the full compound grammar :993-1016) squandered by 3 shallow worked examples (:747/:781/:825), objective signatures that ask the *minimum* (`_OBJECTIVE_SIGNATURES` :881, "AT LEAST 2 sleeves"), an admission filter that passes on that minimum (`plan_matches_objective` :521), and asset-only diversity (dedup is a SHA over the whole root `_root_fingerprint` :441, so structural clones with swapped tickers pass as "distinct"). Critically, the Atlas community strategies are **never embedded in the generation prompt** — `_build_generation_prompt` (:912) takes no atlas argument; the strategies are appended to the gate pool *after* generation (`strategy_builder_engine.py:826`), so the generator learns from 3 toy examples and never from the best real strategies.

3. **Atlas cache (`advisors/atlas_cache.py`)** — `cached_pull` (:67) never CREATEs its table; `init_atlas_cache` (:52) is called only by `universe_provider`. So `community_strats` and the frontrunner path cold-miss on any fresh DB (SELECT and INSERT both hit `no such table`, both swallowed -> **live Mongo query on every call** = real money). Root-cause fix: `cached_pull` idempotently ensures the table exists on connect so no caller can cold-miss.

The bar for "done": **demonstrably sophisticated + data-informed + diverse candidates, empirically gate-validated** — never "it ran / wrote an observation."

## Acceptance Criteria

The generative core is a non-deterministic LLM, so the ACs split into **deterministic prompt/plumbing contracts** (AC-1..AC-11, RED-able in CI against the current code) and **one opt-in empirical proof** (AC-12, live, PM-run). Sophistication is defined by concrete structural metrics — nesting depth, distinct-indicator count, presence of compound (`any`/`all`) conditions, condition/node count — so every criterion gives a RED test something measurable.

- [ ] **AC-1 (Frontrunner prompt invites + exemplifies compound/multi-signal):** `frontrunner_builder._build_generation_prompt` output (a) explicitly instructs the model to emit compound (`any`/`all`) / multi-indicator conditions where warranted, and (b) embeds at least one **compiler-verified** compound (`if_compound`) worked exemplar alongside or in place of the flat 2-tier `_EXAMPLE_OVERLAY`. RED today: the prompt embeds only the single flat 2-tier RSI `_EXAMPLE_OVERLAY` and mentions compound only mechanically (ellipsis, no exemplar). Test asserts on the prompt string (deterministic seam) + compiles the new exemplar through the real `plan_tree_compiler`.

- [ ] **AC-2 (Strategy Builder signatures + examples demand layered structure, not the minimum):** `_OBJECTIVE_SIGNATURES` and the emitted prompt request layered / multi-signal structure per objective (e.g. cut_drawdown = a regime gate **plus** a vol-aware sleeve; lift_risk_adjusted = a momentum filter **combined with** a second construct), and at least one of the embedded worked examples is non-shallow (compound condition and/or nesting depth >= 3). RED today: signatures ask "AT LEAST 2 sleeves" / a single construct (:881); all 3 examples are shallow (depth <= 2, single/flat condition). Test asserts the signature text and example depth/condition metrics exceed the current minimum.

- [ ] **AC-3 (Atlas embedded as real few-shot exemplars — Strategy Builder):** `build_plan_generator.generate_build_plans` / `_build_generation_prompt` accept the Atlas community strategies and embed them **in the generation prompt** as rendered full-structure exemplars (via `symphony_schema.render_rules_text` or an equivalent structural rendering that preserves conditions/nesting/weighting), NOT as scalar fingerprints and NOT gate-only. RED today: `_build_generation_prompt` takes no atlas argument (:912); candidates reach only the gate pool (`strategy_builder_engine.py:826`). Test: pass a known exemplar tree -> assert the prompt contains that exemplar's rendered structural tokens.

- [ ] **AC-4 (Atlas embedded as real structural exemplars — Frontrunner):** The Atlas signal fed into `frontrunner_builder._build_generation_prompt` carries **real structural exemplars** (rendered overlay subtrees or structural tokens — condition shapes, nesting, VIX-basket composition), not the 4-scalar `{vix_tickers, rsi_thresholds, watched_tickers, basket_node_count}` fingerprint. RED today: the fed payload has zero structural tokens (probe-confirmed: no compound/binary/any/all/nested tokens present). Test: assert the fed exemplar payload contains structural tokens absent from the current 4-scalar fingerprint.

- [ ] **AC-5 ("named input actually varies the result" — prompt level, both engines):** Feeding two materially different Atlas corpora (corpus A vs corpus B) produces two **measurably different** generation prompts for BOTH `build_plan_generator._build_generation_prompt` and `frontrunner_builder._build_generation_prompt`. RED today: the SB prompt is Atlas-independent (embeds nothing); the frontrunner prompt embeds an inert fingerprint slice that the output demonstrably moved away from. Test: corpus A != corpus B => prompt A != prompt B, for each engine (deterministic seam).

- [ ] **AC-6 (Structural diversity across the Strategy Builder slate):** The admitted N-plan batch exhibits STRUCTURAL diversity — a spread in nesting depth and condition/node count — not asset-only variation of one skeleton; admission/dedup collapses structural near-clones (identical skeleton, swapped tickers) so an all-shallow-clone slate cannot be returned as N "distinct" plans. RED today: `_root_fingerprint` (:441) is a SHA over the full root, so asset-swapped structural clones produce different hashes and all pass. Test: feed a mock tool payload of N asset-swapped clones of one shallow skeleton -> assert the admitted set is NOT N near-identical structures (collapsed to few / rejected below a structural-diversity floor).

- [ ] **AC-7 (No bare-minimum-only slate; the gate — not admission — decides simple-vs-complex):** A slate composed *solely* of the bare-minimum shape for the objective is rejected or surfaced with an honest reason; the returned batch must contain at least one candidate exceeding the minimum signature (a compound condition OR nesting depth beyond the toy example OR >=2 distinct indicators). A lone simple plan **alongside** richer ones is explicitly allowed — the empirical gate, not the admission filter, adjudicates whether simple beats complex. RED today: `plan_matches_objective` (:521) admits every minimum-satisfying plan with no sophistication/spread requirement. (See Clarifying Question 1 — hard-reject-simple vs. diversity-floor is an operator call.)

- [ ] **AC-8 (Frontrunner per-symphony specificity — step/kind guard fixed):** For a real Composer `step`-keyed incumbent `overlay_tree`, `watched_tickers` is populated (non-empty whenever the overlay references tickers), and two distinct symphonies yield two distinct `signal_context`/prompts. RED today: the `"kind" in cascade.overlay_tree` guard (:1185, :1290) always fails on step-keyed trees -> `watched_tickers` is always `[]` -> every symphony gets the identical `(none supplied)` prompt. Test: feed a step-keyed overlay_tree -> assert `watched_tickers` non-empty; feed two distinct incumbents -> assert distinct prompts. (Fix must use a step-aware collector — the detector's `frontrunner_detector._collect_tickers` — because the kind-keyed `_walk_overlay_tickers` returns empty on step-keyed input; deleting the guard alone is insufficient.)

- [ ] **AC-9 (Atlas cache never cold-misses — table self-created):** `atlas_cache.cached_pull` against a fresh DB with no `atlas_cache` table creates the table idempotently, caches the first fetch, and serves the second call from cache — `fetch_fn` is called **exactly once** across two calls on a cold DB. RED today: `cached_pull` never CREATEs the table, so a cold DB raises `no such table` on both SELECT and INSERT (both swallowed) -> `fetch_fn` called on every invocation. Test: temp DB path, no prior `init_atlas_cache`, two `cached_pull` calls -> `fetch_fn` count == 1, row persisted.

- [ ] **AC-10 (Degradation preserved — Atlas-down never blocks generation):** When the Atlas corpus is unavailable/empty (Mongo down, SRV timeout, empty result), BOTH generators still run using their built-in worked exemplars (no Atlas exemplars embedded), never raise, and log honest degradation (D-1). Test: `community_strats.load_community_strategies` returning `available=False` -> both `_build_generation_prompt` seams still produce a valid prompt and generation still returns candidates or an honest `reason`, no exception.

- [ ] **AC-11 (Gates unchanged — sophistication is generated, the gate is the judge):** The overfitting/acceptance path is unchanged by this cycle — richer candidates flow through the SAME `backtest_gate_engine.evaluate_candidate_batch` (BHY FDR + PBO + SPY-OOS), `strategy_builder_engine` gating, and frontrunner `_gate_and_accept_candidate`; a sophisticated-but-overfit candidate is still culled. Test: the existing gate/acceptance suites stay green (no signature or behavior change on the gate path), and a deliberately-overfit rich candidate is rejected by the gate.

- [ ] **AC-12 (EMPIRICAL PROOF — opt-in live E2E, PM-run, not CI):** A real end-to-end generation run produces, for BOTH engines, at least one candidate **materially richer** than the current single-RSI 2-tier isomorph — evidenced by >=1 compound (`any`/`all`) or multi-indicator condition AND nesting/condition-count beyond the toy exemplar — AND **demonstrable Atlas influence** (candidates differ when the embedded corpus is swapped, and/or a structural motif present in the embedded Atlas exemplars but absent from the built-in toy example appears in the output). RED today: live output is the 2-tier single-RSI isomorph with Atlas-inert generation. This is the operator-facing acceptance bar; it is opt-in (`--include-live` / PM-run) and gated behind real API spend.

## Architecture
Files and functions to change (WHAT, grounded in current code — final construct choices are Gate-2/implementer decisions):

**`advisors/frontrunner_builder.py`**
- `_EXAMPLE_OVERLAY` (:602) — add/replace with >=1 compiler-verified compound/multi-signal exemplar so anchoring pulls toward sophistication (anchoring is the strongest lever per `frquality`).
- `_build_generation_prompt` (:649) — enrich to invite compound(`any`/`all`)/multi-indicator logic; consume real structural Atlas exemplars in the `atlas_patterns` slot instead of the 4-scalar fingerprint line (:678).
- `_gather_atlas_frontrunner_patterns` (:1133) — yield real structural exemplars (rendered subtrees / structural tokens via `symphony_schema.render_rules_text`), with de-dup/diversity, not the `{vix_tickers, rsi_thresholds, watched_tickers, basket_node_count}` fingerprint (:1179-1190).
- The `"kind" in cascade.overlay_tree` guard at `_gather_...` (:1185) and `_run_build_for_symphony` (:1290) — replace the kind-keyed `_walk_overlay_tickers` path with a **step-aware** ticker collector (`frontrunner_detector._collect_tickers`) so `watched_tickers` populates from step-keyed Composer trees.

**`advisors/build_plan_generator.py`**
- `generate_build_plans` (:1037) + `_build_generation_prompt` (:912) — thread an Atlas/community-exemplar argument through and embed rendered structural exemplars in the prompt (sourced from `CandidateInfo.tree`, which already carries the full tree at :1302, or `community_strats` docs' `"tree"` at :328).
- `_OBJECTIVE_SIGNATURES` (:881) — raise from minimum to layered/multi-signal per objective.
- The 3 worked examples `_EXAMPLE_PLAN` / `_EXAMPLE_IF_PLAN` / `_EXAMPLE_IF_COMPOUND_PLAN` (:747/:781/:825) — ensure at least one non-shallow exemplar (the compound example exists but is minimal; deepen and/or re-anchor).
- `_root_fingerprint` (:441) + the admission loop (:1117-1147) — add a structural-diversity term (depth/condition-count aware) so structural clones collapse and an all-shallow-clone slate cannot fill the N slots; add the sophistication/spread admission per AC-7.
- `plan_matches_objective` (:521) — keep as the objective-signature source of truth; the sophistication/diversity check is additive, not a replacement (a lone simple plan must still validate).

**`advisors/strategy_builder_engine.py`**
- `propose_strategies` (:767) — pass the sourced Atlas community strategies into `generate_build_plans` for **generation** (currently they enter only the gate pool at :826). The gate pooling stays.

**`advisors/atlas_cache.py`**
- `cached_pull` (:67) — idempotently ensure the `atlas_cache` table exists on connect (call `init_atlas_cache()` at entry, or `CREATE TABLE IF NOT EXISTS` inside both the read and write connections) so no caller cold-misses. `init_atlas_cache` (:52) already has the exact DDL.

**Reused, unchanged (guardrails):** `advisors/backtest_gate_engine.py::evaluate_candidate_batch`, `advisors/acceptance_gate.py`, `math_engine.compute_pbo`, `advisors/plan_tree_compiler.py` (still the compile/validate gate for every generated tree), `advisors/symphony_schema.py::render_rules_text` + `validate_tree`.

## Edge Cases
- Atlas unavailable / empty / SRV-DNS timeout -> generation proceeds with built-in exemplars only; never raises; honest degradation logged (AC-10). Preserves the existing `community_strats` D-1 timeout contract (`_bounded_fetch_fn`, `AtlasFetchTimeout`).
- Atlas corpus present but no exemplar renders cleanly (malformed tree, `render_rules_text` yields empty) -> skip that exemplar, continue; empty exemplar set degrades to the no-Atlas path.
- All generated candidates fail the sophistication/diversity admission -> return empty plans with an honest `reason` (mirror the existing "no plans matched the {obj} signature" path :1143-1147), never a silent `reason=None`.
- Frontrunner incumbent overlay references no tickers (degenerate) -> `watched_tickers` legitimately empty; the AC-8 assertion is "non-empty **when** the overlay references tickers," not unconditionally.
- Structural-diversity term must not reject a legitimately diverse slate that happens to share depth — diversity is a spread across >=2 structural dimensions (depth AND condition/node count), not a single-axis threshold.
- Prompt-size growth from embedding rendered Atlas exemplars must stay within `MAX_OUTPUT_TOKENS` budget headroom and the bounded exemplar count (cap embedded exemplars; de-dup near-identical ones) — do not reintroduce the 57.7MB-pull-for-inert-hint waste.
- Cold atlas-cache DB under a concurrent writer -> `CREATE TABLE IF NOT EXISTS` is race-safe (idempotent DDL); WAL already enabled.

## Security / Overfitting Considerations
- **The gates are the judge; generation only widens the search.** Richer, more diverse candidates raise the degrees-of-freedom / multiple-testing burden. The existing Harvey-Liu BHY FDR (`n_effective` over the full batch), PBO veto (`pbo > 0.5`), CRRA-EU haircut, purge/embargo folds, and SPY-OOS baseline MUST remain the sole arbiter of accept/reject and MUST NOT be weakened to let sophisticated candidates through. Complexity that does not empirically prove out is culled — that is the intended behavior, not a failure of this cycle. AC-11 pins the gate path unchanged.
- **DoF-ledger honesty:** if the widened search materially increases candidates-per-run, the search breadth recorded to the DoF ledger must reflect it (no under-counting the multiple-testing exposure). Do not silently raise `MAX_CANDIDATES_PER_RUN` / `N_PLANS_PER_OBJECTIVE` without the ledger reflecting the larger search.
- **No trade path touched.** All engines here are advisory-only, off-execution-path, not in `_SETTINGS_WRITE_ALLOWLIST`, no `LIVE_EXECUTION`. This cycle changes generation quality only; it must not introduce any Composer write/deploy or dashboard trade affordance.
- **Real-money robustness (atlas_cache):** the cold-miss fix prevents live Mongo hammering (provider bill). Weekly TTL + `force_refresh` semantics unchanged; only the table-existence guarantee is added.
- **D-1 preserved everywhere:** all generative/cache paths keep the never-raises + `type(exc).__name__`-only error contract.

## Testing Strategy
- **Prompt-contract unit tests (deterministic, CI):** inspect `_build_generation_prompt` output for both engines via the existing prompt-builder seams — assert compound/multi-signal invitation (AC-1/AC-2), embedded rendered Atlas exemplars (AC-3/AC-4), and corpus-varies-prompt (AC-5). RED against current prompts, GREEN after the fix. These carry the sophistication+data-use contract without a live model round-trip.
- **Admission/diversity unit tests (deterministic, CI):** feed hand-crafted mock tool payloads to `generate_build_plans`' admission path — a slate of N asset-swapped shallow clones must collapse/reject (AC-6), an all-minimum slate must be rejected or reasoned (AC-7), a genuinely diverse slate must pass. Use `plan_tree_compiler` to prove exemplars/candidates still compile.
- **Frontrunner guard-bug unit tests (deterministic, CI):** pass a real Composer `step`-keyed `overlay_tree` (captured shape) -> assert `watched_tickers` non-empty and two distinct incumbents -> distinct prompts (AC-8).
- **Atlas-cache unit test (deterministic, CI):** temp `ATLAS_CACHE_DB_PATH`, no prior init, two `cached_pull` calls with a counting `fetch_fn` -> assert count == 1 and row persisted (AC-9). Add a cold-DB regression asserting no `no such table` escapes.
- **Degradation tests (deterministic, CI):** patch the Atlas loader to `available=False` -> both generators still emit + never raise (AC-10).
- **Gate-invariance tests (CI):** existing gate/acceptance suites stay green; add one deliberately-overfit rich candidate -> gate rejects it (AC-11).
- **Empirical E2E (opt-in, `--include-live`, PM-run, NOT CI):** one real run per engine -> assert output structural metrics (compound present, depth/condition-count beyond the toy exemplar) and Atlas influence (corpus-swap changes output, or an exemplar-only motif appears) (AC-12). This is the operator acceptance bar and is run by the PM against real APIs, consistent with the project's live-functional-test merge gate. Local full-suite runs stay within the `ALPHABOT_TEST_MEM_CAP_GB` cap; the live E2E is `-n0` targeted.
- **TDD composition:** Toxic Pair (`quant-test-writer` adversarial RED <-> minimalist implementer) + `quant-code-reviewer` + a matched advisor/integration specialist + mandatory `doc-gen` doc-writer, one shared worktree/branch.

## Clarifying Questions
1. **AC-7 admission policy — hard-reject vs diversity-floor.** THREAD H's principle says "the empirical gate is the judge of simple-vs-complex," which argues admission should enforce *diversity* (no all-clone slate) and let the gate decide, allowing a lone simple plan through. But the dispatch also says "admission/dedup rejects the bare-minimum shallow plan." My default reconciliation: admission enforces a structural-diversity spread + requires >=1 above-minimum candidate in the slate, but does NOT hard-ban a simple plan that sits alongside richer ones (the gate adjudicates). Confirm, or specify a strict per-plan sophistication floor.
2. **Search-breadth budget.** Widening generation increases the multiple-testing / DoF burden. Should `N_PLANS_PER_OBJECTIVE` / `MAX_CANDIDATES_PER_RUN` grow to accommodate more diverse candidates (with the DoF ledger reflecting it), or stay fixed (richer candidates displace clones within the current budget)? Default: keep the budget fixed, replace clones with diverse candidates.
3. **AC-12 Atlas-influence proof form.** Is the acceptance evidence the stronger "swap the corpus -> output changes" (two live runs, ~2x API spend) or the cheaper "a structural motif from the embedded exemplars, absent from the built-in toy example, appears in the output" (single run)? Default: the cheaper single-run motif-trace, with the corpus-swap as an optional stronger confirmation.
