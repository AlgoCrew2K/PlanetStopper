# Feature: Advisor Prompt Caching (Ephemeral Cache Breakpoints)
Status: ready
Created: 2026-07-29

## Summary
Zero of the six advisor Anthropic-SDK call sites (`build_plan_generator.py`, `frontrunner_builder.py`, `asset_swap_engine.py`, `logic_change_engine.py`, `advisor_chat.py`, `lens_pipeline.py`) currently send any `cache_control` marker — confirmed by a repo-wide grep (`anthropic~=0.85.0` is pinned, a version well past caching-beta; zero existing `cache_control` occurrences anywhere). Several of these calls resend a large, byte-invariant chunk of text — a DSL-grammar block, worked JSON examples, a static system prompt, or a tool JSON schema — either within a single call's own truncation-retry loop, or across back-to-back calls in the same run (weekly scheduler, an operator chat session), paying full input-token price every time. This cycle adds ephemeral (5-minute TTL) `cache_control` breakpoints at the genuinely-invariant boundaries in five of the six call sites to cut direct Anthropic API cost — a request-shape annotation only, with the exact text reaching the model, the model itself, and everything the model returns byte-unchanged. The sixth (`lens_pipeline.py`'s one-shot nightly synthesis call) is deliberately excluded (see Decisions). The council path (`prism_scheduler.py`'s headless `claude -p` subprocess, OAuth/subscription-billed) is untouched — it is not an SDK call and cannot carry `cache_control` at all.

## Acceptance Criteria
- AC-1: Each of the 5 in-scope call sites gains at least one `cache_control: {"type": "ephemeral"}` breakpoint, placed per the Architecture table below (either on a message-content block, the `system` block, or the last entry of the `tools` array).
- AC-2 (byte-preservation guard, HARD): the literal text sent to the model on every call site is unchanged from today — `cache_control` is a shape/annotation addition, never a content edit. In particular, `build_plan_generator._build_generation_prompt`'s signature and return value are NOT modified; the existing golden-fixture test (`tests/advisors/test_build_plan_generator_reasoning_context.py::test_from_scratch_prompt_byte_identical_to_golden_fixture_captured_pre_r2_1`, pinned against `tests/fixtures/strategy_builder/generation_prompt_from_scratch_baseline.json`) passes UNMODIFIED.
- AC-3: No prompt-text reordering this cycle (Tier-1 only, see Architecture/Decisions) — every cache breakpoint wraps the ALREADY-computed prompt string(s) at the SDK-call boundary, never restructures the string-building functions.
- AC-4: The ~13 existing tests that assert on `messages.create()`/`system=` kwargs as a bare string (enumerated below) are retrofitted via ONE new shared shape-agnostic helper — not 13 ad hoc edits — before/alongside the cache_control change, so the mechanical shape change (string -> content-block list) does not produce a false-RED wave unrelated to this feature's actual logic.
- AC-5: Tool-schema caching applied where the schema is reused across a same-run loop: `_EMIT_BUILD_PLANS_TOOL` (build_plan_generator), `_EMIT_OVERLAY_TOOL` (frontrunner_builder), `_EMIT_SWAP_CANDIDATES_TOOL` (asset_swap_engine), `_EMIT_LOGIC_EDITS_TOOL` (logic_change_engine) each gain `cache_control` on the tool definition.
- AC-6: `prism_scheduler.py` (the council/OAuth subprocess path) carries ZERO diff.
- AC-7: `lens_pipeline.py`'s nightly synthesis call carries ZERO diff — the exclusion is an explicit, documented Decision, not a silent omission.
- AC-8: Full existing test suites for all 6 touched modules plus `tests/ai_advisor/test_chat_engine.py` pass with zero non-shape-related regressions (both ruff gates too).
- AC-9: A PM-run live probe against the real Anthropic API (post-GREEN, one call site — `advisor_chat.py` recommended, needs no live Composer/portfolio data) confirms `response.usage.cache_creation_input_tokens > 0` on the first call and `response.usage.cache_read_input_tokens > 0` on an immediate repeat call with the same system prompt. Tests-green is necessary, never sufficient for this feature — the whole point is a real Anthropic-side cache hit, which no mock can prove.

## Architecture
Call-site inventory (all six confirmed via grep; no other `messages.create`/`anthropic.Anthropic` sites exist in the advisor suite):

| # | Call site | Retry/reuse pattern | Breakpoint placement | Reorder needed? |
|---|---|---|---|---|
| 1 | `advisors/build_plan_generator.py:1098` (`generate_build_plans`) | `prompt` computed ONCE, reused verbatim across `MAX_GENERATION_ATTEMPTS=3` retries on `stop_reason=="max_tokens"` | Wrap the existing (unmodified) prompt string as a single `content=[{"type":"text","text":prompt,"cache_control":{"type":"ephemeral"}}]` block. Also mark `_EMIT_BUILD_PLANS_TOOL` (`cache_control` on the tools array). | No — guaranteed intra-call retry win with zero reorder. Cross-objective (4 objectives/run) reuse would additionally require moving the invariant DSL-grammar+examples block (currently NOT prefix-anchored — the string opens with `"TASK: Generate exactly {n_plans}... objective='{obj_name}'"` before the grammar) to the front — deferred, see Decisions. |
| 2 | `advisors/frontrunner_builder.py:858` (`generate_candidate_overlay`) | `prompt` computed ONCE before `for attempt in range(n_attempts)`, same string resent on each retry | Same whole-string wrap as #1. Also mark `_EMIT_OVERLAY_TOOL`. Note: this prompt's invariant grammar/hard-requirements block IS already prefix-anchored (opens the string) — a stable-prefix-only breakpoint is a small, safe stretch goal if time allows, but not required for AC-1 (whole-string wrap already captures the guaranteed retry-loop win). | Not required; optional low-risk stretch (see Edge Cases). |
| 3 | `advisors/asset_swap_engine.py:1161` (`generate_reasoned_swap_candidates`) | One-shot per symphony×objective call (no retry loop); prompt text itself is short and mostly volatile (objective + reasoning_context + universe sample) — no large invariant text block worth caching | Cache `_EMIT_SWAP_CANDIDATES_TOOL` on the tools array instead of the prompt — identical across every symphony×objective call within one weekly-scheduler run. | No |
| 4 | `advisors/logic_change_engine.py:880` (`generate_reasoned_logic_candidates`) | Same shape as #3 | Cache `_EMIT_LOGIC_EDITS_TOOL`. | No |
| 5 | `advisors/advisor_chat.py:384` (`explain_artifact`) | `system=_EXPLAIN_ONLY_SYSTEM_PROMPT` — a fully static, non-interpolated ~1.5k-char module constant, resent unchanged on every operator chat turn within a session | Convert to `system=[{"type":"text","text":_EXPLAIN_ONLY_SYSTEM_PROMPT,"cache_control":{"type":"ephemeral"}}]`. The volatile per-turn content (`question`, `artifact`) stays entirely in `messages`, untouched. | No — cleanest, lowest-risk change in the set (no existing test pins the `system` kwarg's shape; see Testing Strategy). |
| 6 | `advisors/lens_pipeline.py:288` (nightly sentiment synthesis) | Single call, once/night, no retry | EXCLUDED this cycle — see Decisions. | N/A |

**Minimum-cacheable-prefix caveat:** Anthropic requires a cached segment to exceed a per-model token floor before it actually gets cached (silently — no error, just `cache_creation_input_tokens`/`cache_read_input_tokens` read 0). cache-impl must verify against the currently-pinned `anthropic~=0.85.0` SDK docs whether a beta header is still required at this version (unlikely, but confirm rather than assume) and should not assume every breakpoint here is large enough to actually activate — AC-9's live probe is the only way to know, and a below-floor breakpoint should ship anyway (harmless/inert) rather than being pulled on suspicion alone.

**Existing tests requiring the shape-agnostic retrofit (AC-4)** — each currently asserts `messages.create()` kwargs' `content`/`system` as a bare string via substring checks; converting to a content-block list breaks every one of these mechanically unless retrofitted first via one shared helper:
`tests/advisors/test_build_plan_generator_reasoning_context.py`, `test_build_plan_generator_truncation.py`, `test_build_plan_generator_property.py`, `test_build_plan_generator.py`, `tests/advisors/test_logic_change_engine_reasoned_generation.py`, `test_logic_change_engine_reasoning_context.py`, `test_logic_change_engine_credentialless_bounded_prompt.py`, `tests/advisors/test_frontrunner_builder_signal_wiring.py`, `test_frontrunner_builder.py`, `tests/advisors/test_asset_swap_engine_reasoning_context.py`, `test_asset_swap_engine_candidate_universe_validation.py`, `tests/ai_advisor/test_cycle4_lens_pipeline.py` (lens_pipeline is excluded from the feature itself, but its existing test still touches `messages.create` shape and should be swept for consistency), `tests/ai_advisor/test_chat_engine.py` (uses `MagicMock`-style call recording, no exact-string assertion found on `system=` — lowest risk, but still worth the shared helper for consistency).

## Edge Cases
- Truncation retry (build_plan_generator/frontrunner_builder): the 2nd/3rd attempt after `stop_reason=="max_tokens"` must hit cache (same prompt, same model) — this is the guaranteed win and should be the primary thing cache-test proves with a recorded-call-count/cache_control-presence assertion (a live `cache_read_input_tokens` assertion isn't mockable; assert the breakpoint marker is present and identical across attempts instead).
- All-falsy volatile sections (no `reasoning_context`, no `correlation_data`, no `edge_signals`) — the cache breakpoint placement must not depend on which optional sections happen to be present; the invariant portion is invariant regardless of the caller's optional kwargs.
- A mid-session model override (`ADVISOR_SUGGESTION_MODEL`/`ADVISOR_SYNTHESIS_MODEL`/`FABLE_MODEL` env change) — Anthropic scopes the cache to an exact (model, prefix) pair; a model swap is a guaranteed cache MISS, never a correctness problem — falls back to normal uncached billing silently.
- Cache-breakpoint budget: Anthropic allows up to 4 `cache_control` breakpoints per request across `system`/`tools`/`messages`, in ascending position order. Every site here uses at most 2 (one tools-array breakpoint + one message/system breakpoint) — well under budget, but cache-impl must not add a breakpoint before an earlier one that's absent (ordering matters).
- Frontrunner_builder's optional stretch (stable-prefix-only breakpoint instead of whole-string wrap) must not touch the two "conforming example" JSON blocks that currently sit AFTER the volatile `signal_context` section — moving them would count as prompt reordering (Tier-2, out of scope) even though they're themselves invariant text.

## Security Considerations
- `cache_control` is a request-shape annotation only, not a new data channel — no new external input surface introduced.
- No secrets ever enter a cached block: the cached content in every site is grammar/tool-schema/system-prompt/static-example text; operator-specific data (`reasoning_context`, `correlation_data`, live signal data, the artifact in advisor_chat) stays in the uncached volatile portion by construction, per the Architecture table above — never moved into a cache breakpoint.
- Anthropic-side ephemeral cache entries are scoped per API key/org under Anthropic's own isolation model — no new cross-tenant exposure.

## Testing Strategy
- **RED (cache-test):**
  1. Land the shared shape-agnostic content-extraction test helper first (e.g. `tests/advisors/_prompt_cache_test_helpers.py`), used to retrofit the ~13 existing tests enumerated above to read prompt text from either a bare string OR a content-block list — this must go green BEFORE any `cache_control` code lands (proves the retrofit itself doesn't change what's being asserted).
  2. New RED tests per call site (mocked `_build_client`/`messages.create`, no live network) asserting: the correct block/tool/system carries `cache_control: {"type": "ephemeral"}`; the retry-loop calls (build_plan_generator, frontrunner_builder) send an IDENTICAL cache-marked block on every attempt; the volatile content (reasoning_context/correlation_data/artifact/question) is verifiably NOT inside the cached block.
  3. A regression test that the golden-fixture byte-identical test (`test_build_plan_generator_reasoning_context.py`) still passes UNMODIFIED.
- **GREEN (cache-impl):** minimal SDK-call-boundary changes only — no changes to any `_build_*_prompt`/`_build_*_generation_prompt` function's return type or internal ordering.
- Both ruff gates (`ruff format --check` + `ruff check`) before GREEN.
- **PM live probe (post-GREEN, AC-9):** one real (non-mocked) Anthropic API round-trip via `advisor_chat.explain_artifact` with a synthetic artifact, called twice in immediate succession — confirm `cache_creation_input_tokens > 0` then `cache_read_input_tokens > 0` in `response.usage`. This is the only verification that proves an actual Anthropic-side cache hit; it is run by the PM, not by pytest.

## Decisions
| Decision | Rationale |
|---|---|
| Tier-1 only this cycle — no prompt-text reordering | Captures the two highest-confidence, lowest-risk wins (guaranteed intra-call retry-loop hits on build_plan_generator/frontrunner_builder; advisor_chat's fully-static system prompt reused across a chat session) without touching the byte-identical-pinned `_build_generation_prompt`. Reordering build_plan_generator's DSL-grammar block to the front of the prompt (to also win cross-objective reuse within one scheduler run) is a separable, higher-risk follow-up — noted here, not built. |
| Cache tool schemas rather than prompt text for asset_swap_engine/logic_change_engine | Their prompt text is short and dominated by volatile per-call content (objective/reasoning_context/universe sample) — no large invariant block exists worth a breakpoint. The tool JSON schema is the only genuinely invariant, non-trivial content, and it repeats across every symphony×objective call in a weekly-scheduler run. |
| Exclude `lens_pipeline.py`'s nightly synthesis call | Single one-shot call, once per night, with no repeat inside the 5-minute ephemeral TTL — a cache-WRITE premium (cache writes cost more than an uncached call) with no corresponding cache-READ to offset it. Net negative ROI; excluding it is a real decision, not an oversight. |
| `prism_scheduler.py` council/OAuth path untouched | Not an SDK call — a headless `claude -p` subprocess billed via OAuth/Claude-subscription. `cache_control` is an Anthropic Messages-API request-shape field; a CLI subprocess invocation has no equivalent surface. |
| One shared test-shape-extraction helper, not ~13 ad hoc edits | Converting `content`/`system` from a bare string to a content-block list mechanically breaks every existing test that substring-checks it, regardless of this feature's actual logic. A single shared normalizer keeps the retrofit auditable and prevents drift across the 13 files. |

## Scope Boundaries
- **IN:** ephemeral `cache_control` breakpoints on the 5 call sites in the Architecture table (message-content and/or tool-schema breakpoints as specified); the shared test-shape-extraction helper; the PM live cache-hit probe.
- **OUT:** `lens_pipeline.py`'s synthesis call (excluded, Decision above); `prism_scheduler.py`'s council subprocess (not an SDK call, Decision above); any prompt-text REORDERING for cross-call/cross-objective reuse (Tier-2, deferred); any change to model choice, `MAX_OUTPUT_TOKENS`, `MAX_GENERATION_ATTEMPTS`, or retry semantics; Anthropic's separate 1-hour (non-ephemeral) cache tier — ephemeral 5-minute only, per the team-lead's brief; any change to what the model is asked to do or what it returns.
