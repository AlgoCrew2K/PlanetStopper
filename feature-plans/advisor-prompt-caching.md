# Feature: Advisor Prompt Caching (Ephemeral Cache Breakpoints)
Status: ready
Created: 2026-07-29
Revised: 2026-07-29 (r2) — corrects two mechanics the team-lead flagged against the r1 scope-narrowing: (a) build_plan_generator needs a stable-base/reasoning_context SPLIT, not a whole-string wrap; (b) frontrunner_builder's reorder moves ONLY the volatile signal hints to a trailing section — the hard-requirements block, node-shape description, and both examples stay in their existing relative order (r1 had incorrectly implied the examples also needed to move). r1 (2-site scope narrowing from the original 5-site draft) stays otherwise unchanged.

## Summary
Zero of the seven advisor Anthropic-SDK call sites currently send any `cache_control` marker (`anthropic~=0.85.0` is pinned, well past caching-beta; confirmed by repo-wide grep). Of the seven, cache-impl measured real token counts for the cacheable (invariant) portion of each prompt/tool bundle and found only TWO clear their model's minimum-cacheable-prefix floor: `build_plan_generator.py` (3,126-token reasoning_context-free base, clears Fable's 2,048-token floor) and `frontrunner_builder.py` (>2,048 tokens once the tool schema is included, needs a small content-preserving reorder to become a contiguous prefix). The other five — `asset_swap_engine.py` (393 tokens), `logic_change_engine.py`, `advisor_chat.py` (~537 tokens, under Opus 4.8's measured 4,096-token floor), `ai_advisor.request_suggestions` (uses `client.messages.parse`, not `.create` — missed in the initial grep, now confirmed measured-too-small), and `lens_pipeline.py` (excluded from the start, one-shot nightly call) — are documented here as measured-not-cacheable or explicitly out of scope, not silently dropped. This cycle adds ephemeral (5-minute TTL) `cache_control` breakpoints to the 2 real sites only. `cache_control` is a request-shape annotation — the exact text reaching the model, the model itself, and everything it returns stay byte-unchanged. The council path (`prism_scheduler.py`'s headless `claude -p` subprocess, OAuth/subscription-billed) is untouched — it is not an SDK call and cannot carry `cache_control` at all.

When `reasoning_context` is truthy, its `## OPERATOR CONTEXT` section is appended as a **separate, uncached trailing content block** — never folded into the cached region, since it is per-symphony volatile, never re-read from cache across a different symphony/run, and would only add a wasted cache-write premium if included. `_build_generation_prompt`'s signature and return value are NOT modified (AC-5) — the split happens entirely at the SDK-call boundary in `generate_build_plans`, not inside the prompt-builder.

## Edge Cases
- Truncation retry (build_plan_generator): the 2nd/3rd attempt after `stop_reason=="max_tokens"` must send the IDENTICAL two-block structure (same cached base, same optional trailing reasoning_context text) — cache-test proves this via block-structure equality across attempts (mock-provable), not a live cache_read count (not mockable).
- frontrunner_builder's `n_attempts` retry loop: same guaranteed-intra-call-hit property, on top of the reorder's cross-call benefit.
- build_plan_generator with `reasoning_context` omitted/`None`: the SDK payload must be a ONE-block content array (just the cached base) — no empty/dangling trailing block ever sent.
- AC-4's reorder must not change which text is inside vs. outside the hard-requirements/node-shape/examples region — a reviewer must be able to diff the OLD prompt string against the NEW one and see only the volatile hints block moving, zero net text added/removed/edited/reordered elsewhere.
- All-falsy `signal_context` (no `watched_tickers`/`atlas_patterns`/`edge_signals`) — the relocated trailing volatile section must still render its existing "(none supplied)" fallbacks; the cache breakpoint's placement must not depend on which of these are present.
- A mid-session model override (`ADVISOR_SUGGESTION_MODEL`/`FABLE_MODEL` env change) — Anthropic scopes the cache to an exact (model, prefix) pair; a model swap is a guaranteed cache MISS, never a correctness problem.
- Cache-breakpoint budget: Anthropic allows up to 4 `cache_control` breakpoints per request (across `system`/`tools`/`messages`, ascending position order). Both real sites use 2 (one tools breakpoint + one message breakpoint) — well under budget.

## Security Considerations
- `cache_control` is a request-shape annotation only — no new external input surface.
- No secrets in either cached block: build_plan_generator's cached base is DSL grammar + worked examples + objective/task text (no operator data — `reasoning_context`, which CAN carry operator-specific tree/stats detail, is always in the separate uncached trailing block); frontrunner_builder's cached prefix is the hard-requirements text + node-shape description + worked examples (no operator data) — the volatile `watched_tickers`/`atlas_patterns`/live edge-signal data stays in the uncached trailing section by construction.
- AC-4 is itself a security consideration: frontrunner_builder is the one module with a structural no-auto-trade boundary (`tests/security/test_frontrunner_no_trade_boundary.py`) — this cycle changes prompt-text ORDER only (relocating one block), never touches `composer_draft_client`/`approve_frontrunner_proposal`/anything on the write path, and ships downstream of all 4 existing gates unmodified.
- Anthropic-side ephemeral cache entries are scoped per API key/org under Anthropic's own isolation model — no new cross-tenant exposure.

## Decisions
| Decision | Rationale |
|---|---|
| Scope reversed from "5 sites, Tier-1 everywhere" (original draft) to "2 real sites + 5 documented-excluded" | Cache-impl's real `count_tokens` measurements showed asset_swap_engine/logic_change_engine/advisor_chat/ai_advisor.request_suggestions all fall under the cacheable-prefix floor for their respective models — shipping a breakpoint there would be inert (zero savings) for real added code/test surface. Only build_plan_generator (3,126 tok) and frontrunner_builder (>2,048 tok with tools) measured viable. |
| build_plan_generator gets a stable-base/reasoning_context SPLIT, not a whole-string wrap (r2 correction) | The r1 draft wrapped the entire returned string (base + optional appended `reasoning_context`) as one cached block. That works for the intra-call retry-loop guarantee either way, but wastes the cache-write premium on `reasoning_context` text that is per-symphony volatile and will never be re-read from cache on any other call. Splitting into a cached reasoning_context-free base + an uncached trailing block avoids that waste, at zero cost to the retry-loop guarantee and zero change to `_build_generation_prompt` itself. |
| frontrunner_builder's reorder relocates ONLY the volatile hints block (r2 correction, reversing r1's "move the examples up" framing) | The true prompt order is hard-requirements -> volatile hints -> node-shape description -> both examples. r1 incorrectly described the fix as moving the two examples up next to the hard-requirements block; the minimal, correct fix is to cut ONLY the volatile hints out of the middle and append them at the end — the hard-requirements block, node-shape description, and both examples were already contiguous relative to each other and need no independent move. This is a strictly smaller diff and avoids separating the node-shape description from the examples that illustrate it. |
| frontrunner_builder's reorder is in scope at all (reversing the earliest "Tier-1 only, no reorder anywhere" stance) | It is the only way to make that site's invariant content a contiguous, cacheable prefix. The reorder is (a) measured-viable, (b) pattern-precedented — mirrors build_plan_generator's own R2-1 `## OPERATOR CONTEXT` append, (c) content-preserving — no substring is edited, added, or removed, only the one volatile block's position changes, and (d) downstream-gated — the generated candidate still passes all 4 existing acceptance gates before it can ever reach Composer. |
| ai_advisor.request_suggestions correctly identified as a 7th real call site | Uses `client.messages.parse`, not `.messages.create` — absent from the original grep pattern. Measured too small to cache; documented here rather than silently left out of the audit trail. |
| Exclude `lens_pipeline.py`'s nightly synthesis call | Single one-shot call, once per night, no repeat inside the 5-minute ephemeral TTL — cache-write premium with no offsetting read. |
| `prism_scheduler.py` council/OAuth path untouched | Not an SDK call — a headless `claude -p` subprocess billed via OAuth/Claude-subscription; `cache_control` is an Anthropic Messages-API request-shape field with no subprocess equivalent. |
| `ai_advisor.py` cross-symphony lens-data caching deferred | A real, distinct opportunity (the 5 lens blocks are identical across every symphony in one scheduler run) but not measured/scoped this cycle — flagged as a follow-up candidate, not built. |
| One shared test-shape-extraction helper, scoped to the 2 real sites only | Converting `content` from a bare string to a content-block list mechanically breaks the 6 existing tests that substring-check it; a single shared normalizer keeps the retrofit auditable. The other 5 modules carry zero diff, so their tests need no retrofit. |

## Scope Boundaries
- **IN:** `cache_control` breakpoints on `build_plan_generator.py` (stable-base/reasoning_context content-block split + `_EMIT_BUILD_PLANS_TOOL`, no text reorder) and `frontrunner_builder.py` (minimal volatile-hints-only reorder + `_EMIT_OVERLAY_TOOL`, content-preserving); the shared test-shape-extraction helper scoped to those 2 sites' 6 existing test files; the PM live cache-hit probe against build_plan_generator.
- **OUT:** any code change to `asset_swap_engine.py`, `logic_change_engine.py`, `advisor_chat.py`, `ai_advisor.request_suggestions`, or `lens_pipeline.py` (all measured-not-cacheable or structurally excluded — documented, not implemented); `prism_scheduler.py`'s council subprocess (not an SDK call); `ai_advisor.py`'s cross-symphony lens-data caching (deferred follow-up); any change to model choice, `MAX_OUTPUT_TOKENS`, `MAX_GENERATION_ATTEMPTS`, retry semantics, or the frontrunner no-auto-trade boundary; any change to the CONTENT of any prompt (only build_plan_generator's tools-array + content-block split, and frontrunner_builder's single-block relocation, are in scope — never new/edited/removed text, never moving the hard-requirements/node-shape/examples text); Anthropic's separate 1-hour (non-ephemeral) cache tier — ephemeral 5-minute only.
