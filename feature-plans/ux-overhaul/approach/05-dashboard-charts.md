### Findings the design rests on (beyond the plan's Trigger)

1. The poll's hero series and `/api/hero-chart`'s series differ. The poll's `hist_bot`/`hist_held` come from `analytics.get_portfolio_bot_and_held_daily_returns()` with its default `days=125` (`app.py:2278-2290`, `analytics.py:1709-1711`) and its `hist_dates` from a second function, `get_portfolio_daily_returns_from_shadow(days=125)` (`app.py:2269-2273`, `analytics.py:1631-1633`). `/api/hero-chart/<token>` reads the bot/held function with `days=None` and compounds each window from 1.0 at its first day (`app.py:3604-3612`). No client slice of the poll payload reproduces the `1y` or `all` response once history passes 125 trading days, so the windowed series comes from the hero-chart code path only (AC-4, PM-3).
2. `dashboard()` never injects guard alpha: `get_api_state_dict` (`app.py:2407-2474`) returns `bot_state` and `portfolio_strip` only, and injection exists only in `get_state`'s open branch (`app.py:3407-3421`). The closed and pre-market branch (`app.py:2630-3093`) serves the close snapshot with no `guard_alpha` key, so at the Ref every after-hours poll replaces a triggered verdict with the dash glyph (`static/index.js:380-383`).
3. The card name renders `normalized_name or name` (`templates/index.html:1198`, `:1349`), and only `get_state`'s open branch stamps `normalized_name` (`app.py:3182`); the server render shows `name`, and the detail title (`static/index.js:440`) shows the lowercase key the poll added.
4. The account filter runs after the closed and pre-market branch has returned (`app.py:3146-3153` after `app.py:3072`), so after hours `/api/state?account=` returns every symphony (S-6.8, PM-7).
5. `POST /api/fleet-alert/dismiss` re-stamps `dismissed_at_et` on every call (`app.py:4918-4924`); the engine's `set_fleet_correlation_alert` clears it through `database.write_fleet_alert` (`alpha_bot_execution.py:497-519`, `database.py:2725-2734`) and its auto-clear deletes the row (`alpha_bot_execution.py:550-561`, `database.py:2770`).
6. JavaScript `toFixed` rounds exact binary ties away from zero; Jinja `"%.1f"|format`, Python `round` and the f-string in `analytics.format_dollar_saved` (`analytics.py:2271`) round them half to even (SC-2).
7. `pyproject.toml:85` runs pytest with `--strict-markers`, so a `browser` mark collects only once SC-7's registration (`pyproject.toml:90-94`) is in the branch.

Three cycles, each a Toxic Pair (`test-writer` running `/tdd` on the plan and this approach, `implementer` running `/tdd-implement` from the handoff, `/tdd-finalize` at close) on its own branch in its own worktree under `.claude/worktrees/`, with `.env` copied in and `git rev-parse --show-toplevel` plus `git rev-parse --abbrev-ref HEAD` checked before any edit (project worktree rule, suite Execution Model). A pair runs only its cycle's test files with at most 4 workers, never `-n auto`, one pytest invocation at a time on the PM host, and C1 runs `python -m pytest -m browser -n 0 tests/ui/test_dashboard_charts_browser.py` before its cycle-complete when its host has Playwright and the PM has set `UX_LAUNCHER_URL` (SC-7). Every cycle renders UI and changes code, so each head gets `qa`, `code-reviewer`, `ux-expert` with `behavioral-evidence-capturer`, and, because each changes an HTTP route's output or contract whose server render must agree with its client render, one `api-expert` and one `integration-auditor` dispatch per head. One `doc-gen` writes the slice's docs (the plan's Docs to Update) after every reviewer passes every head. After the three heads pass, the PM dispatches one task walkthrough (`ux-expert` in `Mode: task-walkthrough` with its capturer) on the assembled `ux-overhaul/05` head over T-1 to T-3. The plan is not sensitive, so no hidden `qa`.

Team size: 17 = 3 test-writer + 3 implementer + 1 qa + 1 code-reviewer + 1 ux-expert + 1 behavioral-evidence-capturer + 3 api-expert + 3 integration-auditor + 1 doc-gen

Captures use SC-8 Mode A and SC-1's capture rules, which this plan's C1 builds: wait on `body[data-dashboard-ready="1"]`, which is written only after every first-paint chart's entry animation has completed; reach refresh N by the 30 s poll or `window.loadState()` and wait on `body[data-refresh-count="N"]` (no scheduler, so no `cycle-complete` event); record `typeof Chart` and `Chart.version`; an undefined `Chart` is BLOCKED. `#fleet-dismiss-btn` is on the capturer's never-click list and Mode A refuses operator-action POSTs, so the dismiss scenarios are proven by Flask and node tests and, when an alert is active, by the PM's live check.
