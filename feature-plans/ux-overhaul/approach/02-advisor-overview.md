- C3 (Retirement tab, pointer, sentences, fragment): renders UI (Overview, Retirement).
- C4 (autotune bounds, Chart.js): renders UI (Overview); runs its SC-7 browser module before cycle-complete.
- C5 (observations, count accessor): renders UI (Overview); `sqlite-specialist` reviews the accessor's SQL (a JSON-column predicate on the state DB); runs its SC-7 browser module before cycle-complete.
- C6 (Overview order): renders UI (Overview); its head is the plan tip, where the full screenshot gate, S-4.18 and every browser module of the plan run.

Every head changes code and renders UI, so each gets `qa`, `code-reviewer`, and `ux-expert` with `behavioral-evidence-capturer` on an SC-8 Mode A launcher the PM provides; `/` is captured only after SC-1 readiness. Run now is never clicked on the launcher (Mode A refuses operator POSTs and the server's network); it is verified in the PM's droplet check (Merge Criteria). No API or pipeline surface changes, so no `api-expert`, `pipelines-expert` or integration auditor; `flask-dashboard-specialist` is not added because `ux-expert` and `code-reviewer` already judge every touched surface. One doc-gen runs for the slice after every head passes.

Environment: per-worker `DB_PATH` from `tests/conftest.py`; node-executed tests need `node` (CI's `ubuntu-latest` has it); browser modules follow SC-7 (marker `browser`, Playwright imported in a fixture, no skip, Firefox headless, run with `python -m pytest -m browser -n 0 <module>` one invocation at a time); never `-n auto`, never more than 4 workers, never `-o addopts=""`; JS syntax only through `tests/js_syntax/test_js_syntax.py`.

Team size: 22 = 6 test-writer + 6 implementer + 2 qa + 2 code-reviewer + 2 ux-expert + 2 behavioral-evidence-capturer + 1 sqlite-specialist + 1 doc-gen
