**Where the matrix reads from, and how fresh it is.** A persisted result, never a cache and never Composer: the `RETIREMENT_RUN_SUMMARY` row (`advisor_observations`, append-only, written by `_persist_retirement_run_summary`, app.py:1142-1165) of the latest successful retirement run. The nightly tick writes it at 03:45 in the host's zone, which is UTC on the droplet (`schedule.every().day.at("03:45")`, app.py:1440; `tests/fixtures/retirement/PROVENANCE.md` on `ux-overhaul/fixtures`), that is 23:45 ET in summer, and Run now writes it outside market hours (app.py:8394). Its data is as fresh as that run: series through the last close the run kept (AC-9 cut-off), run time stated on the as-of (AC-2). The page already reads the row for the Retirement tab (`_fetch_retirement_last_run`, app.py:4418-4436; `_fetch_retirement_cards_run`, app.py:4505-4536; called at app.py:7014-7023); the matrix reuses those two dicts, so a render adds no query and no network call (S-1.6).

## Execution Model
One Toxic Pair (`test-writer`, `implementer`) per cycle, one cycle in flight at a time (Dispatch Ordering is a chain), each pair in its own worktree under `.claude/worktrees/` with `.env` copied in and `git rev-parse --show-toplevel` and `git rev-parse --abbrev-ref HEAD` checked before any edit (`.claude/CLAUDE.md` §Agent Team Composition; suite Execution Model). Peer sessions follow `~/.claude/ORCHESTRATION.md` §Peer Sessions. No worker commits to `ux-overhaul/fixtures`, runs a launcher, or merges into `ux-overhaul/03`; the PM merges each passed cycle head into `ux-overhaul/03` with a merge commit (SC-9).

- C3 (matrix frame, states, as-of, labels, exclusions, series windows, the Retirement line, the API pairs): reviewed by `qa`, `code-reviewer`, `ux-expert` with `behavioral-evidence-capturer`. Renders UI.

- After every reviewer passes every head, one doc-gen for the plan (the plan's Docs to Update).
