# Feature: Held Basis Convergence (Today-Row If-Held + VW Denominator Parity)
Status: ready
Created: 2026-08-13

## Summary
The dashboard's Today's Change comparison row (and the per-symphony card `_tc`) sources its Held (if-held) value from `bot_state.current_return`, which the engine OVERWRITES for a triggered symphony with the TRUE SHADOW RETURN OVERRIDE's VWAP-based basket reconstruction (`alpha_bot_execution.py:1264-1274`, `:1660`). The raw Composer if-held trajectory (`shadow_history.current_return`) sits unread in the very shadow row the same function already fetches for the Bot column. Live capture 2026-08-13 (one triggered symphony): the rendered Today-row guard delta was +0.0347 pp when the real delta was +0.0177 pp — a ~96% overstatement, 49% of the rendered delta a pure reconstruction artifact. Same defect class as `DE-GUARD-ALPHA-SAVED-001` (fixed in `reporting.py` only; the dashboard TC path was never migrated). Secondarily, `_value_weighted_portfolio` divides Held by `total_weight` but Bot by `dry_run_weight` (`analytics.py:1107` vs `:1109`) — different membership sets when a symphony lacks a shadow row, producing a phantom delta on a genuinely zero-exit day (latent today: 11/11 symphonies covered). This cycle converges the Today-row Held basis on `shadow_history.current_return` (the basis S5 hero chart / S6 Performance tab / S8 $-saved already use) and makes the VW delta membership-consistent. Display/aggregation layer ONLY.

**Evidence base (canonical):** `docs/audit/HELD-VS-BOT-DIVERGENCE-2026-08-13.md` (committed in this branch) — every claim file:line-cited, live numbers from one atomic engine cycle at 2026-08-13 13:30:02 ET.

## Architecture
- **`analytics.get_symphony_today_change` (`analytics.py:513-559`)** — the single seam fixing both S1 (Today row) and S4 (per-symphony card `_tc`). The shadow row fetched at `:555` already contains `current_return`; prefer it for `if_held` when the reconstruction marker is set (see Decisions — marker-gated, Option B).
- **Marker threading — [SUPERSEDED, Revise 1, PR #125 review F4]:** originally, the sym_dicts synthesized from `bot_state` at `app.py:1508-1514` and `app.py:2624-2630` carried `current_return_is_reconstructed` through to the seam per-caller (BL-9 stamped it into `bot_state`; `DE-AUDIT-BL9-001` documented "zero consumers" — this cycle creates the intended consumer). The `/review` skill gate on PR #125 found this per-caller-opt-in design left 4 of 6 real `sym_dict`-building call sites unthreaded (F1: `/api/strip`, F3: dashboard SSR card, F5(c): frozen per-symphony loop — see `DECISIONS.md`'s "Revise 1" section). Fixed by the F4 design pivot: `analytics.get_symphony_today_change` now reads the marker from its EXISTING `bot_state_entry` parameter as PRIMARY (a key-presence check, not truthiness), falling back to `sym_dict` only when `bot_state_entry` lacks the key — every real call site already passes the true `bot_state` sub-dict as `bot_state_entry`, so the 2 sites above had their threading REMOVED as redundant. The ONE site that still needs explicit threading is the frozen Tier-2 aggregate's hand-built 4-key `_snap_bot_state` (`app.py:~2277`), which is not the real `bot_state` entry (F5(b)).
- **`analytics._value_weighted_portfolio` (`analytics.py:1085-1109`)** — pairwise delta accumulation (both columns summed only where both exist) alongside the existing full-membership `if_held` average for the floor path. `get_portfolio_today_change_account_basis` / `get_portfolio_cumulative_return_account_basis` (`analytics.py:1246`, `:1318-1324`) consume `guard_delta_vw`; their contract is unchanged.
- **No schema change, no migration, no new routes, no new JS.** `static/index.js` render contract unchanged (values only).
- **Dependencies:** none new.

## Design-System Mapping
N/A — zero markup/CSS/JS changes. The fix alters values flowing through the existing `today_change.if_held`/`dry_run` JSON fields into the existing DOM (`static/index.js:1001-1038`).

## Edge Cases
- Triggered symphony, shadow row present (the live 2026-08-13 case) → AC-1.
- Triggered symphony, NO same-day shadow row (engine died before first `record_shadow_observation`) → AC-4 fallback.
- Untriggered symphony where `shadow_history.current_return` ≠ `bot_state.current_return` by a fresher live fetch (caller shapes `app.py:1274`/`:2169`) → AC-2: marker gating means these never change.
- Post-EOD pass (`alpha_bot_execution.py:1048-1057` rewrites `current_return` raw, marker `False`) → override stops firing; values converge naturally; no stale override.
- Coverage gap day, zero triggers → AC-5 exact-zero delta (the phantom-delta scenario the operator originally suspected).
- ALL symphonies uncovered → AC-8 honest degradation.
- `_twr_fallback` membership (`analytics.py:932-934`) — untouched, see Scope Boundaries.

## Security Considerations
No new input surface: no new routes, no user-supplied values, read-only SQLite access through existing accessors, no template/JS changes (no XSS delta), auth/CSRF surface untouched. No security tests needed beyond the existing route-auth autouse fixtures.
