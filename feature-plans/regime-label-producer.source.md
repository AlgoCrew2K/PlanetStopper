=== INTAKE ANSWERS (PM, [PM-ASSUMED] under the full-autonomy directive) ===
Building
1. Makes true: on every trading day each live symphony's exit confirmation uses the regime label the design specifies, computed off-hours from that symphony's trailing daily returns on the same basis and window as the autotuner replay, so live and replay apply the same exit rule. Trigger: Part 4.
2. Surface: an off-hours daily scheduler job inside the daemon (app.py run_scheduler, beside the existing 03:00 / 03:30 / 03:45 ET slots); the consumer is the engine's existing per-tick cached read. No page, route or button.
3. Screens and flows: none for an operator; the job runs unattended. Each run writes one log line per symphony (label or the reason there is none).
4. Negatives: a symphony with fewer trailing trading days than regime_classifier.MIN_LABEL_SERIES_LENGTH gets no label (engine default 3); a failed price fetch or any error for one symphony gets no label for that symphony and does not stop the others; a run that does not happen (daemon down, job error) must not leave a stale label in force (default 3 instead); a repeated run on the same day replaces the day's labels idempotently; weekends and NYSE holidays: the label applies to the next trading day; a symphony added after the run has no label until the next run; a symphony removed keeps no effect; the job never runs on the 1-minute path and adds no I/O to the tick beyond the existing cached read; the engine's behaviour with no label is exactly today's.
5. Data and contracts: the existing regime_label_cache table (migration 027: symphony_id primary key, label, as_of_date, updated_at) and database.save_regime_label / get_cached_regime_label; whether the engine's read must pass a staleness rule (an engine-file change) or the producer guarantees freshness is a design question (Open Questions). No new config key unless required.
6. Repos: AlphaBotPM only; lands after the dead-table-partial slice (already on this branch's base).
7. Sensitive: yes (live exit timing; money).
Not building
1. No change to regime_classifier.classify_regime, its thresholds, math_engine.apply_regime_exit_adjustment, the 2/5/3 tick table, EXIT_CONFIRM_TICKS, or the autotuner replay; no dashboard display of the label; no backfill of past days; no Optuna retune; no change to any other exit layer.
2. Must stay: the engine's decisions when no label exists; the 1-minute path's I/O; the replay's no-lookahead rule (replay never reads the live cache).
3. Deferred: showing the regime label on the dashboard; a retune once live and replay agree.
4. Consumed, not changed: regime_classifier.py, math_engine.apply_regime_exit_adjustment, autotuner._replay_resolve_regime_exit_ticks, synthetic_history's replay basis, migration 027's schema (an additive migration only if the design truly needs one).
