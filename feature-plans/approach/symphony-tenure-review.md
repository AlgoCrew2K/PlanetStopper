## Architecture

Every `path:line` below is at AlphaBotPM@ed7f43ce. The design is built against the plan's proposed defaults for Q-1 to Q-21; each choice that changes if a default is overturned is listed under Items Raised to the PM.

### Shape
The review is the existing Retirement Recommender's screen, gates, composite and candidate rule (`advisors/retirement_recommender.py:169-420`), run over a new evidence basis and wrapped with tenure gating, four new evidence items and a verdict. It is built as three layers plus the dashboard:

1. **Pure compute, `advisors/tenure_review.py` (new, C1).** No I/O. Takes fetched inputs as plain dataclasses and returns the per-symphony review entries, the retire-candidate recommendation dicts and the run record. Search: no tenure, trading-day-count or keep/retire review module exists (`grep "def .*trading_day"` outside tests finds only `market_calendar.py:41`, `synthetic_history.py:201`, `sleeves/rules/limits.py:95`, `:195`; `grep tenure` finds nothing in code), so the module is new; it composes existing primitives instead of re-implementing them:
   - NYSE calendar: `market_calendar.is_trading_day` (`market_calendar.py:41-59`) and `market_calendar.session_close` (`market_calendar.py:80-104`, half-day aware) for the as-of day (D-4) and the inclusive trading-day count.
   - Screen, gates, composite and candidate rule, constants unchanged (S-3.10): `correlation_diagnostic.compute_pairwise_correlations` (`advisors/correlation_diagnostic.py:196-247`), `correlation_diagnostic._extract_aligned_pairs` (`:86-138`), `retirement_recommender.evaluate_uncertainty_gate` (`advisors/retirement_recommender.py:299-327`), `_compute_stressed_correlation` (`:366-401`), `evaluate_structural_redundancy_gate` (`:335-363`), `_compute_holdings_overlap` (`:404-420`), `compute_composite_scores` (`:192-236`), `select_retirement_candidate` (`:239-291`) and the constants at `:44`, `:51`, `:68`, `:74`, `:83`, `:94-98`. The private-helper import has precedent (`advisors/retirement_recommender.py:401`, `:508`, both `noqa: SLF001`).

One implementation feeds both legs of every comparison, so no comparison mixes two formulas. ### Storage (no migration)
- One `advisor_observations` row per completed run: `advisor_role="TENURE_REVIEW_RUN"`, `subject_type="tenure_review_run"`, `subject_id=<run_id uuid4 hex>`, `verdict="completed"`, `raw_response=<run record>`, written through `database.insert_advisor_observation` (`database.py:1159-1210`, append-only, forces `is_advisory_only=1`). The run id fills the NOT NULL `subject_id` (`migrations/017_advisor_observations.sql:14-15`), which settles the plan's open storage question for S-9.11. `TENURE_REVIEW_RUN` is not added to `_ADVISOR_ROLES` (`app.py:8393-8401`), the same convention `RETIREMENT_RECOMMENDATION` follows.
- Each retire-candidate also persists as today through `retirement_recommender.persist_recommendations` (`advisors/retirement_recommender.py:562-584`), with its existing fields (S-8.1) plus additive `review_run_id`, `as_of_trading_day`, window keys and `explanation_written_on`.
- Commit point: the recommendation rows are written first and the run row last. The latest completed run is the newest `TENURE_REVIEW_RUN` row (`database.get_advisor_observations_for_role(role, limit=1)`, `database.py:1239-1257`, `ORDER BY id DESC`), so a run that fails between the two writes leaves recommendation rows whose `review_run_id` matches no run row; the `recommendations` list is filtered to the latest run's id and never shows them (S-9.9). This replaces the UTC-date filter (`app.py:4286-4293`) whenever a completed run exists (S-9.6); with no completed run the existing filter stays, which keeps `tests/app/test_retirement_recommendations_route.py:175-230` valid.
- Decisions stay in `retirement_decisions` (`migrations/038_retirement_decisions.sql`), keyed by Composer hash, written only by `_dispatch_retirement_decision` (`app.py:7913-7954`), unchanged (NB-9).
- The highest migration stays 38, so `tests/test_mdd_window_truth_zero_diff_guard.py:157` is unchanged.

### Run record and entry contract (C1 defines it; C3 renders it; the API returns it verbatim)
- Run record: `run_id`, `trigger` (`nightly` or `on_demand`), `started_at`, `completed_at`, `as_of_trading_day`, `threshold_in_effect`, `threshold_note` (`null` or `configured threshold invalid; 126 in use`), `composite_window` (`first`, `last`, `days`), `entries`.
- Entry: `symphony_id`, `display_name`, `invested_since`, `tenure_trading_days` (int or `null`, never 0 for unknown), `eligibility_text`, `eligible`, `days_remaining`, `basis` (`kind` composer, shadow or none; `label`; `fallback_reason`; `series_begins`; `tenure_begins`), `verdict` (`keep`, `watch`, `retire_candidate` or `null`), `verdict_text`, `verdict_reasons`, `missing_items`, and `evidence` with six items, `performance`, `composite`, `redundancy`, `backtest`, `marginal`, `long_vix`. Every item carries `status`, `reason` (when not available), `label`, `unit` per figure, `window` (`first`, `last`, `days`), `subject` and `source`. C4 adds `explanation` and `explanation_written_on` to retire-candidate entries; C3 stamps `approval_status` at read time.
- Every float is passed through a finite check at record build, because `insert_advisor_observation` serializes with `json.dumps` defaults (`database.py:1187`), which would store `NaN` tokens.

### Concurrency and scheduling
- `tenure_review.REVIEW_RUN_STATE`: a `threading.Lock` taken with `acquire(blocking=False)` (atomic check-and-take, S-9.5), plus `running_since`, `trigger` and `last_failed_attempt` (time and reason). Both the tick runner and the route call `try_start`; only the job releases it (`finish_success`, `finish_failure`), and a failed thread start or executor submit releases it at once. Both callers live in the daemon process (`app.py:8550` starts `run_scheduler` in a thread of the Flask process), so one in-process lock covers them; no `bot_state` writer is added.
- On-demand work runs on a new dedicated `_TENURE_REVIEW_EXECUTOR = ThreadPoolExecutor(max_workers=1)` with `atexit` shutdown, the pattern at `app.py:426-435`; the nightly tick keeps the scheduler's worker-plus-daemon-thread wrapper (`app.py:1080-1238`) at the existing 03:45 slot. The as-of day is computed from US Eastern time (`app.py:38` `_ET`) at run start, independent of the host-local slot time.
- Composer pacing: each read is followed by `COMPOSER_READ_SPACING_SECONDS = 2.5`, derived from the API reference's 25-per-minute standard limit (the stricter documented figure, `docs/audit/COMPOSER-HISTORICAL-SERIES-2026-09-03.md` Q2); reads are not retried, so a 429 becomes an "unavailable: Composer rate limit" item, never a retry storm; `run_backtest` is called with `max_retries=1`. Budget per run: statistics 1 per account (up to 3), series 1 per live symphony, definition and backtest 1 each per eligible symphony, holdings 1 per 30-day span per account (`HOLDINGS_REQUEST_SPAN_DAYS = 30`, the endpoint's only documented window, same doc S-3); about 11 + 11 + 11 + 3 + up to 90 requests, roughly 6 to 10 minutes plus backtest time, all off the request thread.

### Evidence rules decided here (the HOW of AC-2 to AC-8)
- Values to returns: a symphony's realized points are its `deposit_adjusted_series` values keyed by the UTC calendar date of `epoch_ms`, kept only inside `[invested_since, as_of]`, with absent, null, non-finite or non-positive values dropped (S-2.10). Day `d`'s return is `(v_d / v_prev - 1) * 100` against the previous kept point, so a dropped day neither counts as a point nor erases the move across it; the window's day count is the number of kept points (S-2.1).
- Basis: Composer series usable when the read succeeded and at least 2 points survive; else shadow history with the AC-2 reason; else `none` and every item reads "unavailable: no history" (S-2.9). The fallback label names shadow history without claiming it was traded (plan Known-Unconfirmed on `advisors/retirement_recommender.py:122`).
- Pairs are screened only within one basis; a cross-basis pair is "unavailable: bases differ" (S-2.11). Gate states map from the existing primitives: correlation `None` is "undefined" and not a screen hit (S-3.7); `n_obs < MIN_OBS_FLOOR` is "insufficient data: needs 30 aligned days"; a Fisher-undefined result (`advisors/retirement_recommender.py:317-318`) is "undefined"; the structural gate is "not evaluated: uncertainty gate not met" unless the uncertainty gate passed (S-3.12); otherwise `ceil(STRESS_WINDOW_FRACTION * n) < STRESS_MIN_OBS` is "insufficient data: needs N aligned days", N derived from the two constants (181 today, S-3.2, S-3.3), and a `None` stressed correlation past that check is "undefined: stressed-window correlation cannot be computed" (S-3.11).
- Composite: the common window is the latest `threshold` NYSE trading days ending at the as-of day; the population is eligible, Composer-basis symphonies with a kept point on every one of those days, scored by `compute_composite_scores` over the returns inside the window; everyone else gets "not yet eligible", "not comparable: basis differs" or "insufficient coverage in the common window (N of M days)" (S-4.6 to S-4.10). `select_retirement_candidate` already returns `None` when a pair member is missing from the scores (`advisors/retirement_recommender.py:261-264`), which is exactly the fail-closed rule of S-3.9, S-4.7 and S-8.20.
- Retire-candidate and its pair: every same-basis pair passing both gates yields a candidate through `select_retirement_candidate`; per candidate the strongest-correlation passing pair is kept, the dedup `advisors/retirement_recommender.py:546-548` applies (S-3.13). A non-candidate shows its highest-correlation screen hit, or "no redundant sibling" (S-3.6).
- Backtest item: requested with the realized window's first and last dates; a returned `first_day` or `last_market_day` that differs is "unavailable: backtest dates do not match the realized window" (S-5.12); fewer than 2 values in the window is "unavailable: backtest series too short" (S-5.8). Gaps are realized minus backtest in percentage points.
- Marginal item (Q-22, operator-approved): the comparison portfolio is the eligible symphonies only (tenure at least the threshold). Its value is the sum of their same-basis realized values on the days every eligible same-basis symphony has a kept point (S-6.3); "without" drops the evaluated symphony's values with no reallocation. Every not-yet-eligible live symphony is left out of both legs and listed in the item's `excluded` field as "excluded: not yet eligible" with its display name (S-6.6), so the window is set by the youngest eligible symphony, never by a young ineligible one; with no other eligible symphony the item reads "not applicable: no other eligible symphonies" (S-6.2). Worked Example: "Slate Valley Hedge" (85 days) is excluded, and the comparison for "Copper Ridge Rotation" and "Harbor Lights Momentum" runs from 2025-03-03 (the later of their two invested-since dates) through 2026-12-31. On the shadow basis there are no position values (`migrations/008_shadow_history.sql:16-17` stores percent returns only), so the item reads "unavailable: no position values on the shadow-history basis" (operator-accepted, item 3).
- Long-VIX item: counts use the days on which holdings were returned for the symphony; peak shares are the maximum daily ratio of long-VIX holding value to total holding value across live symphonies, with and without the symphony. Tickers are normalized from either `VIXY` or `EQUITIES::VIXY//USD` form (`tests/fixtures/composer/symphony_stats_meta.json` carries both). The verdict never reads this item (S-7.7).
- Verdict: retire-candidate per the rule above; otherwise watch with "trails its own backtest" when `backtest_total - realized_total > BACKTEST_TRAIL_WATCH_PP` (10.0, strict, S-8.5), and with "drags portfolio return and drawdown" when `without_total > with_total` and `without_mdd >= with_mdd` (S-8.6); otherwise keep; "no verdict: no evidence available" when redundancy, backtest and marginal are all unavailable (S-8.8). `missing_items` lists every unavailable item.
