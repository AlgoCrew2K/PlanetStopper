# Plan — Engine Audit: Fixture-First Integration + Provenance Coverage Audit

| Field | Value |
|---|---|
| Feature | End-of-Phase-1 audit of every golden fixture introduced by the decision-science work (and every existing fixture the new code touches). Confirms each fixture is (a) captured from a producer (`/api-fixture`), (b) schema-derived with a runtime validator, or (c) producer-owner-signed-off — **never** parser+fixture co-design (rubric D-2 ★, global rule `feedback_verify_backend_contract_before_fixtures`). The audit also confirms test coverage gaps that the per-plan §8 tests do not close. |
| Phase | Engine audit (post-Phase-1) |
| Owner agent-type | `quant-code-reviewer` (audit lead) + `quant-test-writer` (gap closure plans) |
| Source-of-truth refs | `docs/handoff/council-attack-rubric.md` D-1 ★, D-2 ★, D-3, D-4; project memory `feedback_verify_backend_contract_before_fixtures`; standing reviewer gate 3 (fixture provenance non-circular); existing fixtures under `tests/fixtures/` |
| Why | Parser+fixture co-design is the single largest fixture-related fail in the global feedback set. The decision-science work introduces several new fixtures (the kNN-pool fixture for M2, the captured `U`-series for CRRA tests, the S-1 reference for M3 parity, the Phase-2 simulator path-bank fixture). Each must be provenance-audited before the cycle closes; otherwise the Gate-1 RED test is hollow. |
| Deliverables | (1) `docs/handoff/engine-audit/fixture-provenance-findings.md` — every fixture file under `tests/fixtures/` enumerated; per-row, its provenance (CAPTURED / SCHEMA-DERIVED / PRODUCER-SIGNED / CIRCULAR / UNCLASSIFIED), the producing tool or owner, the test(s) that consume it, and any provenance defect. (2) Coverage gap analysis: for each Phase-1 RED test (the §8 tests 1-4, the M2 four-part display test, the W-H4 floor test, the Gate-1 parity test, the live-vs-replay tests), record the fixtures consumed and confirm each is non-circular. (3) `tests/integration/test_every_fixture_has_provenance_annotation.py` — every file under `tests/fixtures/` has a sibling `.provenance.md` with the four-row provenance template (origin, tool used, capture date, signer/owner). A fixture without provenance fails. (4) `tests/integration/test_no_inline_fixtures_alongside_parsers.py` — grep test: no `tests/<area>/test_*.py` file contains an inline dict/list-of-dicts fixture that is *both* the parser's expected output and the parser's input (the circular pattern). Inline fixtures that are clearly schema-derived (e.g. a 5-element `numpy.linspace` input) are allowed if annotated. (5) Findings document feeds back into per-plan follow-up tasks for any circular-fixture finding. |
| Dependencies | All Phase-1 fixtures landed; the §8 RED tests committed. |
| Golden-fixture tests required | Tests 3, 4 are structural tests. |
| Definition of Done | (a) Provenance findings document is committed; every fixture file has a row. (b) Tests 3, 4 pass GREEN. (c) Zero circular fixtures remain — any flagged circular fixture has a follow-up TDD plan to recapture via `/api-fixture` or to schema-derive with a runtime validator. (d) The audit confirms the §8 tests 1-5 are non-circular per the per-plan claims. |
| Risk callouts | **R1 — Provenance annotation drifts** (a recaptured fixture's annotation isn't updated): mitigated by sibling-file convention — the test fails if the annotation file is older than the fixture file by > 1 day. **R2 — A "convenience" inline fixture lands in a new test**: test 4 catches at CI. **R3 — Annotation theater** (provenance is annotated honestly, but the fixture was secretly co-designed with the parser): mitigated by the human-review step in the audit — the audit lead reads each annotation against the fixture's hash history. |
| Out of scope | Existing fixtures that predate the decision-science cycle (separate retroactive audit if needed); test execution time; fixture sizes (separate concern). |
