# Plan — Engine Audit: Composer / Alpaca Client Safety Audit

| Field | Value |
|---|---|
| Feature | Audit of every Composer.trade and Alpaca client call site for: (a) retry/backoff behavior under transient failure; (b) timeout configuration (no unbounded blocking — protects architecture constraint 1); (c) response-body redaction in logs (overlay gate 7); (d) credential / account-ID / webhook-URL hygiene (overlay gate 5); (e) fixture-testability (overlay gate, D-4); (f) live-mode flag check before any order-mutating call (overlay gate 2, F-1). |
| Phase | Engine audit (post-Phase-1; re-runs at Phase-2 entry if a new client added) |
| Owner agent-type | `composer-alpaca-integration` (audit lead) + `quant-code-reviewer` (overlay gates) + `composer-api-researcher` (drift check) |
| Source-of-truth refs | `docs/handoff/council-attack-rubric.md` D-4 (fixture-testable client), F-1 ★ (live-mode flag), standing reviewer gates 2, 5, 7; project CLAUDE.md gotcha "Composer.trade API is poorly documented; invoke `composer-api-researcher` before any client change"; existing client code (TBD per repo enumeration) |
| Why | Composer drifts. Alpaca returns sensitive payloads. Phase-1 introduces no new external calls (`run_monte_carlo` is frozen, M2 uses the existing kNN pool), so the audit's primary job is to confirm the **incumbent** clients still meet the overlay gates after the v1 design changes — drift may have happened independently of the decision-science work. Phase 2 may introduce new calls (the longer-window second residue uses the **existing** 3-year Alpaca pool, so no new call there); if a new client lands the audit reruns. |
| Deliverables | (1) `docs/handoff/engine-audit/composer-alpaca-client-findings.md` — every external call site enumerated; each gets a row with timeout, retry policy, redaction status, fixture availability, and live-mode flag check. (2) For each Composer endpoint: confirm against the latest `composer-api-researcher` snapshot — drift is recorded as a finding. (3) For each Alpaca endpoint: confirm against the `alpaca-api-researcher` snapshot. (4) `tests/integration/test_composer_alpaca_no_unbounded_timeout.py` — every client call is wrapped with an explicit `timeout=` keyword; an unbounded call (no timeout) fails. (5) `tests/integration/test_composer_alpaca_credentials_not_in_source.py` — grep test: no hardcoded API keys, webhook URLs, account IDs in any source file (overlay gate 5). (6) `tests/integration/test_composer_alpaca_fixture_testable.py` — every client wrapper has a corresponding fixture file under `tests/fixtures/composer/` or `tests/fixtures/alpaca/`; fixtures are schema-derived or captured via `/api-fixture` (overlay gate 3, non-circular fixture provenance). (7) `tests/integration/test_composer_alpaca_log_redaction.py` — cross-references the logging-redaction plan in Phase 1; integration-level check that response-body redaction holds end-to-end. |
| Dependencies | The logging-redaction plan; `composer-api-researcher` and `alpaca-api-researcher` snapshots being current at audit time. |
| Golden-fixture tests required | Tests 4, 5, 6, 7 are golden-fixture / grep tests. Fixture provenance is enforced (`/api-fixture` captured-from-producer; never parser+fixture co-design). |
| Definition of Done | (a) Findings document is committed with every Composer/Alpaca call site represented. (b) Four tests pass GREEN. (c) Any drift finding has a follow-up TDD plan to update the client. (d) Live-mode flag check is structurally enforced — the live-vs-replay safety-boundary plan's grep test (test 2 there) is the structural backstop. |
| Risk callouts | **R1 — Composer drift mid-cycle**: the gotcha says "invoke `composer-api-researcher` before any client change"; this audit re-invokes it. **R2 — Alpaca payload widens and a new field leaks into logs**: test 7 catches at integration level. **R3 — A "convenience" disables a timeout for a long-running fetch**: test 4 catches; the long-running fetch belongs out-of-band on the autotuner / synthetic-history side, not on the per-cycle path (constraint 1). |
| Out of scope | Composer API design (third-party); Alpaca API design (third-party); rate-limiting policy (operator concern); Discord webhooks (reporting.py audit if needed — separate plan). |
