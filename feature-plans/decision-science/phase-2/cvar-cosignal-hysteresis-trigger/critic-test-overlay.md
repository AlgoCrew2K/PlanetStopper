# Plan (critic overlay) — Phase-2 Test Design: CVaR Co-Signal Hysteresis State Machine

> Companion test plan to the risk-architect-owned `cvar-cosignal-hysteresis-trigger/plan.md`
> in this folder. Critic-domain overlay: enforces rubric C-1 (hysteresis is binding,
> a single-tick hard trigger is dead) and the co-signal contract (never solely fires
> an exit; always confirms one another layer already supports).

| Field | Value |
|---|---|
| Feature | Phase-2 CVaR co-signal trigger: a two-level hysteresis band + multi-tick confirmation state machine, structurally a sibling of `compute_exit_confirmation` and `compute_tp_confirmation`. The trigger is a **co-signal** — it can `narrow`, `veto`, or `confirm` an exit another layer already supports, but it **never solely fires an exit**. Abstains fail-safe when the ensemble is unavailable (`CVaRAssessment.cvar_pct is None` → `breach is False` → co-signal contributes False to the resolver). |
| Phase | 2 (activates only after precondition gate clears) |
| Owner agent-type | `quant-test-writer` + `quant-code-reviewer` (rubric C-1, F-4) + `risk-engine-specialist` |
| Source-of-truth refs | `docs/handoff/council-attack-rubric.md` C-1 ★ (hysteresis required; a hard single-tick CVaR trigger fails); `docs/handoff/decision-science-council-synthesis.md` §5.2 (CVaR as co-signal — narrow/veto/confirm; never solely fires), §5.3 (composition into existing `resolve_trigger_priority`); existing pattern at `math_engine.py:669-692` (`resolve_trigger_priority` + `_TRIGGER_PRIORITY_ORDER`); existing confirmation pattern (the `EXIT_CONFIRM_TICKS = 3` and `VWAP_BREAK_CONFIRM_TICKS = 3` constants — match the bar) |
| Why | A hard, single-evaluation CVaR trigger converts tail-estimation noise into spurious exits (rubric C-1, established fact per the council brief). Hysteresis and multi-tick confirmation are non-negotiable. The co-signal contract is the structural difference between Phase 2's CVaR layer and a "live CVaR trigger" — the latter is REJECTED, the former survives only because it never acts alone. |
| Deliverables | (1) `tests/math_engine/test_cvar_cosignal_hysteresis_arm_disarm.py` — fixture: a sequence of `cvar_pct` values that cross the arm threshold once, then drift; assert the state machine arms after `CVAR_COSIGNAL_ARM_TICKS` consecutive breaches, disarms after `CVAR_COSIGNAL_DISARM_TICKS` consecutive recoveries, and the two thresholds form a band (arm > disarm) — never a single threshold. (2) `tests/math_engine/test_cvar_cosignal_never_solely_fires.py` — fuzz across 100 random scenarios: for every cycle where the resolver's output is `cvar_cosignal=True` AND **no other layer fired**, the final exit decision is **no exit**. The co-signal alone never produces an exit reason. (3) `tests/math_engine/test_cvar_cosignal_confirms_existing_exit.py` — fixture: trailing-stop or VWAP-breakdown layer already supports an exit; co-signal fires; assert the resolver records the co-signal as a confirmation (e.g. via a `confirmed_by` field or the co-fired list at `math_engine.py:679-692`); the exit reason is the existing layer's, not "CVaR." (4) `tests/math_engine/test_cvar_cosignal_vetoes_existing_exit.py` — only if the design includes a veto path (per §5.2 "narrow, veto, or confirm"): fixture: trailing-stop wants to exit; co-signal indicates "wait — tail risk is low and recovery is likely"; assert the resolver respects the veto branch — but **only under explicit, documented design conditions**, never silently. If the design lands without a veto path, this test is `skip`-marked with a docstring citing §5.2. (5) `tests/math_engine/test_cvar_cosignal_none_abstains_fail_safe.py` — fixture: `CVaRAssessment.cvar_pct is None` for many cycles; assert the protective stop continues to fire on its own (cross-references the abstain-fail-safe plan). (6) `tests/math_engine/test_cvar_cosignal_uses_named_constants.py` — `CVAR_COSIGNAL_ARM_TICKS`, `CVAR_COSIGNAL_DISARM_TICKS`, arm/disarm thresholds are all named module constants with source comments (project rule: no magic numbers in `math_engine.py`). (7) `tests/math_engine/test_resolve_trigger_priority_5th_signal_position.py` — the resolver's `_TRIGGER_PRIORITY_ORDER` is extended; the position of `CVaR Co-Signal` in the priority order is the documented design choice (it is **after** the hard layers — VWAP Breakdown, Take-Profit, VWAP Bleed Cut, Trailing Stop — because a co-signal **never solely fires**, so it never beats a primary fire). |
| Dependencies | The simulator plan (`phase-2/simulate-forward-paths/`); the priority-resolver-cvar-cosignal plan (`phase-2/priority-resolver-cvar-cosignal/`); the MC-blast-radius plan (defines `CVaRAssessment`); the abstain-fail-safe plan. |
| Golden-fixture tests required | All seven tests are golden-fixture / property tests. Fuzz tests are seeded for determinism. |
| Definition of Done | (a) Seven tests pass GREEN once the trigger and resolver extension exist; test 1 fails RED before the state machine lands. (b) No magic numbers in the trigger code — test 6 enforces. (c) The "never solely fires" contract is structurally enforced by the resolver design (priority order + co-fire semantics) AND tested by test 2. (d) The veto branch (test 4) ships only with explicit documented design conditions — silent veto is rejected. |
| Risk callouts | **R1 — A "small" optimization replaces the band with a single threshold**: test 1 fails loud (asserts arm > disarm). **R2 — A future PR makes the co-signal a primary firer**: test 2's fuzz catches; test 7's priority-order position pins it as last among the firing layers. **R3 — Magic numbers reappear**: project rule + test 6. **R4 — Veto path lands silently**: design doc must commit to enabling it; until then test 4 is skip-marked. |
| Out of scope | The simulator's correctness (separate plan); the Acerbi-Székely Gate-2 test (separate plan); tier1_seed (separate plan); the Phase-2 Gate-1 5-anchor parity (cross-referenced in tier1_seed plan). |
