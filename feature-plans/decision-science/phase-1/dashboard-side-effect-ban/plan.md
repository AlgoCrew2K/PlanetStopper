# Plan — Dashboard Side-Effect Ban (overlay gate 8) for M2

| Field | Value |
|---|---|
| Feature | Structural enforcement of architecture constraint 2 — the Flask dashboard is a read-only operator surface. Routes in `app.py` MUST NOT call engine functions that mutate state. M2's `cvar_diagnostics` data is rendered read-only; the dashboard never triggers an M2 recomputation, never writes a row, never reaches a broker call. The Advisor's dashboard footprint (Phase 1: Specification Critic + Overfitting Conscience verdict rendering only) inherits the same ban (rubric I-3). |
| Phase | 1 |
| Owner agent-type | `flask-dashboard-specialist` (the routes) + `quant-test-writer` (structural tests) + `quant-code-reviewer` (overlay gate 8) |
| Source-of-truth refs | project CLAUDE.md architecture constraint 2 (dashboard is a read-only operator surface; never an action surface for live trades); `docs/handoff/council-attack-rubric.md` I-3 (Advisor cannot trigger live action; dashboard cannot gain action surface), standing reviewer gate 8; project CLAUDE.md "Templates open SQLite read-only; UI never reruns the engine" |
| Why | Dashboard side-effect mistakes are a recurring AlphaBot failure mode and a standing reviewer-overlay gate. The Advisor's read-only contract from rubric I-3 chains through the dashboard surface — if the dashboard renders Advisor output, that surface must not gain any state mutation. This plan converts the gate from "reviewer attention" into "structural CI assertion." |
| Deliverables | (1) `tests/app/test_dashboard_routes_read_only_db.py` — for every Flask route, the DB connection used is opened read-only (`sqlite3.connect("file:…?mode=ro", uri=True)` or the project's existing read-only helper); a route that opens a read-write connection fails the test. (2) `tests/app/test_dashboard_routes_never_call_engine_mutators.py` — static import-graph test: every symbol called by an `app.py` route is checked against a denylist (`record_*`, `save_state`, `wipe_*`, `init_db`, `run_migrations`, any function in `alpha_bot_execution.py`, any function in `math_engine.py` that has side effects (M2's `record_cvar_diagnostic` etc.), the H4 helper `write_telemetry_row`). A new mutator added to the engine but not denylisted is flagged by an inverted denylist check: every engine function is annotated `@pure` (no I/O) or `@stateful`; routes may only call `@pure`. (3) `tests/app/test_dashboard_no_order_path.py` — same grep as the live-vs-replay plan but scoped to `app.py`: no `submit_order` / `place_order` / `cancel_order` / `liquidate` symbol is reachable from any route. (4) `tests/app/test_dashboard_advisor_render_is_read_only.py` — the route that renders Advisor output reads exclusively from `advisor_observations` (append-only table); never calls an Advisor-write path; the `advisor_ro_query` accessor (rubric M-1) is the only DB call. (5) Reviewer prompt addition to `.claude/agents/quant-code-reviewer.md` — already encoded as standing gate 8; this plan adds the test references so reviewer cites the failing test, not the rule. |
| Dependencies | The M2 plan; the Advisor M-1 wall plan (`advisor_ro_query` exists); the H4 helper plan (the only write path; denylisted from routes). |
| Golden-fixture tests required | Tests 1, 2, 3, 4 are structural — they fixture the import graph and the DB connection mode, not data. |
| Definition of Done | (a) Four tests pass GREEN; any new route that mutates state fails CI loud. (b) The `@pure` / `@stateful` annotation convention is documented (proposed; teammate-owned if persistence-architect prefers a different mechanism — the structural form is what matters, not the syntax). (c) The reviewer gate 8 is now backed by an automated CI signal; a reviewer's verdict cites the failing test ID, not the rule. |
| Risk callouts | **R1 — Read-write connection is opened for a "convenience" SQL like recording last-viewed timestamp**: forbidden; if such state is genuinely needed it lives in a separate non-engine table and is written by a non-route path (or, preferably, in browser-side state). **R2 — The `@pure` annotation is misapplied** (a function with hidden I/O is marked pure): mitigated by a separate property test that calls every `@pure`-annotated function with a sandboxed FS / mocked connection and asserts zero writes. **R3 — Advisor footprint widens to a "rerun analysis" button**: forbidden; the button is a state mutation. |
| Out of scope | Browser-side state (cookies, localStorage); session management for the dashboard (the dashboard is single-operator); HTTPS / authentication (separate concern); dashboard styling / Material Design (separate cycle); the LLM-authored Advisor roles' Phase-2 rollout (the wall ban applies regardless). |
