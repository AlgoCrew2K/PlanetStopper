# Plan — H4 Telemetry Helper (live | replay mode contract; covers H-3 wording and M2 routing)

| Field | Value |
|---|---|
| Feature | A single database write helper used for **all** Phase-1 telemetry writes (M2's `cvar_diagnostics` is the only Phase-1 consumer; Phase 2 extends it to `shadow_decisions`). Contract: takes an explicit `mode: Literal["live", "replay"]` keyword argument with no default; in `live` mode swallows `sqlite3.Error` and logs a one-line warning (matching `record_shadow_observation` at `database.py:1147-1194`); in `replay` mode raises any DB error; the helper opens its own short-lived connection off the live `save_state` transaction; bench-asserts a per-cycle one-row INSERT against the 1-minute cadence budget. |
| Phase | 1 (binding — the moment M2 ships) |
| Owner agent-type | `sqlite-specialist` (the helper) + `quant-test-writer` (mode and benchmark tests) + `quant-code-reviewer` (overlay gates 1, 4, 6, 7) |
| Source-of-truth refs | `docs/handoff/decision-science-v3-and-divergence-evaluation.md` §A.3 (H-3: per-cycle write is **non-zero non-blocking I/O cost**, not "zero"); `docs/handoff/decision-science-council-synthesis.md` §3.7 (H4 hazard verbatim — live swallows, replay raises; Gate-1 parity excludes telemetry incidentals `id`, `ts_utc`); `docs/handoff/council-converged-migration-plan.md` §6 H4; project CLAUDE.md architecture constraint 1 (no blocking I/O on execution path); existing precedent `database.py:1147-1194` (`record_shadow_observation`), `:751-781` (`run_migrations`) |
| Why | The "zero impact" framing of M2 in v3 is imprecise — M2 is **zero decision impact**, **non-zero non-blocking I/O**. Routing all telemetry through one helper makes (a) the live-swallow / replay-raise asymmetry inspectable in one place, (b) the per-cycle latency budget testable against one bench, (c) Gate-1 column exclusion (id, ts_utc, built_at_utc) enforced at the assertion site, and (d) future Phase-2 telemetry (`shadow_decisions`) reuse the same boundary contract instead of introducing a parallel "shadow-helper." Re-using `record_shadow_observation`'s exact swallow pattern keeps the new code adoption-of-existing — global feedback `feedback_adopt_existing_contracts_never_invent`. |
| Deliverables | (1) `database.py:write_telemetry_row(table_name, row_dict, *, mode: Literal["live","replay"])` — required-kwarg `mode` (no default); opens a short-lived `sqlite3.connect(STATE_DB, isolation_level=None)` connection (or matches the existing pattern at `:1147-1194`); writes one row; commits and closes. Live: `try / except sqlite3.Error as e: log.warning(…)`. Replay: no try/except — the error propagates. (2) `tests/database/test_telemetry_helper_live_swallows.py` — inject a write failure (table-doesn't-exist, locked, OperationalError); assert `live` mode returns None and logs once; assert `replay` mode raises. (3) `tests/database/test_telemetry_helper_no_default_mode.py` — calling the helper without `mode=` raises `TypeError` at the Python call site. (4) `tests/database/test_telemetry_helper_per_cycle_latency.py` — benchmark: 100 sequential `write_telemetry_row(..., mode="live")` calls on a realistic `cvar_diagnostics` row; assert the per-call wall-clock median is well within the 1-minute cadence budget (target: median < 50 ms on the CI runner; if CI is too noisy, assert the 99th percentile against a 200 ms budget). Pattern matches the existing `record_shadow_observation` precedent — this bench is the H-3 fast-follow verification. (5) `tests/database/test_telemetry_helper_no_log_response_body.py` — the log line on a failure path does NOT echo the row payload (overlay gate 7 — no Composer/Alpaca response-body echoes; here a row may contain financial values, so the log shows only `table_name`, the error type, and the cycle_id). (6) M2's writer (`record_cvar_diagnostic(...)` in `database.py`) is implemented as a thin wrapper over `write_telemetry_row` — test 4 in the live-vs-replay plan grep-asserts it. |
| Dependencies | Migration `023_cvar_diagnostics.sql` (persistence-architect-owned); the live-vs-replay safety-boundary plan (uses this helper). |
| Golden-fixture tests required | Tests 1, 2, 3, 4 are deterministic-fixture tests. Test 4 (benchmark) is non-fixture — it asserts a real wall-clock budget. |
| Definition of Done | (a) Helper is the only path that writes to `cvar_diagnostics`; grep-asserted in the live-vs-replay plan. (b) `mode` is a required kwarg, never a default. (c) Live-mode swallow and replay-mode raise both pass tests. (d) The per-cycle latency budget passes on CI. (e) The log-redaction test passes — no row-payload values leak into logs. (f) H-3's wording correction lands in v3 (out of scope for this plan but flagged): "near-zero benchmarked," not "zero." |
| Risk callouts | **R1 — A future caller passes `mode="live"` from a replay context (a fixture cycle test that should fail loud silently swallows)**: mitigated by the replay-mode-raise test AND by the autotuner replay harness asserting `mode="replay"` at its single call site (the harness's responsibility, encoded in the autotuner-replay plan). **R2 — Helper widens to take a `**kwargs` row**: the contract is one `row_dict` per table; widening the signature opens a Gate-1 column-exclusion drift surface — mitigated by tests 1-3 over an explicit shape. **R3 — Benchmark is flaky on shared CI runners**: mitigate with the 99th-percentile fallback; if still flaky, mark the bench `@pytest.mark.benchmark` and run in a dedicated stage. |
| Out of scope | Phase-2 `shadow_decisions` writes (separate plan extends this helper); the structural-wall accessor `advisor_ro_query` (separate plan, READ side); cross-DB writes (the two-DB rule forbids them; this helper writes only to the state DB); WAL-mode tuning (handled by `database.py` initialization). |
