# Plan — Rubric M-1 — Structural Advisor Frozen-Eval Wall (COALESCE accessor + breach tripwire)

| Field | Value |
|---|---|
| Feature | The AI Advisor's data-access layer is structurally incapable of reading frozen-eval-fold rows during the selection window. Enforced at **one** single read helper (`advisor_ro_query`) that filters `WHERE COALESCE(fold_role,'') != 'frozen_eval'`; a wall-breach tripwire records any DoF-ledger row that touches frozen-eval data after a `spec_bundle`'s `frozen_at` and exposes it as a queryable invariant. |
| Phase | 1 (mandatory floor — the moment `gamma` is frozen, the structural proof must already exist; a wall retrofitted in Phase 2 cannot certify a Phase-1 freeze) |
| Owner agent-type | `sqlite-specialist` (the accessor) + `quant-test-writer` (the wall-breach tests) + `quant-code-reviewer` (gate) |
| Source-of-truth refs | `docs/handoff/decision-science-council-synthesis.md` §3.7 (021 fold_role + wall + COALESCE H3), §3.6 (Phase-1 Advisor roles), Migration table; `docs/handoff/decision-science-v3-and-divergence-evaluation.md` §A.8 A1 (021 canonical filename `021_fold_role.sql`); `docs/handoff/council-attack-rubric.md` I-1, I-2 (★ — Advisor walled off), M-1 ★ (structural, not convention); `docs/handoff/council-converged-migration-plan.md` §3.1 row 021 + §6 H3 (SQL-NULL trap); `database.py:751-781` (`run_migrations` + duplicate-column swallow) |
| Why | Convention-only walls fail M-1. If any caller can issue raw SQL without going through the accessor, the wall is decorative. A bare `WHERE fold_role != 'frozen_eval'` is also wrong: SQL three-valued logic evaluates `NULL != 'frozen_eval'` to NULL/falsy, **silently** hiding legitimate train/validation rows from the Advisor (H3 trap from the converged migration plan). The breach tripwire makes Advisor over-reach **queryable** — a one-line CI assert proves the wall held over the cycle. |
| Deliverables | (1) Migration `021_fold_role.sql` (additive `ALTER`) per converged-plan canonical filename; dual-written into `database.py:init_db()` to satisfy H1. (2) A new `database.py:advisor_ro_query(sql_text, params)` helper — the ONE accessor path the Advisor uses. It refuses any SQL string that contains the bare token `fold_role` (forcing all consumers to bind through the helper's column filter), wraps the query in `SELECT … FROM (<inner>) WHERE COALESCE(fold_role,'') != 'frozen_eval'`, and logs any caller-supplied raw-SQL bypass attempt to the wall-breach tripwire row. (3) A tripwire view `advisor_wall_breaches` (or query helper): `SELECT * FROM researcher_dof_ledger r JOIN spec_bundles b ON r.spec_bundle_id=b.id WHERE r.touched_frozen_eval=1 AND r.created_at > b.frozen_at`. Any non-empty result is a hard CI failure. (4) Test `tests/database/test_advisor_wall_structural.py` — asserts the accessor's filter is applied; asserts the bare-`!=` path is NOT used (string-grep `database.py` for `!= 'frozen_eval'` outside the COALESCE wrap); asserts the helper raises on a raw-SQL bypass. (5) Test `tests/database/test_advisor_wall_breach_tripwire.py` — seeds a DoF-ledger row with `touched_frozen_eval=1` AND `created_at > spec_bundles.frozen_at`; asserts the tripwire returns it; asserts an honest workflow (touch before freeze) does NOT trigger. (6) Test `tests/database/test_advisor_wall_null_safety.py` — seeds rows with `fold_role IS NULL` (the realistic legacy/pre-021 case); asserts the COALESCE form returns them and the bare-`!=` form (in a negative control) silently drops them. |
| Dependencies | Migration `021` lands (persistence-architect-owned migration plan); `researcher_dof_ledger` (`020`) and `spec_bundles` (`015`) tables exist. H1 dual-write to `init_db()`'s `CREATE TABLE` for any `ALTER`-touched table is in scope per the council-converged plan §6 H1. |
| Golden-fixture tests required | Three tests above are the golden harness. Schema-derived fixtures (DDL runs through `run_migrations()` per converged-plan §7) — not hand-authored against a parser. |
| Definition of Done | (a) `advisor_ro_query` is the only Advisor data-access surface; a string-grep across the codebase shows zero direct Advisor SQL outside the helper. (b) Tripwire query returns empty on the fresh DB; non-empty under a seeded breach. (c) Three tests pass GREEN. (d) `021` migration is additive, NULLable + DEFAULT NULL, dual-written to `init_db()` per H1, idempotent (running migrations twice is a no-op via the duplicate-column swallow at `database.py:780-781`). (e) Wall holds under both the COALESCE filter AND the bypass-detection check — both layers must pass; either alone is insufficient. |
| Risk callouts | **R1 — A future commit reintroduces a bare `!= 'frozen_eval'` filter in a hot path**: mitigated by the string-grep assertion in test 1 (added to CI as the wall's structural invariant). **R2 — The helper is bypassed for a "performance" reason**: mitigated by the raw-SQL-detection assertion; the bypass logs a tripwire row so even a successful bypass is queryable. **R3 — `init_db()` `CREATE TABLE` and `021` ALTER drift** (the H1 hazard): mitigated by dual-write requirement in this plan AND a test that opens a fresh DB and asserts the column exists from `init_db()` alone (no migration applied). **R4 — `fold_role` semantics drift**: this plan does NOT define the role enum's contents — that is the autotuner's domain. The wall only filters the literal string `'frozen_eval'`; if the autotuner ever renames the role, that PR must update this helper and is in scope for `quant-code-reviewer` overlay gate 8. |
| Out of scope | The Advisor's prompt/LLM content (Phase 2 per §3.6 — `advisor_observations` table is Phase 1 regardless); any *write* path on the Advisor side (rubric I-1 — the Advisor is read-only by construction, no write helper exists for it to be walled at); fold-role assignment logic (the autotuner emits `fold_role`; this plan only enforces the read-side filter). |
