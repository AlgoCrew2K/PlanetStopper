# Plan — §8 Tests 1 & 2: S-2 t-stat formula PIN + W-H4 finite-floor sub-case (RED)

> Companion test plan to the tuning-architect-owned M1 + S-2 plan in this folder.
> Critic-domain overlay: enforces H-7 (PINS, not VALIDATES) and H-1's W-H4 named-floor numerical-stability requirement.

| Field | Value |
|---|---|
| Feature | Two RED golden-fixture tests for the new statistical machinery: (a) `test_crra_eu_tstat_formula_pin` — pins `t = mean(U)/(sd(U)/√T)` AND asserts `t ≠ effect_size·√T`; (b) `test_crra_eu_tstat_finite_under_wealth_floor` — exercises W-H4: a fold containing a near-floor wealth-argument day, asserts the returned t-stat is **finite**, `sd(U)` is **finite**, and the floor was applied to `W` (input), **not** to `U` (output). |
| Phase | 1 (companion to the M1 plan) |
| Owner agent-type | `quant-test-writer` (RED test author); reviewed by `quant-code-reviewer` |
| Source-of-truth refs | `docs/handoff/decision-science-council-synthesis.md` §4 (S-2), §3.3 (W-H2/W-H4 four-part claim), §8 tests 1 & 2; `docs/handoff/decision-science-v3-and-divergence-evaluation.md` §A.1 (H-1 WEALTH_ARG_FLOOR on input W), §A.6 (H-6 disclose-and-accept), §A.7 (H-7 PIN not validate); existing pattern in `autotuner.py:289-301` (`compute_sortino_tstat`) and `math_engine.py:30-54` (`_reject_non_finite`) |
| Why | Two distinct categorical guarantees, two distinct tests. Test 1 catches a silent regression to the Sortino form (the H-6 category error the code already fixed once at `autotuner.py:266-271`). Test 2 catches the H-1 NaN-poisoning failure mode: an unfloored CRRA on a near-total-loss day sends `U_i → -∞`, poisons `mean(U)` and `sd(U)`, propagates through `compute_haircut_pvalue`'s `erf` clamp (which only clamps finite extremes), and silently breaks BHY's running-min. **The wording must be "PINS the formula," not "validates the statistic"** — a unit test cannot discharge the methodology claim that √T is the correct denominator under serial-dependence (W-H5 residual). |
| Deliverables | (1) `tests/autotuner/test_crra_eu_tstat_formula_pin.py` — fixture: a known `U`-series with `sd(U) ≠ 1` (e.g. `U = [-0.4, -0.1, 0.0, 0.2, 0.3]` precomputed); assert `t == mean(U)/(sd(U)/√T)` to within 1e-12; assert `t != effect_size·√T` (`effect_size` defined as `mean(U)/sd(U)` only if the function exists — the test must be robust to either reusing or removing the Sortino-style helper for the CRRA path). Docstring explicitly says "PIN, not validation." (2) `tests/autotuner/test_crra_eu_tstat_finite_under_wealth_floor.py` — fixture: a 5-day fold whose `wealth_argument` series contains one near-floor day (e.g. `W = [1.02, 1.00, 1.01, WEALTH_ARG_FLOOR + 1e-9, 1.03]`); assert the returned t-stat is finite; assert `sd(U)` is finite; assert the floor was applied at the *input* — by checking that swapping the near-floor day for an actually-zero-W day produces the **same** t-stat (the floor swallowed it), and that the unfloored CRRA on the zero-W day would produce a non-finite `U` (negative-control via a second fixture asserting `u_crra(0.0, gamma) == -inf`). (3) A documentation fixture (W-H5 disclosure) `tests/autotuner/test_crra_eu_tstat_serial_correlation_known_residual.py` — a known `U`-series with injected lag-1 autocorrelation; assert the function returns plain-√T (no HAC correction); the test's docstring states the result is *known* anti-conservative and the remediation is out of scope per H-6. |
| Dependencies | The M1 plan (defines `compute_crra_eu_tstat` and `WEALTH_ARG_FLOOR`); the W-H2 wealth-argument plan (defines the wealth-argument derivation the floor protects). |
| Golden-fixture tests required | All three test files ARE the §8 deliverables. Fixtures are hand-derived from the formula (`mean(U)/(sd(U)/√T)` evaluated by an independent path — Python's `statistics.mean`/`statistics.pstdev` or numpy — not by re-running the production `compute_crra_eu_tstat`). **Non-circular** because the reference value is computed by a different code path. |
| Definition of Done | All three tests fail RED against a pre-M1 trunk (function not defined → ImportError is RED) and pass GREEN against the M1 implementation. Test 1's docstring explicitly says "PIN, not validation"; the §8 §10-style write-up must use the same wording — any document calling test 1 a "validation" or "verification" of S-2 fails H-7. |
| Risk callouts | **R1 — A future refactor reroutes CRRA through the Sortino helper and test 1 silently passes**: mitigated by the `t != effect_size·√T` assertion using independently-computed `effect_size` (not the helper's output). **R2 — Floor is silently applied to U instead of W**: mitigated by the negative-control fixture and the swap-equivalence assertion. **R3 — Wording drift in v3**: a documentation-only follow-up may be needed if v3 §8 still says "validates"; flag during cross-review. |
| Out of scope | Validating that √T is the correct denominator (that is the W-H5 residual, explicitly out of scope per H-6 and the council); validating the wealth argument derivation (that is W-H2's golden fixture in test 2); any HAC / Newey-West / T_eff correction (out of scope for HARDEN Phase 1 per A.6). |
