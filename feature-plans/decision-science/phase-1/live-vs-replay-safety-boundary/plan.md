# Plan — Live-vs-Replay Safety Boundary (rubric F-1..F-4 + M-2 in Phase 1)

| Field | Value |
|---|---|
| Feature | Phase-1 enforcement of the live-vs-replay safety boundary: (a) every new decision-content code path has an explicit `is_live` flag check before any path that could reach `submit_order` / `place_order` / `cancel_order` / `liquidate`; (b) M2's `cvar_diagnostics` write is deterministic given `(cycle_id, holdings, historical_data)` — same inputs produce bit-identical persisted rows (decision-content columns); (c) the **one** replay-determinism anchor for Phase 1 is M2's CVaR off the `cycle_id`-seeded kNN pool (`derive_cycle_mc_seed` at `math_engine.py:695-702`); (d) shadow mode is defined: M2 takes no action, takes no order path, and the dashboard cannot mutate state via M2's surface; (e) the H4 telemetry helper is the *only* write path for `cvar_diagnostics` and has explicit `live | replay` mode. |
| Phase | 1 (binding — the moment M2 ships) |
| Owner agent-type | `risk-engine-specialist` (the wiring) + `quant-test-writer` (boundary tests) + `quant-code-reviewer` (overlay gates 2 and 8) |
| Source-of-truth refs | `docs/handoff/council-attack-rubric.md` F-1..F-4 ★, M-2 ★ (persisted artifacts replay-deterministic from a recorded seed), I-3 (no Advisor action surface); `docs/handoff/decision-science-council-synthesis.md` §3.7 (anchor count: Phase 1 = 1, Phase 2 = 5), §3.8 (Gate 1 bit-identical replay); `docs/handoff/decision-science-v3-and-divergence-evaluation.md` §A.3 H-3 (H4 helper covers the live per-cycle write, not just Gate-1 parity exclusion), §A.8 A3 (decision-content columns named, `id` and `ts_utc` excluded); project CLAUDE.md architecture constraints 2 (dashboard read-only) and 4 (`is_live=True` explicit); existing `math_engine.py:695-702` (`derive_cycle_mc_seed`), `:828` (isolated `np.random.default_rng`), `database.py:1147-1194` (swallow precedent), `alpha_bot_execution.py` cycle loop |
| Why | M-2 makes replay-determinism a structural invariant — without it K-1 (Gate-1 bit-identical) is unachievable. The H4 helper is load-bearing: it converts a per-cycle write into a non-blocking telemetry side effect in live mode (swallow), and into a hard failure in replay mode (raise) so a replay that cannot persist its decision is loud-broken. The dashboard side-effect ban (architecture constraint 2, overlay gate 8) is a recurring AlphaBot failure mode — any `app.py` route that touches M2's writer or any engine function is a quant-code-reviewer hard block. |
| Deliverables | (1) `is_live` audit table: a single committed CSV `tests/fixtures/live-mode-audit.csv` mapping every new Phase-1 code path that could reach an order helper to the line that gates it (`file:line` of the `if is_live:` guard). One row per path. M2 produces zero rows (it has no order path) — that empty row count is itself the assertion. (2) `tests/execution/test_m2_no_order_path.py` — `grep`-style structural test: asserts no `submit_order` / `place_order` / `cancel_order` / `liquidate` symbol appears in any M2 call-chain reachable from `cvar_diagnostics` writer or its callers; the test reads the import graph, not a wildcard. (3) Tier-1 replay-determinism test `tests/math_engine/test_cvar_5pct_replay_determinism.py` — call M2 twice with identical `(cycle_id, holdings, historical_data)`; assert `cvar_5pct` and `cvar_n_tail` are bit-identical (the §8 test 4 anchor); the seed is `derive_cycle_mc_seed(cycle_id)`, never the global RNG. (4) `tests/execution/test_m2_h4_helper_routing.py` — assert M2's `cvar_diagnostics` write is routed exclusively through the H4 helper (with `mode="live"` or `mode="replay"`); a direct `conn.execute("INSERT INTO cvar_diagnostics …")` outside the helper is grep-fail. (5) `tests/execution/test_h4_helper_live_swallows_replay_raises.py` — H4 helper in `live` mode swallows an injected `sqlite3.OperationalError` and never raises (matching `record_shadow_observation`'s swallow precedent at `database.py:1147-1194`); in `replay` mode the same injection raises and the calling test pytest-fails. (6) `tests/app/test_dashboard_m2_read_only.py` — every Flask route that renders M2 data calls only read-only DB helpers (the dashboard standing read-only-connection pattern); no engine function is called from any `app.py` route; no `cvar_diagnostics` INSERT can originate from the dashboard surface. |
| Dependencies | The M2 plan (defines the per-cycle write); the H4 telemetry helper plan in this folder (`h4-telemetry-helper.md`); rubric M-1 plan (Advisor walling, separate concern but co-resident in Phase 1). |
| Golden-fixture tests required | Tests 3, 4, 5 are golden fixtures (deterministic kNN pool + seeded RNG + injected failure modes). Tests 1, 2, 6 are structural/grep-style — they are not golden-fixture tests but enforce structural invariants the rubric demands (M-2 and constraint 4). |
| Definition of Done | (a) Live-mode audit CSV is committed and CI fails if any new path appears without a row. (b) All six tests pass GREEN; tests 3 and 5 fail RED on the trunk before the M2 and H4-helper land. (c) **Phase-1 replay-determinism anchor count = exactly 1** (M2). A second anchor introduced in Phase 1 is a scope violation; the rubric and §3.7 hard-pin this number. (d) The shadow-mode contract for Phase 1 is explicitly: M2 is read-only on decisions (writes one row of telemetry); there is no shadow *decision* in Phase 1 (`shadow_decisions` is Phase 2). |
| Risk callouts | **R1 — A reviewer approves a "small" Advisor-driven mutation in `app.py`**: overlay gate 8 blocks (dashboard side-effect ban). Reviewer prompt encodes the gate. **R2 — `is_live` defaulted to True for a "convenience"**: overlay gate 2 blocks; test 1's audit CSV makes this auditable. **R3 — Global RNG bleed**: the existing `np.random.default_rng(seed)` pattern at `math_engine.py:828` is the only acceptable shape; tests 3 and 4 fail loud if any new code uses `np.random.seed` or `np.random.choice` directly. **R4 — H4-helper "convenience" union of modes**: a single `mode` parameter, default value disallowed — every call site states `live` or `replay` explicitly (matches the `is_live` discipline). |
| Out of scope | Phase-2's five-anchor seed regime (separate plan in `phase-2/tier1-seed-determinism/`); shadow-decision schema (Phase 2); any change to `is_live` semantics itself; the Advisor frozen-eval wall (separate plan, but co-required); Gate 2 acceptance threshold details (separate Gate-2 plan). |
