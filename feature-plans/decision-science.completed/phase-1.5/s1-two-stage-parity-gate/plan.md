# Plan — S-1 Two-Stage Parity Gate (with committed per-cycle attribution table)

| Field | Value |
|---|---|
| Feature | S-1 — M3's two-stage parity gate. Stage 1: pre-M3 engine replays bit-identical to the current frozen reference; Stage 2: post-M3 engine replays, and **every** divergent cycle is enumerated in a committed per-cycle attribution table, each attributed to a specific re-derived curve value in the intended direction. Post-M3 output then becomes the new committed frozen reference. |
| Phase | 1.5 (ships with M3) |
| Owner agent-type | `quant-test-writer` (RED test author and harness builder) + `risk-engine-specialist` (M3 implementer) under `quant-code-reviewer` overlay |
| Source-of-truth refs | `docs/handoff/decision-science-council-synthesis.md` §3.1, §4 (S-1), §8 test 5; `docs/handoff/decision-science-v3-and-divergence-evaluation.md` §A.5 (H-5: floor removes R3 only; R1/R2 need M3 under S-1); `docs/handoff/council-attack-rubric.md` K-1 (Gate-1 concrete checkable definition), F-2 (bit-identical replay); existing parity harness `tests/autotuner/test_c3_replay_exit_parity.py`; current frozen-eval implementation in `autotuner.py` |
| Why | "Explained divergence as prose" is K-1 fail per the rubric. Without a per-cycle attribution table, an M3 PR could ship undetected drift smuggled in as a "curve re-derivation." The two-stage form proves (Stage 1) the harness itself is faithful, then (Stage 2) every byte of divergence is owned by a named curve change. |
| Deliverables | (1) A pre-M3 reference frozen at the M3-merge-base SHA, captured as a committed artifact (`tests/fixtures/s1-stage1-reference/decision-records.jsonl` or equivalent). (2) The replay-parity harness extended with a `--reference=<path>` flag and an attribution-table emitter. (3) `tests/autotuner/test_s1_stage1_pre_m3_parity.py` — runs the pre-M3 code on the committed reference fixture, asserts bit-identical decision records (decision-content columns only; exclusion list named in H-8/A3). (4) `tests/autotuner/test_s1_stage2_post_m3_attribution.py` — runs post-M3 code, emits the per-cycle attribution table `tests/fixtures/s1-stage2-attribution.csv` (one row per divergent cycle: `cycle_id`, `symphony_id`, `field_changed`, `old_value`, `new_value`, `attributed_curve` ∈ {`time_squeeze`, `vwap_system_a`}, `intended_direction` ∈ {`tighter`, `looser`}, `direction_check_passed` bool). Asserts every divergent cycle is in the table; every row's `direction_check_passed` is True; non-divergent cycles are bit-identical. (5) Post-M3 reference promoted into the same artifact path — the post-M3 output becomes the new committed reference under a versioned filename. |
| Dependencies | M3 plan (`phase-1.5/m3-redrive-provenance-gaps`); rubric H-8/A3 column-exclusion list (named in M2 plan and Gate-1 plan). Stage 1 must commit **before** M3 changes land — otherwise the harness has nothing to reference. |
| Golden-fixture tests required | The Stage 1 reference fixture and the Stage 2 attribution-table fixture are themselves the golden artifacts. Provenance: Stage 1 reference is captured from the actual pre-M3 production code on a frozen historical fold; Stage 2 attribution is hand-derived from the documented intended directions of the re-derived curves and machine-verified by the harness. **Non-circular**: the attribution table's `intended_direction` is authored from the M3 design doc, not from the post-M3 code's output. |
| Definition of Done | (a) Stage 1 test passes: pre-M3 code replays the reference fixture with zero divergence on decision-content columns. (b) Stage 2 test passes: every post-M3 divergent cycle is attributed in the table with the intended-direction check green. (c) The post-M3 reference is committed and replaces the pre-M3 reference for all subsequent regression runs. (d) A prose-only "summary of divergences" is **explicitly insufficient** — this DoD requires the per-cycle table. (e) Both tests run on CI; the attribution table is a checked-in artifact, not a generated-at-test-time output. |
| Risk callouts | **R1 — A flaky upstream input (wall-clock, locale, RNG global) causes spurious divergence**: mitigated by F-2 determinism rules in the live-vs-replay plan; the harness asserts the seeded MC RNG is the only randomness source. **R2 — The exclusion list silently grows**: an exclusion ledger (`tests/fixtures/s1-column-exclusions.txt`) is the only place exclusions are added; a PR that grows it triggers reviewer attention. **R3 — Stage 2 attribution is hand-curated and becomes stale**: when M3 ships further curve revisions, the table must be regenerated and re-committed by the M3-revision author, not the reviewer. |
| Out of scope | Performance/profiling of M3's curves (covered by engine-audit lane); ES-coverage validation of M3 (the curves are protective heuristics, not statistical estimators); any divergence diagnostic that goes beyond the named curve set (an unattributable divergence is a hard fail, not an explained residual). |
