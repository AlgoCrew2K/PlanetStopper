# Plan — Engine Audit: Live-vs-Replay Determinism Stack Audit

| Field | Value |
|---|---|
| Feature | Post-decision-science-changes audit of every RNG, wall-clock read, environment read, unordered iteration, and parallel reduction in the engine's hot path. Confirms (a) the Phase-1 anchor count is exactly 1; (b) the Phase-2 anchor count is exactly 5; (c) no global RNG is used in any decision-content code; (d) no wall-clock read affects a decision value (only telemetry `ts_utc`); (e) Python dict iteration ordering or set iteration ordering does not affect a numerically-sensitive reduction. |
| Phase | Engine audit (post-Phase-1; re-runs at Phase-2 entry) |
| Owner agent-type | `quant-code-reviewer` (audit lead) + `risk-engine-specialist` |
| Source-of-truth refs | `docs/handoff/council-attack-rubric.md` F-1..F-4 ★, M-2 ★; `docs/handoff/decision-science-council-synthesis.md` §3.7 (anchor count Phase 1 = 1, Phase 2 = 5); existing pattern at `math_engine.py:695-702`, `:828` (isolated `np.random.default_rng`); existing seed discipline `derive_cycle_mc_seed`; the live-vs-replay safety-boundary plan in `phase-1/` |
| Why | Determinism is the precondition of Gate-1 (K-1) and the structural anchor of M-2. A single RNG bleed, wall-clock leak, or dict-ordering dependency breaks bit-identical replay silently. The audit must find these structurally, not by waiting for a Gate-1 failure to surface them. |
| Deliverables | (1) `docs/handoff/engine-audit/determinism-stack-findings.md` — the full enumeration: every RNG construction site, every `datetime.now()` / `time.time()` / `time.monotonic()` call, every `os.environ` read, every `set(...)` / `dict.items()` iteration that feeds a numerically-sensitive reduction. Each row records whether the consumer is on the decision-content path or telemetry-only. (2) `tests/integration/test_no_global_rng_in_decision_content.py` — grep test: no `np.random.seed`, no `np.random.choice` without a `default_rng(seed)`, no `random.seed`, no `random.choice` on the module-level RNG, in any function reachable from the decision-content path. (3) `tests/integration/test_no_wallclock_in_decision_content.py` — grep test: every `datetime.now()` / `time.time()` call is annotated `# telemetry-only` or is in the telemetry-routing helper (`write_telemetry_row` / `record_*`); a wall-clock call in `math_engine.py` or in any decision-content code path is flagged. (4) `tests/integration/test_decision_content_dict_iteration_safe.py` — for every dict-iteration in a numerically-sensitive reduction, the iteration is over an explicitly sorted key list — `sorted(d.keys())` not `d.keys()`. (5) `tests/integration/test_phase_1_replay_determinism_anchor_count_is_one.py` — opens the anchor-set JSON (also used by the Gate-1 plan); asserts the count is exactly 1 (Phase 1) or 5 (Phase 2 when enabled). (6) Audit cross-checks every entry in `feedback_no_git_stash_in_shared_worktree` and `feedback_fresh_git_check_before_stall_escalation` — these are determinism-adjacent operator-process invariants and the audit confirms tooling matches (not in-scope for production code, but in-scope for the audit document if any audit tooling is added). |
| Dependencies | The live-vs-replay safety-boundary plan (defines the anchor list); the H4 helper plan (telemetry routing); the MC-blast-radius plan (the consumer enumeration). |
| Golden-fixture tests required | Tests 2, 3, 4, 5 are structural/grep tests; the audit document is the deliverable. |
| Definition of Done | (a) Findings document is committed with every RNG / wall-clock / iteration site enumerated. (b) Four tests pass GREEN. (c) The Phase-1 anchor count is structurally pinned at 1; Phase-2 at 5. (d) Every BLOCK finding has a follow-up TDD plan. |
| Risk callouts | **R1 — `datetime.now()` in a math function bleeds wall-clock into a decision value**: rubric F-2 fail; test 3 catches. **R2 — A `set` of strings iterates differently across Python versions and changes a reduction order**: test 4 catches. **R3 — A "small" `random.choice` slips into a helper**: test 2 catches. **R4 — Anchor count drifts from 1 → 2 in Phase 1**: test 5 hard-pins. |
| Out of scope | Cross-machine reproducibility (matching numpy versions etc. — operational concern); parallelism / multi-threading reproducibility (Optuna study parallelism is handled by the optuna-methodology audit lane); time-zone handling (separate concern, already audited under `is_in_open_window_grace`). |
