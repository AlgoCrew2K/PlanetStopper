# Plan — Engine Audit: Dashboard Read-Only Surface Enforcement Audit

| Field | Value |
|---|---|
| Feature | End-of-cycle structural audit of `app.py` and all Flask routes against architecture constraint 2 (dashboard is a read-only operator surface) and standing reviewer gate 8. The audit closes the loop with the Phase-1 dashboard-side-effect-ban plan: confirms its `@pure` / `@stateful` annotation discipline holds end-to-end, the read-only DB connection pattern is universal, and no Advisor-rendering route gains an action surface. |
| Phase | Engine audit (post-Phase-1; re-runs whenever a new route lands) |
| Owner agent-type | `flask-dashboard-specialist` (audit lead) + `quant-code-reviewer` (overlay gate 8) |
| Source-of-truth refs | project CLAUDE.md architecture constraint 2; `docs/handoff/council-attack-rubric.md` I-3 (Advisor cannot trigger live action; dashboard cannot gain action surface), standing gate 8; the dashboard-side-effect-ban plan in `phase-1/` |
| Why | Dashboard side effects are a recurring AlphaBot failure mode and a standing reviewer-overlay gate. The Phase-1 plan installs the structural tests; this engine-audit lane confirms the tests have full coverage (every route, every Advisor render path, every M2 panel) and that the `@pure` / `@stateful` annotation is applied to **every** engine function so the denylist test 2 in the Phase-1 plan has nothing to escape. |
| Deliverables | (1) `docs/handoff/engine-audit/dashboard-routes-findings.md` — every Flask route enumerated; per-row, the DB connection mode, the engine functions called, the `@pure`/`@stateful` annotation status of each called function, and whether the route is allowed under constraint 2. (2) Full annotation sweep: every function in `math_engine.py`, `alpha_bot_execution.py`, `database.py`, `autotuner.py` annotated `@pure` or `@stateful` (or whatever marker the team picks). Functions without an annotation fail the audit. (3) `tests/app/test_every_engine_function_is_annotated.py` — structural test using `inspect` over every function in those modules; asserts each has the annotation. (4) `tests/app/test_every_route_calls_only_pure_or_h4.py` — for every route handler, the import-graph reachable function set is a subset of `{@pure-annotated} ∪ {write_telemetry_row}`. The H4 helper is the **only** stateful exception, and it must never be called from a route (the live-vs-replay plan's test 6 enforces this — the audit cross-references). (5) The audit produces a follow-up TDD plan per route that fails the audit (none expected if Phase-1 is honest). |
| Dependencies | The dashboard-side-effect-ban plan; the H4 helper plan; the Advisor M-1 wall plan; the live-vs-replay plan. |
| Golden-fixture tests required | Tests 3, 4 are structural tests (no fixture). |
| Definition of Done | (a) Findings document is committed with every route enumerated. (b) Two tests pass GREEN. (c) Every engine function is annotated. (d) Zero routes call a `@stateful` function. (e) The reviewer gate 8 is now backed by two CI signals (one from the Phase-1 plan, one from this audit). |
| Risk callouts | **R1 — Annotation is misapplied** (a `@pure`-annotated function has hidden I/O): the Phase-1 plan's property-test catches; the audit cross-references. **R2 — A new route lands without an audit re-run**: the structural test 4 fails CI loud on a new unannotated function called from a route — auto-catch. **R3 — The annotation convention is renamed / refactored**: the audit document binds the convention; renaming requires the audit to re-run. |
| Out of scope | Browser-side state / cookies; HTTPS / authentication; dashboard styling; the Material Design re-style cycle. |
