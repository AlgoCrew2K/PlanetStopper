# Plan — Gate 1: Backtest-Replay Parity (decision-content bit-identical) — Phase-1 floor

| Field | Value |
|---|---|
| Feature | The Phase-1 form of Gate 1: replay reproduces the live Guard-Alpha decision sequence **bit-identical** on a named decision-content column set, with a committed exclusion list (`id`, `ts_utc`, `built_at_utc`). For Phase 1 the parity surface includes M2's `cvar_diagnostics` decision-content columns (`cvar_5pct`, `cvar_5pct_stderr`, `cvar_n_tail`; plus `cvar_5pct_long`, `cvar_n_tail_long` if the §B residue ships); M1 introduces zero new decision content (deployment-objective change only — autotuner-internal). |
| Phase | 1 |
| Owner agent-type | `quant-test-writer` (the parity harness extension and the §8 test 4 anchor) + `quant-code-reviewer` (overlay gate 4 on the migration column exclusion list) |
| Source-of-truth refs | `docs/handoff/decision-science-council-synthesis.md` §3.8 Gate 1, §8 test 4; `docs/handoff/decision-science-v3-and-divergence-evaluation.md` §A.8 A3 (named exclusion list: `id`, `ts_utc`); `docs/handoff/council-attack-rubric.md` K-1 ★ (concrete checkable definition), F-2 ★ (bit-identical under seed), M-2 ★ (replay-deterministic from seed); `docs/handoff/council-converged-migration-plan.md` §6 H4 (Gate-1 parity excludes telemetry incidentals); existing parity test `tests/autotuner/test_c3_replay_exit_parity.py` |
| Why | "It looked fine" fails K-1. A bit-level reference under a fixed seed is the only structurally-checkable form of Gate 1. The exclusion list must be named (not "decision-content columns" as prose) because a reviewer cannot otherwise tell whether `id` or `ts_utc` is excluded — and asserting on either of those would falsely fail a bit-identical decision. M2 is the **one** Phase-1 anchor (per §3.7); a second anchor is a scope violation. |
| Deliverables | (1) `tests/fixtures/gate-1-decision-content-columns.json` — the committed, machine-readable column list per state-DB table. For `cvar_diagnostics` (Phase 1): `["cvar_5pct", "cvar_5pct_stderr", "cvar_n_tail"]` (+ optional `"cvar_5pct_long", "cvar_n_tail_long"`); for `bot_state` and `exit_triggers` (existing): the existing decision-content set, copied from the current parity harness as a baseline. **Exclusion list** (committed alongside): `["id", "ts_utc", "built_at_utc"]`. (2) `tests/autotuner/test_gate_1_replay_parity_decision_content.py` — runs the autotuner's `_replay_exit_tick` over the Phase-1 frozen replay set; for every `cycle_id` collected, the live-captured `cvar_diagnostics` row and the replay-captured row are diff'd on the decision-content column set only; an excluded column is silently allowed to drift. Asserts zero divergence. (3) `tests/autotuner/test_gate_1_exclusion_list_is_committed.py` — opens the JSON, asserts `id`, `ts_utc`, `built_at_utc` are in the exclusion list; asserts no decision-content column also appears in the exclusion list (no overlap). (4) `tests/autotuner/test_gate_1_no_silent_column_drift.py` — for each named decision-content column, the test queries `PRAGMA table_info(cvar_diagnostics)` and asserts the column exists in the schema — a column rename / drop / accidental migration that omits the column from the decision-content surface fails Gate 1 even before the parity diff runs. (5) The §8 test 4 anchor `tests/math_engine/test_cvar_5pct_replay_determinism.py` (also referenced in the live-vs-replay plan) — same `cycle_id` run twice yields bit-identical `cvar_5pct` and `cvar_n_tail` from the `cycle_id`-seeded kNN pool. This is the **1** Phase-1 anchor. |
| Dependencies | Migration `023_cvar_diagnostics.sql` (persistence-architect); the M2 plan (defines the column set); the live-vs-replay plan (defines the seed discipline); the H4 helper plan (defines the writer routing so live and replay rows are written via the same code path). |
| Golden-fixture tests required | Tests 1, 2, 3, 4, 5 are all golden-fixture tests. The replay set itself is captured from frozen historical cycles via the existing autotuner replay harness — **non-circular** because the live-captured rows came from production runtime, not from the replay code under test. |
| Definition of Done | (a) Five tests pass GREEN; the test 5 anchor fails RED before M2 lands (function not yet defined). (b) The exclusion list is the **only** place exclusions are declared; the parity test reads the JSON, not a hardcoded set. (c) Adding a Phase-1 decision-content column requires a one-line diff to the JSON; a forgotten JSON update fails test 4 loud. (d) Phase 1 ships with **exactly one** replay-determinism anchor (test 5); a second anchor in Phase 1 is a scope violation flagged by the live-vs-replay plan. (e) M1 contributes zero new Gate-1 columns (offline-only); the test inventory confirms this. |
| Risk callouts | **R1 — A reviewer flags a column "incidental" and adds it to the exclusion list silently**: mitigated by the no-overlap assertion and an exclusion-ledger commit-log discipline encoded in the reviewer prompt. **R2 — `cvar_5pct_long` column lands without `cvar_n_tail_long`**: both ship together or neither — the migration plan enforces; the Gate-1 test fails if only one is present. **R3 — The replay set drifts** (capture changes between live and replay runs): the harness emits the captured run's commit SHA into a manifest at capture time; the parity test asserts the manifest SHA matches the test-run SHA before comparing. |
| Out of scope | Phase-2 parity (separate plan — 5 anchors including `tier1_seed`); Gate 2 (separate plan — live shadow N-weeks-clean); P&L-based parity (rubric K-1 forbids — parity is asserted on the decision record, not on P&L); the autotuner's existing per-symphony replay (existing harness unchanged by this plan). |
