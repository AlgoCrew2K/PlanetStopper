# Plan — Gate 2 (Phase-1 form): Live Shadow N-Weeks-Clean — Diagnostic Quality Only

| Field | Value |
|---|---|
| Feature | The Phase-1 form of Gate 2: M2's diagnostic runs in shadow permanently (takes no action). The pre-registered acceptance criterion is **diagnostic quality**, not trigger behavior — explicitly **not** a joint VaR-ES coverage backtest (which is structurally underpowered at AlphaBot's data scale and is a Phase-2-or-never deliverable per §2.3). Criteria: zero NaN/inf in persisted `cvar_5pct`; the four-part S-3 display contract present on every render; reproducibility under replay; M2 writer's per-cycle latency within budget. |
| Phase | 1 |
| Owner agent-type | `risk-engine-specialist` + `quant-test-writer` + `quant-code-reviewer` |
| Source-of-truth refs | `docs/handoff/decision-science-council-synthesis.md` §3.8 Gate 2 (Phase-1 form); §3.9 W-H1 (M2 evidentiary ceiling KILL-or-INCONCLUSIVE); `docs/handoff/decision-science-v3-and-divergence-evaluation.md` §A.4 H-4 (M2 is operator instrumentation, not a Phase-2 stepping-stone); `docs/handoff/council-attack-rubric.md` K-2 ★ (pre-registered acceptance threshold), F-3 ★ (shadow-mode contract); existing shadow precedent in the codebase |
| Why | A joint VaR-ES coverage test (Acerbi-Székely / Fissler-Ziegel) needs ~1,000 tail observations; AlphaBot has ~37 per 3 years. Forcing a calibration-grade Gate 2 onto M2 makes Gate 2 either unpassable or fraudulent. The honest Phase-1 Gate 2 is the **diagnostic-quality** form — does the diagnostic render correctly, honestly, and reproducibly. That is verifiable; the calibration form is not. |
| Deliverables | (1) `docs/handoff/gate-2-phase-1-acceptance-criteria.md` — pre-registered, committed BEFORE shadow mode begins, with: (a) shadow run length (concrete: ≥ 20 trading days, matching `PURGE_DAYS`); (b) zero NaN/inf in any persisted `cvar_5pct` (the H-1 W-H4 floor's runtime invariant); (c) the four-part S-3 display contract present on every M2 render (S-3 a/b/c/d — synthesis §3.1); (d) reproducibility — re-running the replay over the shadow period yields bit-identical `cvar_5pct` (Gate-1 parity passes on the shadow period); (e) the H4 helper's per-cycle write latency within the bench budget. **Explicitly out of scope for Phase-1 Gate 2:** any calibration test of CVaR-vs-realized tails. (2) `tests/integration/test_gate_2_phase_1_nan_inf_freedom.py` — drains `cvar_diagnostics` over the shadow window; asserts zero NaN, zero ±Inf in `cvar_5pct` and `cvar_5pct_stderr`. (3) `tests/integration/test_gate_2_phase_1_display_contract_persistence.py` — for every row in the shadow window, the rendered dashboard fragment carries all four S-3 elements (cross-references the §8 test 3 / s3-display test). (4) `tests/integration/test_gate_2_phase_1_replay_parity_holds_on_shadow_window.py` — Gate-1 parity test (separate plan) is run over the shadow window's cycle_ids; asserts zero divergence. (5) Operator runbook `docs/runbooks/gate-2-phase-1-shadow-mode.md` — names the runtime owner, the daily inspection step (one query for NaN/inf + one render check), and the failure escalation. |
