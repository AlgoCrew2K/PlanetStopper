# Plan — MC Sentinel Consumer Blast Radius (frozen run_monte_carlo through Phase 1; `CVaRAssessment` typed object for Phase 2)

| Field | Value |
|---|---|
| Feature | Two binding constraints carried as Phase-1 invariants: (a) `run_monte_carlo`'s signature and return type are **frozen** through both phases until the LAST symphony cuts over — no Phase-1 PR mutates them; (b) the Phase-2 forward-path simulator and CVaR co-signal use a new typed object `CVaRAssessment` with fields `cvar_pct: float | None`, `breach: bool`, `tail_obs_count: int`, `insufficient_reason: str | None`. **`cvar_pct is None`** is the out-of-band insufficient sentinel mirroring `MC_INSUFFICIENT_HISTORY_SENTINEL`; **`breach` is always `False` when `cvar_pct is None`** (fail-safe — heuristic floor still protects). |
| Phase | 1 (the freeze invariant is a Phase-1 gate against scope creep); the `CVaRAssessment` shape is consumed in Phase 2 but its contract is finalized now so the M2 column shape (`cvar_diagnostics`) and Phase 2's eventual cutover are coherent (rubric G-1, G-2, E-3) |
| Owner agent-type | `risk-engine-specialist` (Phase 2 simulator) + `quant-code-reviewer` (overlay gate for `run_monte_carlo` freeze) + `quant-test-writer` (consumer-enumeration tests) |
| Source-of-truth refs | `docs/handoff/council-attack-rubric.md` G-1 ★ (7+ consumers enumerated), G-2 ★ (net-new not "parameter change"), F-4 (sentinel discipline), C-2 ★ (bias direction); `docs/handoff/decision-science-council-synthesis.md` §2.6 (critic spine — no mutation of `run_monte_carlo`, `CVaRAssessment` frozen typed object with `tail_obs_count`), §5.3 (Phase-2 `simulate_forward_paths` is net-new); `docs/handoff/council-converged-migration-plan.md` §6 H7 (run_monte_carlo blast radius); project memory `project_mc_sentinel_consumer_blast_radius` (7+ consumers across alpha_bot_execution / reporting / synthetic_history / autotuner); existing sentinel pattern at `math_engine.py:70-74`, `:739-744` |
| Why | A return-type change to `run_monte_carlo` touches 7+ sites (memory-confirmed). The freeze invariant is the project's single largest blast-radius defense and must be enforced **structurally**, not by reviewer attention. `CVaRAssessment` is the typed shape that lets Phase-2 cutover proceed per symphony without a big-bang signature change. The `None`-implies-`breach=False` invariant is fail-safe: if the new layer cannot produce a CVaR, the existing protective stop must still fire — never the other way around. |
| Deliverables | (1) Frozen consumer enumeration `docs/handoff/run-monte-carlo-consumer-map.md` — a committed table of all `run_monte_carlo(...)` call sites and `mc_prob` / `mc_history` consumers as of the Phase-1 baseline SHA (project memory says 7+; the enumeration must be exhaustive). (2) `tests/math_engine/test_run_monte_carlo_signature_frozen.py` — an introspection test: `inspect.signature(run_monte_carlo)` is compared against a frozen baseline; a parameter add/remove/rename fails the test. Return-type annotation also pinned (or a structural test on the return shape: scalar OR `None`). (3) `tests/math_engine/test_cvar_assessment_dataclass_contract.py` — the `CVaRAssessment` dataclass: assert exact field set `{cvar_pct, breach, tail_obs_count, insufficient_reason}`; assert `cvar_pct=None → breach=False` invariant via `__post_init__` (or a frozen `@dataclass(frozen=True)` constructor that raises on a `cvar_pct is None, breach=True` combination); assert the dataclass is import-safe and unused in Phase 1 (no production consumer; Phase 2 introduces the consumer). (4) `tests/math_engine/test_cvar_assessment_fail_safe_invariant.py` — every `CVaRAssessment` returned by the (future) `simulate_forward_paths` with `cvar_pct is None` has `breach=False`; a property test exhaustively constructs `None`-case instances. (5) `tests/integration/test_run_monte_carlo_consumers_enumerated.py` — `grep`-asserts the count of `run_monte_carlo(` and `mc_prob` / `mc_history` references is ≥ the baseline count, and zero of those sites are mutated by this PR (a structural diff-fail on the consumer-map columns). |
| Dependencies | The consumer-map document must be authored against the merge-base SHA; the M2 plan (`m2-cvar-diagnostic`) uses scalar columns matching `CVaRAssessment` field names so Phase-2 cutover is field-rename-only. Phase-2 `simulate_forward_paths` plan in `phase-2/simulate-forward-paths/` consumes this typed object. |
| Golden-fixture tests required | Tests 2, 3, 4 are structural / contract tests with golden fixtures (the frozen signature, the dataclass shape, the property-test invariant). Tests 1, 5 are grep-and-introspect — no fixture file. |
| Definition of Done | (a) Consumer map is committed and references each `file:line`. (b) Signature-freeze test passes; any PR that mutates `run_monte_carlo`'s signature fails CI loud. (c) `CVaRAssessment` is defined, frozen, and the fail-safe invariant holds. (d) Zero Phase-1 PRs land that touch `math_engine.py:run_monte_carlo`'s public surface. (e) The M2 column shape in `023_cvar_diagnostics.sql` matches `CVaRAssessment`'s scalar projection — `cvar_5pct`, `cvar_n_tail`, `cvar_5pct_stderr` map to `cvar_pct`, `tail_obs_count`, the (new) `stderr` field; the migration plan adds `stderr` from this contract. |
| Risk callouts | **R1 — A "tiny" `run_monte_carlo` keyword-only argument addition lands**: the introspection test fails — but a reviewer can blue-stamp the test diff. Reviewer prompt encodes: "any signature change blocks until Phase-2 cutover is approved." **R2 — `CVaRAssessment` grows fields silently**: the exact-set assertion in test 3 catches any field add/remove. **R3 — The `None`-implies-`breach=False` invariant is violated by a future caller** (constructing the dataclass with `cvar_pct=None, breach=True`): the `__post_init__` raises; test 4's exhaustive construction covers it. **R4 — The dataclass is added in Phase 1 and a Phase-1 caller "experiments" with it**: forbidden — the dataclass must have zero production consumers in Phase 1; test 3 grep-asserts that no Phase-1 production code imports it (only tests). |
| Out of scope | The actual `simulate_forward_paths` implementation (Phase 2 plan); the block-bootstrap generator design (Phase 2 plan); kNN regime conditioning (Phase 2 plan); changes to existing MC consumers (frozen by this plan); the legacy-drop ceremony at last-symphony cutover (`council-converged-migration-plan.md` §6 H6 and H7 — Phase-2 cutover plan). |
