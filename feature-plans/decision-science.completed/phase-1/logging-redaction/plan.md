# Plan — Logging Redaction (overlay gate 7): no Composer/Alpaca response bodies in logs

| Field | Value |
|---|---|
| Feature | Phase-1 enforcement of overlay gate 7: log lines must not echo raw Composer or Alpaca response bodies. Applies to every new Phase-1 log line (M2 writer failure log, H4 helper warning log, Advisor render log, any new Composer/Alpaca client wrapper added by the migration). |
| Phase | 1 (binding when any new log line ships) |
| Owner agent-type | `composer-alpaca-integration` (client wrappers) + `quant-test-writer` + `quant-code-reviewer` (overlay gate 7) |
| Source-of-truth refs | `docs/handoff/council-attack-rubric.md` standing reviewer gate 7 (no Composer/Alpaca response bodies verbatim), I-3 (Advisor logs included); project CLAUDE.md (logs are operator-visible artifacts) |
| Why | Composer and Alpaca responses contain account IDs, position-level dollar amounts, and webhook URLs. Logging response bodies verbatim is a credentials-and-PII leak vector. Phase-1 introduces several new log lines (H4 helper warning, M2 NaN-guard logs); each is a new attack surface. |
| Deliverables | (1) A redaction allowlist `tests/fixtures/log-redaction-allowlist.txt` — the named log fields permitted for each new Phase-1 logger (`table_name`, `cycle_id`, `symphony_id`, `error_type`, `error_message_class` — never raw error messages from Alpaca/Composer, which may echo response payloads). (2) `tests/integration/test_h4_helper_log_redaction.py` — inject a synthetic Alpaca-style `APIError("response body containing account_id=ALP1234567890 position_qty=12345.67")`; assert the H4 helper's log line contains the error class only and NOT the response body substring. (3) `tests/integration/test_m2_log_redaction.py` — inject a Composer response payload as an M2 holdings input; assert any log line that fires on the unhappy path contains only the cycle_id and the error class. (4) `tests/integration/test_composer_alpaca_client_log_redaction.py` — for any new Composer/Alpaca client wrapper added in Phase 1, assert response-body fields (account_id pattern, position_qty pattern, webhook URL pattern — regexes captured) never appear in stdout/stderr. (5) Reviewer prompt addendum — overlay gate 7 cites the failing test ID when blocking. |
| Dependencies | The H4 helper plan; the M2 plan; any new Composer/Alpaca wrapper introduced by the migration (none in Phase 1 by default — `run_monte_carlo` is frozen and no new external call lands). |
| Golden-fixture tests required | Tests 2, 3, 4 are golden-fixture tests with injected synthetic responses. |
| Definition of Done | (a) Allowlist is committed and is the only source of permitted log fields. (b) Three integration tests pass GREEN. (c) Reviewer gate 7 is now backed by a CI signal — a reviewer cites a failing test, not the rule. |
| Risk callouts | **R1 — A "debug" log line echoes the full response for triage**: forbidden in committed code; if needed at all, gate behind an env-var that is **never on in production** (operator runbook step). **R2 — Allowlist creep**: a new field added to the allowlist requires reviewer sign-off — encoded as a comment in the file. **R3 — Structured-log formatter widens the payload**: the test asserts on the final formatted string, not the structured object, catching formatter regressions. |
| Out of scope | Phase-2 logging surfaces (additive — same rules apply); the LLM-authored Advisor's prompt content (Phase 2; rule applies); Discord webhook payloads (separate redaction concern in `reporting.py` — existing audit). |
