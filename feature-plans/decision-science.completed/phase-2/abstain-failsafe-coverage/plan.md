# Plan — Phase-2 Test Design: Abstain-Fail-Safe Coverage for the Forward-Path Simulator

| Field | Value |
|---|---|
| Feature | Test design for the Phase-2 forward-path simulator's abstain-fail-safe contract: when the simulator cannot produce a multi-day path (thin pool, failed calibration, missing manifest, stale bank), it returns `CVaRAssessment(cvar_pct=None, breach=False, tail_obs_count=N, insufficient_reason="...")` and the existing heuristic floor (6 layers) continues to protect. The protective stop never depends on a CVaR estimate that could be biased permissive. |
| Phase | 2 (test design parallel to the simulator build; activates only after precondition gate clears) |
| Owner agent-type | `quant-test-writer` + `quant-code-reviewer` (rubric F-4, C-2) |
| Source-of-truth refs | `docs/handoff/council-attack-rubric.md` F-4 (insufficient-data path returns out-of-band sentinel, never an in-band CVaR; protective stop still functions), C-2 ★ (bias direction must not leave protective stop silently disabled); `docs/handoff/decision-science-council-synthesis.md` §5.3 (`CVaRAssessment` frozen typed object; `None`-implies-`breach=False`); existing pattern at `math_engine.py:70-74`, `:739-744` (`MC_INSUFFICIENT_HISTORY_SENTINEL`); MC-blast-radius plan in `phase-1/mc-sentinel-blast-radius/` (defines the typed object); existing fail-safe call-path memory `feedback_audit_findings_need_call_path_verification` |
| Why | A live CVaR layer that cannot compute a budget must abstain, not abstain-and-disable-protection. The path bank, calibration, regime bucketing, and Tier-1 batch all have failure modes (stale manifest, thin bucket, latency miss). Each must return the `None` sentinel and let the heuristic stack continue to fire. The audit-finding memory says file-scoped grep is not enough — the test must verify the *reachable call path* from the simulator's failure modes through to the protective-stop branch. |
| Deliverables | (1) `tests/math_engine/test_simulate_forward_paths_thin_pool_abstain.py` — fixture: a regime bucket with fewer than the floor of distinct tail observations; assert `simulate_forward_paths(...)` returns a `CVaRAssessment` with `cvar_pct is None`, `breach is False`, and a non-None `insufficient_reason`. (2) `tests/math_engine/test_simulate_forward_paths_missing_manifest_abstain.py` — fixture: a Tier-2 cycle reads `path_bank_manifest` and finds the row missing or `superseded_at_utc` set; assert the same abstain result. (3) `tests/math_engine/test_simulate_forward_paths_failed_calibration_abstain.py` — inject a calibration failure (Politis-White block-length selector returns NaN); assert the same abstain result. (4) `tests/integration/test_protective_stop_fires_when_cvar_abstains.py` — set up a holdings + history fixture where the heuristic stack (specifically the trailing-stop layer) is on a clear exit signal AND `simulate_forward_paths` returns `cvar_pct is None`; assert the protective stop fires. Asserts on the resolved exit reason being one of the heuristic layers, NOT "no exit." (5) `tests/integration/test_cvar_cosignal_never_silently_disables_protective_stop.py` — fuzz test: across 100 random `(holdings, history, regime)` fixtures, the protective stop's behavior is identical whether `cvar_cosignal` is `None` or `False`; the test fails if any fixture's exit decision differs between the two. (6) `tests/integration/test_cvar_assessment_post_init_invariant_holds_under_simulator.py` — every `CVaRAssessment` returned by the simulator across the fuzz set passes the `cvar_pct=None → breach=False` invariant (the post-init guard from the MC-sentinel-blast-radius plan). |
| Dependencies | The simulator plan (`phase-2/simulate-forward-paths/`); the MC-blast-radius plan (`phase-1/mc-sentinel-blast-radius/` — defines `CVaRAssessment`); the priority-resolver-cvar-cosignal plan (`phase-2/priority-resolver-cvar-cosignal/`). |
| Golden-fixture tests required | All six tests are golden-fixture / property tests. Fixtures: thin regime pool (hand-derived), absent manifest (DB fixture), NaN calibration (mocked Politis-White), and the integration fuzz set (seeded RNG over a parameterized space). |
| Definition of Done | (a) Six tests pass GREEN once the simulator and `CVaRAssessment` exist; tests 1-3 fail RED before the simulator's abstain branches land. (b) The reachable call path from each simulator failure mode to the protective-stop branch is enumerated in a committed `docs/handoff/phase-2-cvar-abstain-call-path.md` — never a file-scoped grep claim (per memory `feedback_audit_findings_need_call_path_verification`). (c) The fuzz test (test 5) achieves the property: protective stop NEVER varies on `cvar_cosignal` being `None` vs `False`. |
| Risk callouts | **R1 — A "convenience" assumes `cvar_cosignal` defaults to `False`** silently coercing `None` → `False`: forbidden — the resolver plan must distinguish None (abstain) from False (didn't fire); test 5 catches this. **R2 — A future "performance" PR turns `CVaRAssessment(cvar_pct=None)` into an in-band negative value**: forbidden by the `__post_init__` invariant (MC-blast-radius plan) and by test 6. **R3 — The fuzz test passes by luck**: the test runs over a fixed seed list large enough to exercise every resolver branch; coverage is asserted. |
| Out of scope | The simulator's actual generator family (block bootstrap / GARCH-FHS — Phase-2 implementation plan); calibration of the simulator (Phase-2 plan); the trigger's hysteresis logic (separate plan); the Acerbi-Székely Gate-2 test (separate plan). |
