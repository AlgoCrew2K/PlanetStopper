# Source: backtest-slippage-calibration

Operator source (verbatim, 2026-11-16):
"The fact that you're reporting "problems found in the app" and not fixing them is also suspect.."

The problem it refers to, as the PM reported it (verbatim):
"The advisor's backtests assume 0.5% slippage per trade. On these daily-rebalancing trees that understates live results by 0.2–0.5% a day. At 0.1% the backtests match live within about 0.02% a day. Every advisor backtest gate therefore leans against high-turnover strategies, and against beating SPY."

Pre-supplied answers (PM, verbatim):
1. What this makes true: a Composer backtest the app runs without an explicit slippage argument assumes the per-trade slippage that live Composer fills show, so every advisor gate that compares backtests (Strategy Builder candidates and its SPY baseline, Asset Swaps, Logic Changes, Frontrunner Builder, the incubation tick, backtest_gate_engine) compares on a basis that tracks realized results.
2. Evidence (PM measurement 2026-11-16, read-only, inline these numbers in the plan; the raw files are not tracked): for 8 live symphonies, the current Composer tree was backtested (Composer v2, broker alpaca) at slippage_percent 0, 0.001 and 0.005 and compared day by day with Composer's realized deposit-adjusted daily returns over the 87 trading days since each tree's last edit (2026-07-15..2026-11-13). Daily correlation live vs backtest 0.976–0.996 for all 8. Mean daily gap (live minus backtest), bps/day, at 0 / 0.001 / 0.005: HuntedCascades 1.6/7.8/32.2; FeaverdAlloc 0.1/9.3/45.9; ErasedHistory -11.1/-2.7/30.5; GoldenAgeCopy -1.1/4.2/25.2; Reasonabilists(46 days) -0.9/7.1/38.8; LQD+EYEG -18.1/-11.4/15.3; CorpChaos -3.4/3.2/29.3; Paragons -18.7/-10.5/22.2. Cross-symphony mean: about -6.5 / +2.1 / +30 bps/day. Compounded over the 87 days, e.g. FeaverdAlloc live +57.2% vs backtest +54.8% / +43.1% / +4.4%. Conclusion used: 0.001 is the setting closest to live while staying slightly conservative.
3. Current code (verify at the ref): `advisors/composer_backtest_client.py` `_DEFAULT_SLIPPAGE_PERCENT: float = 0.005` (comment says it matches Composer UI defaults) used as `run_backtest`'s default; `autotuner.py` `SIM_EXIT_FRICTION_PCT: float = 0.5` whose comment derives it from that constant, and `tests/autotuner/test_exit_friction_constant.py` pins that derivation. Find every caller of run_backtest/submit_backtest and whether it passes slippage explicitly.
4. [PM-ASSUMED] New default value: 0.001 (0.1% per trade), with the calibration evidence above recorded where a reader of the constant finds it.
5. [PM-ASSUMED] SIM_EXIT_FRICTION_PCT keeps its value 0.5 percentage points: it models the cost of a Planet Stopper full-position exit in the autotuner replay, a different cost from Composer's daily-rebalance slippage, and changing it would change the optimizer objective without evidence. It must no longer be derived from the backtest default (so the backtest default can change without moving it), and its pin test changes accordingly.

8. Negative cases to cover: a caller passing slippage_percent explicitly (including 0.0) still sends exactly that value; the request body field name and units sent to Composer are unchanged except the default value; SPY baseline backtests use the same default as candidates.
