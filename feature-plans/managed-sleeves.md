# Feature: Managed Sleeves (rule engine + direct Alpaca trade path)
Status: ready
Created: 2026-07-07
Supersedes: feature-plans/guard-rules-engine.md (v1 no-order-path scope; operator overruled 2026-07-07 — direct trade path is IN scope)

## Summary
A managed sleeve is a bounded slice of our own Alpaca account (paper today; live only when operator provisions live keys) governed by operator-authored declarative rules — `when/if/then/limits` + a signed `envelope` hard box — evaluated each engine tick. Rules sense symphony/portfolio state, daily-bar indicators, time-of-day, and cached FRED series; they act via direct Alpaca orders (buy/sell/scale, bracket-with-broker-side-stops, trailing stop, go-to-cash-flatten) with risk-based sizing, plus Discord notify and the existing Composer go-to-cash for symphonies. Every order is clamped to the sleeve's envelope at fire time (reduce-only clamping), preceded and followed by broker-truth reconciliation, and every rule is born in SHADOW. Arming ladder per sleeve: SHADOW (no orders) → PAPER (real orders, paper account) → LIVE (requires live keys + panic-style confirm ceremony). Adapted from the "Managed Sleeves" concept doc (sleeve_guide.pdf — concept validated, product verified non-existent); improved over the source by using Alpaca-native bracket/trailing-stop orders so protective stops live at the broker and survive engine outages.

## Acceptance Criteria

### Sleeve + capital
- [ ] AC-1: Operator can create a sleeve (name, fixed dollar capital, envelope) via CSRF-protected route; sleeve starts in SHADOW; the sleeve's cash ledger is initialized to its capital and all buys are funded exclusively from that ledger — a sleeve can never spend beyond its allocation even if the account holds more cash.
- [ ] AC-2: Envelope is a hard box enforced at fire time: ticker allowlist (validated tradeable via the existing universe check), max single-position % of sleeve equity, per-order dollar cap, max daily turnover, long-only, no margin/shorting. Clamps only ever reduce (qty down, never up; refusal if reduce-to-zero); every clamp/refusal logged with reason.
- [ ] AC-3: Widening an envelope (adding tickers, raising caps) requires re-confirmation through the same ceremony as arming; narrowing takes effect immediately.

### Rule engine (carried from v1 plan, unchanged semantics)
- [ ] AC-4: Rules are validated JSON (`when/if/then/limits`): size/depth/enum-closed schema, field-level errors, no code strings. Senses: symphony state, portfolio state, daily-bar indicators (SMA/EMA/RSI/momentum/realized vol/drawdown-from-high), time-of-day/day-of-week (ET), cached FRED series. Missing/stale sense data ⇒ not-fireable, logged deduped (fail-safe).
- [ ] AC-5: All pacing state (cooldown_sec, max_fires_per_day, episode latch, churn-brake state) is enforced from SQLite across engine restarts — proven by a test simulating consecutive one-shot engine invocations (engine = fresh subprocess per minute, app.py:572-587,697).
- [ ] AC-6: SHADOW rules record fires (sensed snapshot + the exact order the envelope-clamped sizing WOULD have produced) and execute nothing.

### Direct trade path
- [ ] AC-7: A PAPER/LIVE-armed rule with an entry action places the order via the single designated order module against the correct host (paper-api vs api), sized by `riskPct` (risk = riskPct × sleeve equity; qty = risk ÷ stop-distance), or pct-of-sleeve/dollars/shares; every entry defaults to a bracket (Alpaca native order_class=bracket) so no position exists without a broker-side exit.
- [ ] AC-8: `set_stop` arms Alpaca-native trailing-stop or stop/take-profit orders held at the broker — stops survive engine downtime by construction; a test proves the stop order exists at the broker (fixture) independent of our process state.
- [ ] AC-9: Pre-trade reconciliation: before any order, positions/cash for the sleeve are verified against Alpaca account truth within declared tolerances; mismatch ⇒ sleeve status PAUSED_RECONCILIATION, no order, Discord alert. Post-fill: fills polled/recorded, ledger updated, drift re-checked.
- [ ] AC-10: Stop-precedence: protective exits (stop hits, go-to-cash, drawdown flatten) are never blocked by pacing limits, never benched, and are processed before entry actions in the same tick. Flat-latch: after a go-to-cash fires, entries stay suppressed while its condition holds.
- [ ] AC-11: Churn brake: an ENTRY rule with ≥5 same-day round trips at a meaningful net loss is benched for the day (visible status, Discord note, auto re-arm next trading day). Exits are never benched.
- [ ] AC-12: Disarm (per sleeve, one click): all autonomy stops, open UNFILLED orders are cancelled, positions and broker-side stops are NOT touched. Kill is non-destructive; re-arm requires the ceremony.

### Arming ladder & gates
- [ ] AC-13: SHADOW→PAPER arming requires ≥1 recorded shadow evaluation window per rule (no arm-on-faith); PAPER orders are structurally confined to paper-api.alpaca.markets.
- [ ] AC-14: PAPER→LIVE arming is impossible unless distinct live-key env vars are present, a dedicated SLEEVE_LIVE_EXECUTION flag is set, and the operator completes the panic-flow ceremony (session auth + CSRF + exact confirm phrase + audit-always-fires) — modeled precisely on app.py:2764-2845's 6-gate chain.
- [ ] AC-15: New whole-repo invariant test: Alpaca order-endpoint calls (POST/DELETE /v2/orders, position-closing endpoints) exist ONLY in the designated order module; the live trading host string appears nowhere outside the gated config; existing test_m2_no_order_path.py and test_dashboard_no_order_path.py remain green unmodified (engine subprocess places orders, dashboard routes never do).

### Statistical validation (overfitting culling)
- [ ] AC-20: Rule class is declared AND structurally enforced from the action set: DEFENSIVE = reduce-only actions (sell/flatten/go-to-cash/stop-tighten/notify); ENTRY = any position-opening action. Class determines the gate chain; a rule cannot claim DEFENSIVE while holding entry actions (schema-level check).
- [ ] AC-21: PAPER→LIVE arming of an ENTRY rule is blocked without a recorded culling verdict: the rule simulated over the established 250-trading-day walk-forward window as a perturbation cohort (the rule + parameter-perturbed siblings + do-nothing baseline), scored through `advisors/backtest_gate_engine.evaluate_candidate_batch` (BHY winner at q≤0.05 + PBO≤0.5). `pbo=None` is a FAIL for entry-class arming — fail-closed, deliberately stricter than the engine's current None-passes semantics.
- [ ] AC-22: Every culling simulation logs BACKTEST_SELECTION rows to the researcher DOF ledger, so BHY `n_effective` and the Overfitting Conscience S/N watchdog count operator rule-authoring churn. A reworked rule is a new candidate burning recorded trials — iteration is never free.
- [ ] AC-23: DEFENSIVE rules are never alpha-culled. Their live-arm gate: parameter sanity bounds (e.g., stop distance vs realized vol), measured shadow/paper cost (guard-alpha-style), and an envelope insurance-budget cap. "Didn't beat baseline in a calm window" is not a rejection reason for insurance.
- [ ] AC-24: The rule simulator IS the sleeve rule engine executed against historical bars — same senses/conditions/envelope/sizing code, conservative cost haircut — parity by construction, pinned by a parity test in the spirit of `test_c3_replay_exit_parity`. Verdicts persist with their power context (window days, fire count, cohort size, PBO, adjusted p) and render beside the rule on the panel — a verdict never displays as a bare pass/fail.

### Observability
- [ ] AC-16: Dashboard Sleeves panel: sleeve status (SHADOW/PAPER/LIVE/BENCHED/PAUSED_RECONCILIATION/stale), cash ledger vs broker truth, per-rule today/lifetime fires + realized per-rule P&L (attribution from fill records), arm/disarm/delete controls, Atlas cache-health badge (audit MEDIUM-2).
- [ ] AC-17: Discord alerts: fires, fills, clamps/refusals, reconciliation pauses, churn-bench events; EOD digest extended with a sleeve section (per-rule P&L, round trips, benched rules). Routine no-ops silent; repeated identical conditions dedupe to one alert/day.
- [ ] AC-18: Replay: `GET .../replay?days=N` (N ≤ 60) evaluates a rule's conditions over historical daily bars → would-have-fired dates + sensed values; labeled condition-replay, no P&L claim (fill-simulating backtest is OUT).
- [ ] AC-19: Every trade traces to a named rule + fire row + order + fill records; every sleeve/rule/envelope mutation is in the config-audit pattern.

## Architecture
**Build phases (each a PR-able cycle on one feature branch):**
- **P1 — Sleeve infrastructure + order layer:** `sleeves/` package: `alpaca_orders.py` (THE only order-capable module: raw requests like the rest of the codebase, no SDK; bounded retry/backoff modeled on advisors/composer_backtest_client.py:21-65 incl. 429 Retry-After, explicit timeouts, never-raises result objects), `reconciliation.py` (account/positions/orders GET + tolerance checks), `ledger.py` (sleeve cash/position accounting), `envelope.py` (clamp-at-fire, reduce-only), `sizing.py` (riskPct/pct/dollars/shares). DB migration. Paper-host confinement + whole-repo order-symbol invariant tests.
- **P2 — Rule engine core:** `sleeves/rules/` (schema, senses, conditions, limits, runner) — the v1 guard-rules design verbatim, minus the engine/ placement (see Decisions). Shadow fires end-to-end with would-have-ordered snapshots.
- **P3 — Wiring + surfaces:** runner hooked into alpha_bot_execution.main() tick after the existing exit machine (absolute precedence preserved); Flask routes + dashboard panel + replay + digest extension + arming ceremonies (SHADOW→PAPER gate: shadow-window minimum; PAPER→LIVE gate: culling verdict per AC-21/23 + paper track-record minimum + ceremony).
- **P4 — Culling integration (prerequisite for the LIVE rung, not for paper):** `sleeves/culling.py` — rule→daily-returns simulator (the rule engine itself run over historical bars per AC-24), perturbation-cohort builder, `evaluate_candidate_batch` wiring, DOF-ledger logging, verdict persistence + panel rendering. FORBIDDEN integrations: sleeve rules never enter `OPTUNA_SEARCH_SPACE_KEYS` (NN1 structural gate forbids it, autotuner.py:1857) and never touch the autotuner's auto-apply path (autotuner.py:2803 writes live config with no operator gate — the wrong model for order-placing rules); the integration point is exclusively the advisory-verdict producer `backtest_gate_engine.evaluate_candidate_batch` (advisors/backtest_gate_engine.py:525) + the new operator-gated arm route.

**Module placement:** new top-level `sleeves/` package, NOT under `engine/` (engine/ has active port-removal guard tests around exit_authority/dual_altitude; keep blast radius zero). Lazy-import convention (ai_advisor.py CC-2 pattern): alpha_bot_execution imports sleeves.rules.runner inside main(), never module-level.
**DB (additive migrations):** `sleeves` (id, name, capital_usd, status, envelope_json, timestamps); `sleeve_rules` (id, sleeve_id, name, json_doc, mode, enabled, timestamps); `sleeve_rule_fires` (rule_id, fired_at, sensed_snapshot_json, action, clamped, clamp_reason, episode_id, order_id FK nullable); `sleeve_orders` (alpaca_order_id, sleeve_id, rule_id, symbol, side, qty, order_class, status, submitted_at, raw_json); `sleeve_fills` (order_id, fill_price, filled_qty, filled_at); `sleeve_runtime` (pacing/latch/bench state). No changes to existing tables.
**Config:** `ALPACA_KEY/SECRET` stay paper (existing). New: `ALPACA_LIVE_KEY/ALPACA_LIVE_SECRET` (absent by default), `SLEEVE_LIVE_EXECUTION` (default false). Host selection is derived from sleeve status + key presence in exactly one function, unit-locked.
**Data:** iex-feed bars as today (feed pinning per tests/alpaca/test_feed_pinning.py). Market calendar: existing `market_calendar.py` (XNYS, holiday-aware) gates all evaluation — never "hours-only" (Jul-3 lesson).
**Routes:** `GET/POST /api/sleeves`, `POST /api/sleeves/<id>/arm-paper|arm-live|disarm|delete`, `GET/POST /api/sleeves/<id>/rules`, `POST .../rules/<id>/arm|disarm|delete`, `GET .../rules/<id>/replay` — CSRF pattern from POST /api/settings; live-arm route replicates the sell_account gate chain.
**Dependencies:** none new (raw requests; stdlib validation).

## Edge Cases
- Partial fills (bracket parent partially filled at close; ledger reflects filled qty; bracket legs auto-adjust per Alpaca semantics — pin with fixtures).
- Order rejected (buying power, halted symbol, wash-trade rejection, not tradable) → fire recorded with rejection outcome, no ledger mutation, alert; rule NOT benched for broker rejections (only for realized losses).
- Unfilled DAY entry orders at session close → cancelled by TIF; ledger releases reservation.
- Orphaned bracket legs after manual operator intervention at the broker → reconciliation detects unknown/missing orders → PAUSED_RECONCILIATION.
- Engine restart mid-episode/cooldown → state from SQLite (AC-5); engine down while stops armed → broker-side stops still protect (AC-8).
- Reconciliation drift within tolerance (fees, rounding) vs breach → tolerance declared per check; breach pauses only the affected sleeve.
- Corporate actions/splits on sleeve positions → qty/price drift caught by reconciliation; sleeve pauses rather than mis-trades.
- PDT: flag sleeves whose day-trade pattern could trip PDT on a sub-$25k live account (advisory; paper default equity makes it moot in P1).
- Same-tick conflicts: protective exits > entries (AC-10); two entries same symbol same tick → first by deterministic rule order, second skipped+logged.
- Market closed/holiday/early close (XNYS calendar), DST for time senses (ET wall-clock).
- Sleeve deleted with open positions → refuse unless flat, or detach-without-liquidating (guide semantics: delete never liquidates) — refuse-unless-flat in v1, detach is the fallback decision at build time.
- Missing/stale sense data ⇒ not-fireable (AC-4); Alpaca data API down ⇒ skip tick for affected senses, protective broker-side stops unaffected.
- Rule references delisted/renamed symbol → rule flagged stale, skipped.

## Security Considerations
- **Credential separation:** paper and live keys are distinct env vars; live keys absent by default; host selection unit-locked; live host string denylisted outside the config gate (AC-15). Keys never in logs/fire snapshots/Discord/client responses (D-1 contract; existing log-redaction test pattern extends to the order module).
- **Input validation:** rule/sleeve/envelope JSON strictly schema'd (size 32KB, depth 8, enum-closed); parameterized SQL; no eval.
- **XSS/CSRF:** Jinja autoescape for rule/sleeve names; CSRF on all mutating routes; live-arm ceremony additionally requires exact confirm phrase (compare via secrets.compare_digest like app.py:325-362).
- **Order-path containment:** one module may construct order requests (whole-repo AST invariant); envelope clamp is structurally on every order path (runner cannot reach alpaca_orders except through envelope.clamp — enforce by API shape + test).
- **Abuse/DoS:** per-tick evaluation wall-clock budget; replay bounded N≤60; rule count cap; order rate implicitly bounded by tick cadence + pacing limits + turnover cap.
- **Data exposure:** fire snapshots contain market/portfolio values only; static-token error responses; no account numbers in UI beyond last-4.
- **AuthZ:** single-operator posture, same session gate as existing routes; live-arm is the highest-privilege action and gets the full ceremony.

- **Culling tests (P4):** simulator↔live-engine parity (same code path, AC-24); perturbation-cohort construction (sibling generation determinism, do-nothing baseline included); entry-class fail-closed on `pbo=None`; defensive-class rules never routed through BHY-winner requirement; DOF-ledger rows written per simulation; verdict persistence includes full power context; arming route rejects a stale verdict (rule edited after verdict → verdict invalidated).

- **Behavioral/e2e:** seeded-DB dashboard render + Playwright screenshot of the Sleeves panel in every status — screenshot READ and described before any "renders" claim (standing rule); full paper-mode dress rehearsal: one sleeve, one bracket entry rule against fixture-fed engine tick → order in DB, ledger updated, panel shows attribution. | Direct Alpaca trade path IS in scope | Operator decision 2026-07-07, overruling PM's keep-the-invariant default (logged in project memory). The sleeve concept's value is bounded self-directed execution; its safety apparatus exists to make exactly this safe. |

| Broker-side stops (Alpaca native bracket/trailing) over engine-side | Fixes the soft-stop weakness identified in the source PDF: stops survive engine outages. Engine-side logic still decides; broker holds the protective order. |
| Raw requests, no Alpaca SDK | Matches entire existing stack (recon: no SDK anywhere; composer_backtest_client is the retry/timeout gold standard to copy). |
| New top-level `sleeves/` package, not `engine/` | engine/ is a partially-decommissioned area with active removal-guard tests; zero blast radius. |
| Existing m2/dashboard denylist tests stay untouched; containment via NEW whole-repo invariant | Recon: those tests are single-file AST scans that a new module can't trip; honest containment needs a repo-wide scan asserting order code exists in exactly one module. Old guarantees preserved verbatim. |
| Long-only, no margin/shorting, DAY orders, RTH-only in v1 | Minimum-complexity risk posture; matches guide's own defaults; leverage/shorting would need envelope semantics we shouldn't invent yet. |
| Fixed-dollar capital + internal cash ledger, tolerance-based reconciliation | Guide's "books balance exactly" is naive (fees/rounding/corporate actions); tolerance + pause-on-breach is the operable version of its conservation pause. |
| Rule cadence stays the 1-min subprocess tick | Verified subprocess model; 5s would need a daemon rearchitecture; broker-side stops cover intra-minute gaps. |
| Churn brake for entries + episode latch for exits | Entries exist now, so the guide's brake applies as designed (exits never benched); latch still prevents exit fire-storms. |
| Composer symphony go-to-cash remains an action; symphonies-as-layers OUT | Symphonies stay Composer-executed; multi-layer budget pass deferred (phase 2+ if ever). |
| Atlas/Front Runner data is design-time only | Audit ground truth: weekly-cached top-500 catalog, not an intraday feed; bill-protection mandate stands. |
| Class-tiered statistical gates: ENTRY = full culling; DEFENSIVE = sanity bounds + measured cost + budget cap; NOTIFY = schema only | Alpha-culling insurance is a category error (a drawdown brake fitted to the window's crashes, or rejected for a calm sample, is overfitting in the other direction); precedent is the project's own D3 decision to match gate to objective. Guard-alpha exists to MEASURE protection cost, not to demand protection be profitable. |
| Culling integration point = `backtest_gate_engine.evaluate_candidate_batch`, never the autotuner | Recon: the only decoupled abstraction (accepts arbitrary daily-return candidates through fold-transform + BHY + PBO + acceptance gate); the autotuner space is an NN1-closed 6-dial frozenset AND its winner auto-applies to live config with no operator step — structurally the wrong gate model for operator-authored order-placing rules. |
| Entry verdicts require a perturbation cohort; `pbo=None` fails closed for entry arming | A single-candidate run yields `pbo=None`, which today never fires the veto — a vacuous gate is worse than none. The cohort (parameter-perturbed siblings + do-nothing baseline) makes PBO computable AND tests neighborhood robustness: a rule that only wins at its exact parameters is curve-fit. |
| Rule-authoring churn is counted: every simulation logs DOF-ledger BACKTEST_SELECTION rows | The guide's design-lab iterate loop is uncounted search (data snooping). The ledger + Overfitting Conscience S/N watchdog already exist to make search cost visible — operator rules join that accounting rather than bypassing it. |
| Daily-entry signals only in v1; intraday senses reserved for exits | The 250-day window's 1-min tick replay is holdings-shaped (exit replay); validating arbitrary-universe intraday entries would need a per-ticker 1-min warehouse — unjustified cost for the most overfitting-prone trading mode. Daily entries validate on existing data. |
| Culling machinery (P4) gates the LIVE rung only; paper needs shadow-window minimums | Paper trading IS forward-test evidence (the one unminable sample) — gathering it shouldn't wait on P4. Live stays impossible-by-construction meanwhile (no live keys + AC-14 + AC-21). |
| Condition-replay endpoint demoted to diagnostics; never an arming input | Eyeball-fitting a replay is manual data snooping; arming consumes only recorded culling verdicts and forward-test track records. |

## Scope Boundaries
- **IN**: `sleeves/` package (orders, reconciliation, ledger, envelope, sizing, rules, culling); additive DB migrations; paper-account order execution with native brackets/trailing stops; risk sizing; envelope hard box; shadow/paper/live ladder + ceremonies with class-tiered statistical gates; P4 culling integration (rule simulator, perturbation cohorts, `evaluate_candidate_batch` wiring, DOF-ledger accounting, verdict persistence + panel); churn brake + latch + pacing; per-rule attribution from fills; dashboard Sleeves panel + Atlas health badge; Discord alerts + digest extension; condition replay (diagnostics only); whole-repo containment invariant; Composer go-to-cash + notify actions.
- **OUT**: live-money trading until operator provisions live keys (structural); margin, shorting, options, extended-hours; cash-account settlement pacing (paper is margin-style; revisit at live); multi-layer sleeves + budget pass; symphonies-as-layers; sub-minute cadence; intraday ENTRY signals + per-ticker 1-min warehouse (daily-entry signals only); sleeve rules in `OPTUNA_SEARCH_SPACE_KEYS` or the autotuner auto-apply path (never — NN1 + gate-model mismatch); DSR reinstatement (respect decision D3); fill-simulating slippage models beyond the conservative cost haircut; NL rule authoring; advisor-proposed rules (phase 2 attach at existing consent gate); email digests; any non-Alpaca broker; SIP data subscription (operator decision at live).
