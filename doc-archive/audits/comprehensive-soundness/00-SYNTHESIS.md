## 1. Executive Verdict (honest broker)

**Planet Stopper is SOUND-BUT-UNPROVABLE — with three real, fixable code defects (one of which contradicts its own documented intent and needs a user decision only on the fix shape).** The engine is a competently engineered, intellectually honest risk-control overlay: no math layer is unsound *in form* (mathimpl found zero Critical/High/Medium correctness defects across all eight layers; theory found no layer unsound and verified every load-bearing citation against its primary source), the fail-safe *direction* is correct throughout (None-sentinels never silently disable protection at the confirmation layer), and the project's most sophisticated machinery — the BHY/Yekutieli overfitting haircut and the NN1 spec-freeze — is correctly implemented and, crucially, *honest about its own limits in writing*. The user's walk-away bar — "grounded in sound reasoning" — is **met**: the design reasons correctly from cited theory, and where the theory runs out the project has repeatedly chosen to wall off action rather than fake confidence (the twice-rejected CVaR-trigger and CVaR-divergence ideas are both theoretically correct rejections; do not re-litigate). **But the headline value claim splits cleanly and must be reported honestly: the "halve drawdowns" half is theoretically grounded (a stop mechanically truncates the left tail, no regime assumption needed); the "capture upside / Guard Alpha is positive on average" half is regime-conditional and is currently *contraindicated* by the available data — not merely unproven for lack of sample.** The operator's own symphonies measure as mean-reverting-to-random-walk at the intraday horizon (the regime where the project's own cited Kaminski-Lo says stops are neutral-to-harmful), and the live track record (≈6 trading days) is far too thin to prove otherwise — and structurally can never reach the proof bar at this data scale. This is not a defect to fix; it is a property of the problem, and the project already says so. Net: **trust the engineering and the honesty; treat the alpha claim as an unproven regime bet currently leaning the wrong way; fix the three defects; and decide only the fix-shape for the fail-safe gap below.**

## 4. Prioritized Findings

### CRITICAL
*None.* No auditor surfaced a defect that makes the engine actively dangerous on the live path (i.e. no false-liquidation / runaway-order path). The three HIGH items below are serious but bounded: two affect optimization-gate calibration and dashboard state integrity, and the third is an under-protection (fail-to-exit) gap partially covered by the MC-independent VWAP detectors.

### HIGH

- **H-1 — OPT-INVALID-1: CRRA-EU overfitting-haircut significance gate is scored with the WRONG t-statistic.** `_haircut_select`'s per-trial loop hardcodes `compute_sortino_tstat` (`autotuner.py:1251`) and never calls its `tstat_fn` parameter, even though the call site correctly passes `tstat_fn=compute_crra_eu_tstat` for CRRA-EU bundles (`autotuner.py:1953-1954`, `:1976-1977`) and the docstring says swapping `tstat_fn` is "the ONLY permitted change" (`:1203-1207`). The CRRA-001 block computes `_crra_gamma` (`:1243`) then discards it. **Effect:** for CRRA-EU bundles the deploy/reject FDR decision is calibrated on the Sortino sampling distribution — the exact "H-6 category error" the surrounding code claims to forbid (`:1241-1242`, `compute_crra_eu_tstat` docstring `:529-534`).
  - **Cross-verification:** static defect confirmed by **three independent reads** — optmethod-auditor (found it), mathimpl-auditor (independently confirmed HIGH from file:line), and synthesizer (read the loop, call site, and `_objective_kind` resolution directly). **Runtime reachability confirmed via the full production call chain by runtime-auditor (and synthesizer):** production calls `run_autotuner(..., spec_bundle_id=get_or_create_phase1_theory_bundle_id())` (`alpha_bot_execution.py:1096-1098`); the canonical bundle inserts NO explicit `objective_kind` facet but sets `utility_family = PHASE1_THEORY_UTILITY_FAMILY = "CRRA"` (`database.py:1185`, `:1213-1217`); so the fallback at `autotuner.py:1731-1733` fires and **`_objective_kind` resolves to `"crra_eu"` at runtime**, routing `tstat_fn=compute_crra_eu_tstat` (`:1953-1954`, `:1976-1977`) into a `_haircut_select` that drops it. **The defect is LIVE on the canonical THEORY-bundle path, not theoretical.** *Residual caveat:* confirmed by full static call-chain reading; the daemon was not executed against a live DB (read-only mandate), but the canonical-bundle facet values are set in code, not data-dependent, so execution would not change the conclusion. Recorded as Section H of `pillar4-runtime.md`.
  - **Remediation a future cycle would address:** call `tstat_fn(series, ...)` (with the documented U-transform for CRRA-EU) inside the loop instead of the hardcoded `compute_sortino_tstat`; add a golden test asserting the CRRA-EU path produces a different gate decision than the Sortino path on a fixture where the two t-stats diverge. Strict TDD (math-layer change → adversarial `quant-test-writer`).

- **H-2 — RT-01: cross-process lost-update race on `bot_state`.** `bot_state` is a single JSON blob, read-modify-written wholesale (`database.py:211-225`). The dashboard `flush_resync` background writer does `load_state → mutate → save_state` **without** `database.acquire_lock()` (`app.py:2147-2161`), while the engine subprocess holds `acquire_lock()` across its whole cycle (`alpha_bot_execution.py:593` → `:1848`). `_FLUSH_STATE_LOCK` is in-process only (`app.py:73`) and gives zero protection against the out-of-process engine. An operator clicking flush-resync mid-cycle can clobber a freshly-written `triggered=True` (the double-charge guard) → re-evaluation/re-exit risk.
  - **Cross-verification:** file:line conclusive (structural absence of `acquire_lock()` in `_flush_state_async`). Static-only (live race not reproduced — read-only mandate); the structural absence is conclusive, the operational *frequency* is unquantified.
  - **Remediation:** route `_flush_state_async` through the same engine row-lock (`acquire_lock`/`release_lock`), or gate flush-resync to off-hours (drops to LOW). Tied to OQ-2 below.

### HIGH — FAIL-SAFE GAP (reclassified: code contradicts its own documented intent; fix-shape needs user sign-off)

- **H-3 / OQ-1 — FAIL-SAFE GAP: the trailing stop is fail-CLOSED on permanently-missing MC, contradicting both the vision AND the code's own stated intent.** The vision (anchor §2, README §4.7) states "if any supporting signal is unavailable, the protective stop still fires." This is TRUE at the **confirmation** layer (`math_engine.py:503-511`: `prob_beating is None` passes the MC sanity gate) but the only **arming** path requires `mc_available` (`alpha_bot_execution.py:1292-1303`). When MC is *permanently* unavailable — insufficient history, OR the regime-match guard forcing `prob_beating=None` on an "unprecedented" day (`:1271-1272`) — the symphony **never arms, so the trailing stop never fires**, and the fail-open confirmation gate is unreachable. VWAP-Breakdown and VWAP-Bleed are MC-independent and *do* still protect (`math_engine.py:744-787`), so the operator is **not wholly unprotected** — but the *headline* mechanism is silently off in exactly the thin-history/unprecedented regime the vision says matters most. This is an **under-protection / fail-to-exit** risk, **not** a harmful over-exit risk (a single late `None` tick cannot itself create a below-stop condition).
  - **Reclassification (new evidence — runtime-auditor, file:line):** this is now a genuine **defect**, not merely an open design question. The comment directly above the arming logic states the designer's intent verbatim (`alpha_bot_execution.py:1284-1291`): *"Insufficient MC = the MC second opinion is absent: no arm, no disarm, no TP — and no MC veto of the trailing stop ... The protective stop still fires on its ticks-below-stop condition alone."* The intent is **unambiguous and documented: fail-safe / stop fires anyway.** But the comment is self-contradictory — it says "no arm" AND "the protective stop still fires," yet `compute_exit_confirmation` returns early when `(not armed)` (`math_engine.py:503-504`), so a permanently-unarmed position's stop can never fire. The author believed the confirmation-layer `None`-handling was sufficient and did not account for the arming gate at `:1292` *also* requiring `mc_available`. **So the code contradicts its own stated intent — a real fail-to-exit defect, HIGH severity.** No test asserts the no-MC arming behavior either way (runtime-auditor trace).
  - **What still needs user sign-off is the FIX SHAPE, not whether the behavior is intended** (the comment proves it is not): (a) add a no-MC fail-safe arming path so the trailing stop arms and fires on ticks-below-stop alone when MC is permanently absent (matches documented intent + vision); or (b) if the team instead decides VWAP/Bleed-only protection is acceptable in that regime, correct the misleading comment at `:1284-1291` and soften the vision wording. Default-recommended is (a) — it aligns code with its own asserted intent. Either is a new codepath → Agent Teams TDD. **Blocking for the fail-safe verdict only; non-blocking for the rest of the audit.**

### MEDIUM

- **M-1 — Optimization is statistically underpowered at the live data budget (not a code bug; a data-scale property the code self-documents).** The Optuna objective maximizes a CRRA-EU t-stat over a **~4-day** purged validation fold (`autotuner.py:1779-1802`, `:1854`; pin `:375-377`). At T≈4 the normal-CDF p-value is miscalibrated and selection is dominated by sampling noise — the code says so in writing (`:362-374`). Single-path walk-forward (1 fold, 1 path, ~6 months) cannot establish regime-representativeness; the code names CPCV (López de Prado) as the remedy but it is **not implemented**. *Down-rank note:* this is correctly bounded — BHY corrects selection bias (which it does), the per-trial-length problem is owned by DSR/PSR, and the no-trial-clears default keeps yesterday's params as a no-harm fallback. Verdict is "underpowered, honestly," not "broken."
- **M-2 — RT-02: `acquire_lock` is a non-atomic check-then-set** (`database.py:184-194`, no `BEGIN IMMEDIATE`), and its 60s stale-expiry can let a >60s cycle have its lock stolen mid-write. Advisory, racy; low concurrency given one spawn/minute, but compounds H-2.
- **M-3 — RT-04: scheduler has no market-hours gate; spawns a full interpreter every minute 24/7** (`app.py:301-307`), including off-hours live Composer calls. Efficiency/blast-radius, not correctness.

### LOW / INFORMATIONAL

- **L-1 — F-COV-1: `compute_tp_confirmation` lacks a dedicated golden-fixture test file** — the only genuine gap against the project's "every math layer requires a golden fixture" rule (`math_engine.py` TP layer; mathimpl-auditor). Covered only indirectly via blast-radius/integration tests.
- **L-2 — Advisor naming oversell (as-built):** the three `advisors/` producers are honest governance/meta instruments (DoF-budget audit, spec lint, a rejected-idea tombstone), and the **Divergence Explainer is INERT by default** — `cvar_5pct_long` is hardcoded `None` (`math_engine.py:1456-1457`, `:1544-1545`) unless `SECOND_WINDOW_CVAR_ENABLED=1` (default off, `alpha_bot_execution.py:1588`), so it writes only `NOT_APPLICABLE` rows. Calling the layer "AI Advisor producers" overstates what it computes relative to the north-star strategist the name evokes.
- **L-3 — RT-05:** `_refresh_account_totals` runs a `requests.get(timeout=10)` on the scheduler thread itself (`app.py:269,303`) — the one network call on the daemon's own loop; bounded, but against the spirit of constraint 1.
- **I-1 — Three theory citation-misuse tensions** (flagged, all cited and primary-source-verified, none fatal): (a) √-time decay cites Danielsson-Zigrand 2003, a paper arguing √-time is *biased* under the momentum the system elsewhere assumes; (b) the VWAP gate cites Leung-Zhang 2019, whose optimality proof is for a *mean-reverting* model; (c) below-VWAP-as-exit runs opposite to the documented academic edge (below-VWAP price tends to mean-revert *up*). These weaken the "THEORY" labeling of those specific layers but do not make them unsound as heuristics.
- **I-2 — Vestigial `migrations/003_llm_suggestions.sql`** table exists, unpopulated by any current producer (advisor-auditor OQ-A1). Adjacent; not audited.

## 6. Bottom line for the user

You set out to build something "grounded in sound reasoning," and on that bar **Planet Stopper passes.** The engineering is competent, the fail-safe instincts are correct, the overfitting defenses are real, and the project is honest — sometimes brutally so, in its own code comments and decision log — about where the data runs out. Three concrete defects warrant action: **H-1** (the CRRA-EU haircut is scored with the wrong t-statistic — runtime-confirmed LIVE on the canonical THEORY-bundle path), **H-2** (the dashboard flush can clobber live state), and **H-3** (when Monte Carlo data is permanently missing, the headline trailing stop never arms and so never fires — which directly contradicts the code's own comment at `alpha_bot_execution.py:1284-1291` asserting "the protective stop still fires"; VWAP detectors still protect, so it is under-protection, not runaway). H-3's *fix shape* is the only thing needing your sign-off — recommended: add a no-MC fail-safe arming path so the stop behaves as the comment and vision already promise. Beyond that, hold the line you already hold: the "halve drawdowns" protection is real, but the "Guard Alpha is positive" alpha claim is an unproven regime bet that the available data currently leans *against* — so any product copy should say "regime-conditional, operator-evaluated," not "proven." The aspirational advisor is buildable only at its explain-and-diagnose tiers; everything that recommends an *action* hits the same data wall the project already mapped twice.
