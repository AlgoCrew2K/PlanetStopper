## Findings

### Sub-question 1 — Permission-to-tune mechanism

**Finding 1.1 — The existing haircut ALREADY is a permission gate; it just gates one winner, not per-weight.** [High, Tier 1 code]
`_haircut_select` (`autotuner.py:1184-1272`) computes a per-trial t-stat → one-sided p-value (`compute_haircut_pvalue:686-698`, `1−Φ(t)`) → BHY/Yekutieli adjustment over `N_effective` (`benjamini_hochberg_adjust:711-748`) → selects the argmin-p_adj winner **iff** `p_adj ≤ HARVEY_LIU_FDR_Q` (`:1268`). When no trial clears, it returns `None` and the call site cascades to fallback/default (`:1979-1991`). This *is* a permission gate: the AI proposal only deploys when it clears an FDR-controlled bar; otherwise yesterday's params persist (`:1983-1991`). **The "permission-to-tune" design the experiment wants is not a new invention — it is a re-targeting of the gate from "which whole param-set wins" to "which individual weight has earned a move off its prior."**

**Finding 1.2 — Each candidate is already treated as a separate hypothesis with its own p-value; adding hypotheses raises the bar for all.** [High, Tier 2: Harvey & Liu 2015]
The BHY framework treats each tested candidate as an independent hypothesis test with single-test p-value `p^s = Pr(|r| > SR·√T)`, then the multiple-testing adjusted value `p^m = 1−(1−p^s)^N` rises monotonically with the number of tests `N`; the Yekutieli factor `c(N)=Σ_{j=1}^{N} 1/j` (`_yekutieli_c_n:701-708`) is the arbitrary-dependence correction the code correctly uses because TPE trials are dependent (Harvey & Liu 2015; verified against the code's own citation). **The direct consequence for per-weight gating: if you let K weights each be free to move, you are running K hypothesis tests, and each weight's move must clear a bar inflated by the larger family.** This is the honest cost of degrees of freedom, expressed as a calibrated penalty rather than a hand-wave.

**Finding 1.3 — The per-weight gate is a clean extension of `compute_n_effective`'s additive-S accounting.** [High, Tier 1 code + Tier 2 methodology]
`compute_n_effective = n_optuna + S` (`:761-811`) already implements "every additional thing you searched counts against the multiple-testing N." The structural property the audit praised (a `BACKTEST_SELECTION` ledger row inflates S → inflates c(N) → raises the FDR bar for every trial; NN1-honest S=0 is byte-identical) is exactly the hook a per-weight gate needs: **each weight permitted to float off its prior is one more dimension of search, so it should enter the N_effective accounting.** My interpretation (labeled): the cleanest honest design treats "K free weights" as adding to the effective hypothesis family the optimizer is selecting over — either by counting each free weight as a searched dimension in S, or (stricter, and what I'd flag for the H-1 team) by running an explicit per-weight test as in Finding 1.4.

**Finding 1.4 — Two architecturally distinct per-weight gating designs; they are NOT equivalent and the choice is load-bearing.** [Medium — this is design-space enumeration grounded in the literature, flagged as interpretation where it goes beyond cited fact]

- **Design A — Joint gate, per-weight DOF charge (lighter touch).** Keep the single objective-level gate (one consensus objective → one t-stat → one p_adj), but charge `N_effective` for the number of free weights so the *whole* proposal clears a higher bar the more weights it frees. Prior-fallback is all-or-nothing: the entire tuned weight vector deploys or the entire prior vector persists. This is the smallest change to the existing machinery (it is essentially today's gate with K folded into N). Cost: it cannot say "weight 3 earned its move but weight 5 didn't" — it is coarse.
- **Design B — Per-weight test, individual prior-fallback (honest but data-hungry).** Run one hypothesis per weight: H0_k = "weight k = its research prior." A weight moves off its prior only if its individual adjusted p-value clears the FDR gate *across the family of all weight-tests* (BHY over K p-values). Weights that don't clear snap back to their prior. This is the literal "permission per weight" the experiment describes, and it is the statistically correct framing — **but it multiplies the data demand by K** because each weight now needs its own powered test, and the audit's ~4-day fold (`pillar2-optmethod.md` item a) already cannot power *one* test (Finding 1.6).

**Finding 1.5 — The gate's calibration dial is Harvey & Liu (2020), not 2015 — and it is the right tool for "permission."** [High, Tier 2: Harvey & Liu 2020]
The 2015 haircut controls only false discoveries (Type I). The 2020 follow-up ("False *and Missed* Discoveries") establishes, via a **double-bootstrap**, a t-statistic hurdle tied to a chosen **ratio of misses to false discoveries (Type II scaled by Type I)** — i.e. it lets you set the *relative cost* of "froze a weight that should have moved" vs "moved a weight that was noise." This is precisely the permission-gate's policy knob: a permission-to-tune gate is a deliberate choice to accept many *misses* (weights staying on prior) to avoid *false* moves (weights chasing noise). **My interpretation:** the experiment's stated philosophy — "stays at the prior unless statistically earned" — is an explicit, asymmetric Type-II-tolerant / Type-I-averse policy, and Harvey-Liu 2020's misses-to-false-discoveries hurdle is the literature's name for that exact dial. The current code uses the 2015 single-FDR-q gate (`HARVEY_LIU_FDR_Q`); it does **not** implement the 2020 asymmetric hurdle. That is a gap if the team wants to tune the asymmetry explicitly rather than inherit whatever asymmetry q=0.05 implies.

**Finding 1.6 — Prior-fallback in practice: at this data scale the gate's *default* output is "stay on prior," and that is the honest answer.** [High — follows directly from the audit's verified T≈4 finding + small-sample power literature]
The audit established (`pillar2-optmethod.md` items a, d; pin `autotuner.py:375-377`) that the Optuna objective is scored on ~4 purged validation days, and a normal-CDF p-value at T≈4 is miscalibrated and underpowered. A permission gate honestly applied at T≈4 will *almost never* grant permission, because almost nothing clears an FDR bar on 4 observations. **So "warm-start from prior, tune as data accrues" resolves, at the current data budget, to "sit on the prior."** This is not a flaw in the gate; it is the gate working correctly — the data wall is real and the gate refuses to launder 4 days of noise into a weight move. The honesty of the experiment (the team-context's stated load-bearing concern) is preserved *only if* the team accepts that, for the foreseeable data budget, the expected behavior is prior-persistence, and any weight that does move is a rare, hard-won, well-powered exception. If the gate is instead tuned loose enough to "let weights move so the experiment feels alive," it ceases to be honest.

### Sub-question 2 — Pooling vs per-symphony

**Finding 2.1 — Partial pooling's data gain is quantifiable via the variance ratio → "effective observations per group."** [High, Tier 2: Gelman multilevel framework]
The information-content relationship: effective observations contributed by the group-level (prior) structure ≈ `σ²_within / σ²_between` (the variance ratio). In the canonical radon example, σ_between=0.33, σ_within=0.76 → variance ratio gives ≈**5 effective observations per group** from pooling. The operative rule: **when a group's own sample size is below that effective-observation threshold, partial pooling shrinks it heavily toward the population (pooled) estimate; when it is above, the group estimate dominates** (Gelman & Hill 2007; Laplace-Bayes exposition). Per-group estimates converge to no-pooling as per-group n grows and to complete-pooling as n→0.

**Finding 2.2 — Apply that rule to this experiment: per-symphony n is far below threshold → the math forces near-complete pooling.** [High — direct application of 2.1 to the audit's data scale]
**The honest independent-observation unit is the REGIME count, not raw days** (correction folded in from prior-researcher's dimensionality track; cross-reference their file for the derivation). Raw daily returns are heavily autocorrelated/regime-clustered, so counting ~4 raw validation days as 4 independent observations *overstates* power — the same overstatement the audit's pillar3 finding (~5-15 independent regime-shifts) and López de Prado's "10 years of daily data ≈ a few dozen independent regimes, not 2,500 obs" both warn against. Each symphony's *own* fold therefore contributes on the order of a *handful* of independent observations, not ~4 clean ones (and over the full 125-day history, on the order of single-digit regimes, not 125 obs). Even a modest between-symphony variance puts the effective-observations-per-symphony threshold (Finding 2.1) well above that, which means a partial-pooling model shrinks each symphony's weights almost all the way to the shared (pooled) vector. **Quantitatively (in the honest regime-count unit): free per-symphony weights spend K×(num_symphonies) degrees of freedom against a per-symphony regime count that is single-digit at best; a single shared weight vector spends K degrees of freedom against the *pooled* regime history of all symphonies (≈ regime_count × num_symphonies, modulo cross-symphony regime correlation — which shares tail/crisis regimes and so further deflates the effective independent count).** The pooled design multiplies the effective independent sample backing each weight by roughly the symphony count (less the shared-regime overlap). Given the audit's central finding that even the pooled-ish single-objective tuning is underpowered *when counted in days*, the regime-count correction makes it worse, not better: free per-symphony weights are categorically un-tunable; pooling is not a preference, it is the only regime with any power at all. **Caveat (my prior framing):** an earlier draft of this finding stated the sample in raw days (~4 days × num_symphonies); that overstated power and is corrected here to the regime count — the direction is unchanged, the magnitude is worse.

**Finding 2.3 — Where on the spectrum: shared weight vector + optional shrunk per-symphony deviation, never free per-symphony.** [Medium — this is a recommendation-shaped finding; reframed as options in §Options]
The spectrum runs: complete pooling (one weight vector for all symphonies) ←→ partial pooling (shared prior + shrunk per-symphony offsets) ←→ no pooling (free per-symphony weights). The data wall rules out the no-pooling end entirely. The defensible region is **complete-to-strong-partial pooling.** A hierarchical/partial-pooling layer that *allows* per-symphony deviation but shrinks it to ~0 by default is the most expressive honest option — but note (caveat) it adds variance-component hyperparameters (σ_between) that themselves must be estimated from the same thin data, so empirical-Bayes estimation of σ_between is itself low-powered. **My interpretation:** at this data scale, the partial-pooling model will, in practice, collapse to near-complete-pooling anyway (per 2.1), so the *simpler* complete-pooling design buys almost all the power with far fewer moving parts and fewer estimable nuisance parameters. The hierarchical layer is worth it only if/when per-symphony n grows past the effective-observation threshold.

**Finding 2.4 — Pooling assumption has a validity precondition: the weights must be *exchangeable* across symphonies.** [Medium, Tier 2 hierarchical-modeling theory]
Pooling borrows strength by assuming the per-group parameters are draws from a common distribution (exchangeability). If symphonies are structurally heterogeneous (different asset classes, leverage, holding horizons) such that the *optimal* consensus weights genuinely differ by symphony, pooling introduces bias (the complete-pooling estimate is biased for any individual group — search corroboration). **This is the pooling counterpart of the regime-representativeness wall:** pooling trades variance for bias, and the bias is only benign if the symphonies are similar enough to share a weight prior. Flag for prior-researcher / engine-integrator: whether the operator's symphonies are exchangeable in the relevant sense is an empirical question the audit did not settle, and it bounds how much pooling is honest.

### Sub-question 3 — Regularization / shrinkage to keep effective DOF low

**Finding 3.0 (keystone) — The FORECAST-COMBINATION PUZZLE is the decades-replicated theoretical backbone for "stay at the prior unless earned."** [High, Tier 2: Bates-Granger 1969, Clemen 1989, Smith-Wallis 2009, Claeskens et al. 2016 — handed off from prior-researcher's design-space track; I own the quantitative shrinkage treatment, they own the puzzle as prior-art]
The forecast-combination puzzle is the robust, repeatedly-replicated empirical finding that a **simple equal-weighted (fixed-prior) average of forecasts routinely beats an *estimated* "optimal" weighting.** The accepted explanation is exactly the estimation-error mechanism that governs this whole experiment: *the variance of the estimated optimal weight is so large on finite samples that the estimate lands further from the true optimum than a fixed equal weight does* — "the benefit of optimal weights is offset by the estimation uncertainty of unknown weights, especially when large estimation noise is present." This is the keystone because the consensus core is, structurally, a forecast/signal-combination problem (combine K exit-criterion confirmations via weights), and the puzzle says: at small effective n (Finding 2.2's regime count), the *fixed research-prior weight vector is expected to out-of-sample-beat any data-estimated weight vector.* **The unifying frame for the rest of this sub-question:** fixed/equal weights = the shrinkage-toward-prior **limit** (Dirichlet concentration → ∞, or ridge-to-prior λ → ∞); freely-estimated weights = the **no-shrinkage** limit (the puzzle's losing end); the permission gate + shrinkage is the **principled middle** that only departs the prior-limit in proportion to evidence. **My interpretation:** the puzzle is the strongest single piece of external evidence that the experiment's permission-to-tune philosophy is correct *and* that its honest near-term equilibrium is the prior — it is not a counsel of despair, it is the literature confirming that the prior is a *good place to be* under estimation noise, not merely a safe fallback.

**Finding 3.1 — Shrinkage-to-prior IS the permission gate, expressed continuously.** [High — unifies sub-q 1 and 3]
The discrete permission gate (move/don't-move per weight, Finding 1.4 Design B) and continuous shrinkage-to-prior (James-Stein / empirical-Bayes pull toward the prior, strength set by data) are two encodings of the same idea: **let the data overcome the prior only in proportion to the evidence.** The James-Stein/empirical-Bayes result (Efron-Morris 1973, surfaced in search) is the canonical statement that shrinking small-sample estimates toward a common target dominates the unshrunk estimates in mean-squared-error — directly relevant because the per-symphony/per-weight estimates here ARE small-sample. **My interpretation:** a continuous shrinkage formulation may be *more* honest than a hard pass/fail gate, because it never produces the binary illusion of "this weight is now proven" — it produces "this weight has moved 8% of the way from prior toward the data-implied value, because that is all the evidence supports." The hard FDR gate and continuous shrinkage are not rivals; the team could use the FDR gate as the *permission to shrink at all* and the shrinkage factor as *how far*.

**Finding 3.2 — Constrained-simplex weights with a Dirichlet prior is the natural regularizer for a weighted-consensus objective.** [Medium-High, Tier 2/3: double-spike Dirichlet, forecast-combination literature]
The consensus core's weights are a natural simplex (non-negative, and the experiment's design sums active weights to a tunable threshold = "one confirm"). A **Dirichlet prior places probability mass directly on the simplex**, enforcing non-negativity and the budget constraint by construction, with concentration parameters controlling dispersion (how far weights may stray from the prior). **The "double-spike Dirichlet" result is directly on-point:** structured high-dimensional simplex weighting works well precisely because *equal weights often achieve favorable empirical performance* and the prior can shrink most weights toward zero or toward a constant — i.e. the literature's repeated finding that **equal-weight / prior-anchored combinations beat data-fit combinations out-of-sample under estimation noise** (the "1/N" forecast-combination result). For this experiment that means: the research-prior weight vector is a strong default, and the Dirichlet concentration parameter is a single, interpretable dial for "how much total deviation from the prior the data is allowed to buy" — a clean way to cap effective DOF with one number rather than K.

**Finding 3.3 — L1 vs L2 vs simplex-Dirichlet — what each buys for DOF control.** [Medium, Tier 2 standard regularization theory + Tier 3 corroboration]
- **L2 (ridge) toward the prior** = Gaussian prior on (weight − prior); shrinks all deviations smoothly, never exactly to prior; equivalent to the empirical-Bayes pull of 3.1; effective DOF reduced continuously by the shrinkage factor.
- **L1 (lasso) toward the prior** = Laplace prior on (weight − prior); produces *exact* snap-backs (weight == prior for sub-threshold evidence), which is the discrete permission gate's continuous cousin and yields a directly interpretable "k of K weights have actually moved" count — itself a clean DOF tally to feed N_effective.
- **Dirichlet/simplex** = the only one that *also* enforces the sum-to-threshold and non-negativity structure the consensus design requires; concentration parameter caps total deviation.
**My interpretation:** L1-toward-prior (sparse moves) composes best with the per-weight permission framing (Finding 1.4 Design B) because the L1 "active set" size is exactly the number of weights that earned a move — which is exactly what should be charged into the multiple-testing N. A Dirichlet layer on top handles the simplex constraint. This keeps the *effective* DOF equal to the number of weights that actually moved, not the number of weights that *could* move — the honest accounting the audit's NN1/N_effective machinery already rewards.

### Sub-question 4 — H-1 prerequisite spec (load-bearing)

**Finding 4.1 — The H-1 defect, restated precisely from the code on HEAD 8586ab2.** [High, Tier 1 code — independently re-verified this pass]
`_haircut_select` accepts `tstat_fn` (default `compute_sortino_tstat`) and its docstring says swapping `tstat_fn` is "the ONLY permitted change" (`:1203-1207`). The call site correctly routes `_tstat_fn = compute_crra_eu_tstat` for `_objective_kind == "crra_eu"` (`:1953-1954`) and passes `tstat_fn=_tstat_fn` (`:1976-1977`). **But the loop body hardcodes the Sortino t-stat and never calls `tstat_fn`:**
```
1251:        tstats.append(compute_sortino_tstat(series, seed=trial_idx))
```
`gamma`/`_crra_gamma` is computed (`:1243`) then discarded. Net: for a CRRA-EU bundle, Optuna optimizes the CRRA-EU objective but the FDR gate scores each trial with the Sortino bootstrap t-stat — the H-6 category error the surrounding code forbids (`compute_crra_eu_tstat` docstring `:529-534`). The audit confirmed this is **LIVE on the canonical THEORY-bundle path** (synthesis H-1), not theoretical.

**Finding 4.2 — The statistical principle that makes the gate's statistic load-bearing: the test statistic must match the *functional form of the objective*.** [High, Tier 1/2: Sharpe↔t-stat relationship]
The literature is unambiguous that `Sharpe = t-statistic / √T`, i.e. `t = Sharpe·√T` (Sharpe-ratio↔Student-t relationship, multiple sources). A **ratio/effect-size objective** (Sharpe, Sortino) has its sampling distribution characterized by `effect_size·√T`; a **mean-valued objective** (expected utility, a weighted *sum* of criterion scores, a mean CRRA utility) has its sampling distribution characterized by the **one-sample t-statistic `mean(X)/(sd(X)/√T)`** (`compute_crra_eu_tstat:520-553` is exactly this and is correct in form). These are NOT interchangeable: applying `effect_size·√T` scaling to a mean-valued objective, or a Sortino-downside-deviation SE to a full-distribution mean, miscalibrates the p-value and therefore the FDR decision. **This is why H-1 is not cosmetic: the gate that decides deploy-vs-reject is computing significance against the wrong sampling distribution.**

**Finding 4.3 — H-1 PREREQUISITE for a *weighted-consensus* objective — exact spec.** [High on the principle; Medium on the specific construction, flagged where it requires a design decision the H-1 build team must make]

The weighted-consensus exit objective is, by construction, a **mean-valued functional**: it scores each replayed day by a weighted sum of criterion confirmations and the objective is (some aggregation of) the per-day consensus score / resulting P&L utility. It is NOT a Sortino, NOT a Sharpe. Therefore the gate statistic MUST be the **one-sample t-statistic of the per-day objective series**, `mean(score_series)/(sd(score_series)/√T)`, NOT `compute_sortino_tstat`. Concretely the H-1 prerequisite is:

1. **`_haircut_select` must actually call its `tstat_fn` parameter** inside the per-trial loop (the literal fix to `:1251`: replace `compute_sortino_tstat(series, seed=trial_idx)` with `tstat_fn(series)` — and resolve the `seed`/`gamma` signature mismatch between the two stat functions: `compute_sortino_tstat(returns, seed)` vs `compute_crra_eu_tstat(U_series)` take different args, so the loop must adapt the call per `tstat_fn`, or the two functions must be given a unified signature). **This is the minimal H-1 fix and is a prerequisite regardless of the consensus experiment** — it is a live defect today.
2. **A `compute_consensus_tstat` (or reuse of the mean-valued `compute_crra_eu_tstat` form) must exist** that takes the per-day consensus objective series and returns the one-sample t-stat `mean/(sd/√T)`, with the same numerical discipline the CRRA function already has: `statistics.stdev` (ddof=1), return 0.0 for T≤1 and for constant series (degenerate trials rank last via argmin-p_adj). The consensus objective is mean-valued like CRRA-EU, so `compute_crra_eu_tstat`'s *form* is reusable; what differs is the input transform (CRRA U-transforms returns first; the consensus objective's per-day score is its own series — **the H-1 team must decide and pin what the per-day "score" series is**: raw consensus score, realized utility, or P&L — and that choice IS the objective definition, so it is a Gate-1 decision, not an implementation detail).
3. **The p-value mapping must be honest about T.** `compute_haircut_pvalue` uses the normal CDF (`:686-698`). At T≈4 this is miscalibrated (audit item d). For the consensus objective the prerequisite is either (a) accept the documented underpowered regime and keep the normal CDF *with the pin comment making the miscalibration explicit* (as CRRA-EU does today), or (b) use a t(T−1) CDF — but note (caveat) a t(3) CDF does not rescue power, it only stops *overstating* significance; it makes the gate *stricter*, reinforcing prior-fallback (Finding 1.6). **My interpretation:** (b) is the more honest choice for a permission gate whose entire purpose is to avoid false moves, but it must be paired with the team's eyes-open acceptance that it will grant permission even more rarely.
4. **If per-weight gating (Design B / L1-sparse) is adopted, the gate statistic is computed per-weight-test, and the BHY family is the K weight-tests** — the same `benjamini_hochberg_adjust` over K p-values, with `N_effective` charged for the K free weights. This is the load-bearing coupling: **H-1's correct statistic is a prerequisite for the per-weight gate to mean anything, because a per-weight gate built on the wrong (Sortino) statistic would launder noise per-weight, K times over.**

**Finding 4.4 — H-1 is on the critical path: the consensus experiment CANNOT honestly launch until the gate statistic is correct.** [High — synthesis of 4.1–4.3]
The team-context states the honesty of the whole experiment rests on the permission gate. The permission gate is the FDR-haircut. The FDR-haircut today scores the wrong statistic (H-1). Therefore: **fixing H-1 is a hard prerequisite, not a parallel nicety.** A weighted-consensus core deployed on top of the current `_haircut_select` would have every weight-move decision calibrated against a Sortino sampling distribution that has nothing to do with the consensus objective — the exact "laundering noise as signal" failure the team is trying to prevent. This is the single most important finding in this report for sequencing.

## Statistical Validity (finance time-series specifics)

- **Purge + embargo:** present and correct in the existing walk-forward (`PURGE_DAYS=20`, `EMBARGO_DAYS=1`; `:1799-1802`), so look-ahead from autocorrelated overlapping windows is structurally handled — the consensus core inherits this for free **as long as it reuses the same fold construction**. The prerequisite: the consensus objective's per-day series must be built on the *same purged validation fold*, not the raw 25-day or full 125-day window, or it silently reintroduces look-ahead. [High, grounded in audit item a]
- **The T≈4 wall applies unchanged to the consensus objective.** A weighted-consensus objective scored on the same ~4-day fold is exactly as underpowered as the CRRA-EU objective is today (audit items a, d). [Medium — interpretation, but directly grounded in the audit's CPCV finding]
- **Two distinct "n"s — do not conflate them.** The T≈4 above is the literal *fold length* the per-trial t-stat divides by (a code fact; correctly in days). The *power* of the pooling/permission decision is governed by the **independent-regime count** (Finding 2.2, ~single-digit per symphony per prior-researcher's track), because autocorrelated days are not independent observations. The t-stat's √T uses the day count; the *honest significance* of clearing the gate should be read against the regime count. A gate that treats 4 autocorrelated days as 4 independent observations overstates significance — the day-vs-regime gap is itself a source of false permission. [High — synthesis of audit T≈4 + prior-researcher regime count]
- **Pooling vs look-ahead interaction:** pooling across symphonies increases the effective sample but introduces a new validity question — cross-symphony *correlation*. If symphonies share holdings/regime exposure, their per-day returns are correlated, so the pooled sample's *effective* independent observation count is less than `regime_count × num_symphonies` (and far less than `day_count × num_symphonies`). The Yekutieli arbitrary-dependence factor handles *trial* dependence but NOT cross-symphony observation dependence in a pooled t-stat — that would need a clustered/block SE. **Flag:** a naïve pooled one-sample t-stat over correlated symphony-days would overstate the effective independent n and thus overstate significance — a new look-ahead-adjacent hazard the pooling design introduces. [Medium — this is my interpretation extending the dependence principle; not directly cited, labeled accordingly]

## Interpretation (labeled — may be wrong)

My overall read of how these four pieces fit together:

1. **The experiment's honesty hinges on accepting that the gate's *expected* output is "stay on prior."** The permission-to-tune framing is correct and the machinery to implement it already largely exists. But at the current ~4-day-fold data budget, an honest gate grants permission rarely. "Tunes as data accrues" is true only in the limit of much more data (or CPCV-recovered paths). If the team wants to *see* weights move soon, the temptation will be to loosen the gate — and that is exactly where the experiment would stop being honest.

2. **Pooling is not optional — it is the only regime with any power.** Free per-symphony weights are categorically un-tunable at this scale. A single shared weight vector (complete pooling) buys ~`num_symphonies×` the effective sample per weight and is the simplest honest design; a hierarchical partial-pooling layer is more expressive but, at this n, collapses to near-complete-pooling anyway while adding hard-to-estimate variance components.

3. **The cleanest honest encoding is: shared (pooled) Dirichlet-prior weight vector + L1-sparse shrinkage toward the research prior + the corrected (H-1-fixed) one-sample t-stat as the per-move FDR gate, charging N_effective for each weight that actually moves.** This keeps effective DOF equal to the number of weights that *earned* a move, not the number that *could*. That is the design that composes the project's existing NN1/N_effective discipline with the permission-to-tune philosophy without inventing new machinery.

4. **H-1 is the gate. Fix it first, or nothing downstream is honest.** Everything in sub-questions 1–3 sits on top of "the significance statistic correctly matches the objective." Today it doesn't.

## Options & Trade-offs (NOT recommendations — team/PM decides)

**O1 — Gate granularity:**
- *Joint gate + per-weight DOF charge (Design A):* smallest change; reuses today's machinery almost verbatim (fold K into N_effective); coarse (cannot move weights individually). Lower data demand.
- *Per-weight test + individual fallback (Design B):* literal "permission per weight"; statistically correct framing; K× the data demand; needs CPCV-like path multiplication to have power.

**O2 — Shrinkage encoding:**
- *Hard FDR pass/fail per weight:* binary, interpretable "moved / on prior" count; risks the false binary "this weight is now proven."
- *Continuous shrinkage-to-prior (L1/L2/empirical-Bayes):* never overclaims; "moved 8% toward data"; L1 gives an interpretable active-set count to feed N_effective; L2 smooth but never snaps to prior.
- *Dirichlet/simplex prior:* the only option that also enforces the sum-to-threshold + non-negativity structure; one concentration parameter caps total deviation.

**O3 — Pooling level:**
- *Complete pooling (one weight vector):* max power per weight; biased if symphonies are not exchangeable; simplest.
- *Partial pooling (shared prior + shrunk offsets):* most expressive; adds estimable variance components that are themselves low-powered at this n; collapses toward complete pooling anyway at T≈4.
- *No pooling (free per-symphony):* ruled out by the data wall — listed only for completeness.

**O4 — Type I/II calibration:**
- *Keep 2015 single-FDR-q (HARVEY_LIU_FDR_Q):* status quo; inherits whatever Type-II cost q=0.05 implies.
- *Adopt 2020 double-bootstrap misses-to-false-discoveries hurdle:* lets the team set the asymmetry explicitly (the "permission" philosophy IS an asymmetric policy); more machinery; the principled choice if the asymmetry should be a deliberate dial.

**O5 — p-value calibration at small T:**
- *Normal CDF (status quo):* overstates significance at T≈4; documented in pin comment.
- *t(T−1) CDF:* stops overstating; stricter; does NOT recover power; reinforces prior-fallback.

**O6 — H-1 fix shape (the prerequisite):**
- *Minimal:* make `_haircut_select` call `tstat_fn` and unify the `seed`/`gamma` signature mismatch; add a golden test where Sortino and consensus t-stats diverge and assert different gate decisions. This is a live-defect fix independent of the experiment.
- *Plus consensus statistic:* add/define `compute_consensus_tstat` (mean-valued one-sample t over the pinned per-day consensus series) — requires the team to pin *what the per-day score series is* (Gate-1 objective-definition decision).
